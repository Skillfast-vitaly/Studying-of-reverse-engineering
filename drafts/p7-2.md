
## П7.4. Конструктор, деструктор, `new` и `delete`

### Конструктор и деструктор

```cpp
Dog() : Animal(4), bones_(0) {}
```

**Конструктор** (constructor `[констрáктор]`) — метод с именем класса,
который готовит новый объект: заполняет поля. После двоеточия —
список того, что сделать первым: `Animal(4)` — сначала построить
«животную» часть объекта с четырьмя ногами, `bones_(0)` — потом
обнулить кости.

**Деструктор** (destructor `[дистрáктор]`) — метод с тильдой: `~Animal()`.
Его вызывают, когда объект уничтожают, — убрать за собой. У нас он
пустой, но слово `virtual` перед ним важно — о нём в П7.6.

### `new` и `delete`

```cpp
Animal *zoo[2] = { new Dog(), new Bird() };
…
delete zoo[0];
```

`new Dog()` делает две вещи: выделяет память под объект — как `malloc`
из главы 5 — и вызывает для неё конструктор. `delete` — наоборот:
сначала деструктор, потом освободить память, как `free`. Выделяет
и освобождает память особая функция `operator new` и пара к ней
`operator delete` («оператор new», «оператор delete»).

### Конструктор в листинге

Отладочная сборка (Debug), где ничего не встроено. Конструктор `Dog`:

```
Dog::Dog:
    sub     rsp, 38h
    mov     [rsp+30h], rcx
    mov     rcx, [rsp+30h]
    mov     [rsp+28h], rcx             ; запомнить this
    mov     edx, 4                     ; второй аргумент: 4 ноги
    call    Animal::Animal             ; первый — this, он уже в RCX
    mov     rax, [rsp+28h]             ; rax = this
    lea     rcx, Dog::`vftable'
    mov     [rax], rcx                 ; this+0 = адрес таблицы Dog
    mov     dword ptr [rax+10h], 0     ; this->bones_ = 0
    add     rsp, 38h
    retn
```

И конструктор `Animal`, который он зовёт:

```
Animal::Animal:
    sub     rsp, 10h
    mov     [rsp+0Ch], edx             ; legs
    mov     [rsp], rcx                 ; this
    mov     rax, [rsp]
    lea     rcx, Animal::`vftable'
    mov     [rax], rcx                 ; this+0 = адрес таблицы Animal
    mov     ecx, [rsp+0Ch]
    mov     [rax+8], ecx               ; this->legs_ = legs
    add     rsp, 10h
    retn
```

Видишь порядок? Сначала конструктор `Animal` пишет в первые 8 байт
объекта адрес таблицы `Animal` и ставит ноги по смещению `8`. Потом
конструктор `Dog` **перезаписывает** первые 8 байт адресом своей
таблицы и обнуляет кости по смещению `10h`. Что за таблица и зачем её
адрес лежит в самом начале объекта — тема П7.6. Пока запомни примету:
**в начале конструктора класса с виртуальными функциями в `[this]`
записывается адрес из `.rdata`**. По этой строке конструкторы и находят.

### `new` в листинге

Теперь сборка с оптимизацией. Начало `main`, где создаются два объекта:

```
main:
    …
    mov     ecx, 18h                   ; размер Dog — 24 байта
    call    operator new(unsigned __int64)
    mov     rsi, rax                   ; rsi = новый объект
    mov     dword ptr [rax+8], 4       ; legs_ = 4
    lea     rax, Dog::`vftable'
    mov     [rsi], rax                 ; таблица Dog
    mov     dword ptr [rsi+10h], 0     ; bones_ = 0
    mov     [rsp+20h], rsi             ; zoo[0]
    mov     ecx, 10h                   ; размер Bird — 16 байт
    call    operator new(unsigned __int64)
    mov     rdi, rax
    mov     dword ptr [rax+8], 2       ; legs_ = 2
    lea     rax, Bird::`vftable'
    mov     [rdi], rax                 ; таблица Bird
    mov     [rsp+28h], rdi             ; zoo[1]
```

Конструкторы встроились: вызовов `Dog::Dog` больше нет, остались их
три записи. Зато `operator new` всегда остаётся вызовом, и его
единственный аргумент в `ECX` — **размер объекта**. Это подарок
реверсеру: увидел `mov ecx, 18h` перед `operator new` — знаешь, что
объект этого класса занимает 24 байта, и можешь заводить структуру
под него.

### `delete` в листинге

Конец `main`:

```
    mov     rax, [rsi]                 ; таблица объекта zoo[0]
    mov     rcx, rsi                   ; this
    mov     edx, 1                     ; «и освободи память»
    call    qword ptr [rax]            ; первая ячейка таблицы
```

`delete` вызвал **первую функцию из таблицы объекта**. Visual Studio
кладёт туда особую функцию — **scalar deleting destructor**
`[скéйлер дилúтинг дистрáктор]`, «удаляющий деструктор». Она вызывает
деструктор, а если во втором аргументе 1 — ещё и освобождает память:

```
Dog::`scalar deleting dtor':
    push    rsi
    sub     rsp, 20h
    mov     rsi, rcx                   ; this
    test    edx, edx                   ; освобождать?
    jz      short skip
    mov     edx, 18h                   ; размер — опять 24 байта
    mov     rcx, rsi
    call    operator delete(void *, unsigned __int64)
skip:
    mov     rax, rsi
    add     rsp, 20h
    pop     rsi
    retn
```

Деструктор у нас пустой, и компилятор его выбросил: осталось только
освобождение. Обрати внимание на `mov edx, 18h`: Visual Studio
по умолчанию передаёт в `operator delete` и размер объекта (так написано
в документации Microsoft про ключ `/Zc:sizedDealloc`). Размер класса
виден дважды — у `new` и у `delete`.

## П7.5. Наследование и раскладка объекта

```cpp
class Dog : public Animal { … };
```

Запись `: public Animal` значит: `Dog` **наследует** (inherits
`[инхéритс]`) `Animal`. У каждой собаки есть всё, что есть у животного:
поле `legs_`, методы `legs()`, `name()`, `speak()`. `Animal` — **базовый
класс** (base class), `Dog` — **производный** (derived class, «наследник»).
В памяти объект `Dog` — это объект `Animal`, к хвосту которого
приписаны поля собаки.

Соберём, что мы узнали о смещениях из листингов П7.3 и П7.4:

```
Dog у Visual Studio, 24 байта (new 18h):
+00  адрес таблицы класса       8 байт   ┐
+08  legs_                      4 байта  │ часть Animal, 16 байт
+0C  (пусто)                    4 байта  ┘ выравнивание (П1.4)
+10  bones_                     4 байта    своё поле Dog
+14  (пусто)                    4 байта    выравнивание до 8
```

А теперь та же программа, собранная **g++** из w64devkit. Метод `feed`:

```
feed:
    add     dword ptr [rcx+0Ch], 1     ; bones_ по смещению 0Ch!
    retn
```

И `new Dog()`:

```
    mov     ecx, 10h                   ; 16 байт, а не 24
    call    operator new(unsigned long long)
```

```
Dog у g++, 16 байт (new 10h):
+00  адрес таблицы класса       8 байт   ┐ часть Animal
+08  legs_                      4 байта  ┘
+0C  bones_                     4 байта    своё поле Dog — в «пустоте» Animal
```

Один исходник — два разных объекта! g++ разрешает себе положить поле
наследника в пустые байты выравнивания базового класса. Visual Studio
так не делает: часть `Animal` у неё всегда занимает полные 16 байт.
Обе правы: каждый компилятор следует своим правилам раскладки, и в
пределах своей программы они соблюдаются строго.

Отсюда правило реверсера: **смещения полей бери из листинга, а не
высчитывай в уме**. И сначала узнай компилятор — Detect It Easy,
глава 7.
