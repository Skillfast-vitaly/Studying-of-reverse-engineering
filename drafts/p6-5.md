
### Что нового в коде

- **Три маленькие функции** `u16`, `u32`, `u64` — чтобы не писать
  каждый раз `struct.unpack_from(…)[0]`. Имена — по размеру в битах:
  `WORD`, `DWORD`, `QWORD`.
- **Строка в тройных кавычках** сразу под `def` — описание функции
  (docstring `[дóкстринг]`, «строка документации»). Python её
  не выполняет, она для людей.
- **Словарь** (dictionary `[дúкшенери]`, коротко dict) — `info = {…}`.
  Это набор пар «ключ → значение»: `info["machine"]` достаёт машину,
  `info["base"] = …` добавляет новое поле. Похоже на структуру в C,
  только поля можно добавлять на ходу.
- **Список кортежей** `info["sections"]`: каждая секция — кортеж
  из шести чисел. Цикл `for name, vsize, va, rsize, raw, flags in …`
  сразу раскладывает кортеж по переменным.
- **`.rstrip(b"\0")`** — отрезать нули справа: имя секции дополнено
  нулями до 8 байтов (глава 8).
- **`None`** — «ничего», как `NULL` в C. `rva_to_off` возвращает его,
  если такого адреса в файле нет: например, у `.bss`, которая есть
  в памяти, но не в файле. Кто вызывает функцию, обязан это проверить.
- **`if __name__ == "__main__":`** — самая загадочная строка. Когда
  ты запускаешь `python pe_info.py`, Python кладёт в особую переменную
  `__name__` текст `"__main__"`, и `main()` срабатывает. А когда
  другой скрипт пишет `import pe_info`, в `__name__` будет
  `"pe_info"`, и `main()` не вызовется — подключатся только функции.
  Так один файл служит и программой, и модулем. В П6.9 это пригодится.

не открыта на запись и выполнение сразу, а это красный флаг
из раздела 8.6.

А что за `/4`, `/19` и дальше? У этих секций имя длиннее восьми букв
и в 8 байтов не влезло. Тогда в поле имени пишут косую черту
и номер — смещение настоящего имени в отдельной таблице имён в конце
файла. Это отладочная информация gcc (формат DWARF, П1.9).
По документации Microsoft длинных имён в `.exe` быть не должно,
а gcc их всё равно пишет: Windows на имена секций не смотрит.
Как достать настоящие имена — упражнение П6.2.

## П6.9. Проект: свой поиск строк

В главах 7 и 16 первое, что ты делал с незнакомой программой, — искал
строки. Напишем свой поиск: найти в файле все цепочки печатных байтов
длиной от пяти. А заодно — подключим `pe_info` как модуль, чтобы
по смещению в файле сразу видеть адрес, как в IDA.

Файл `strings.py` положи в ту же папку, что `pe_info.py`:

```python
# strings.py — строки в файле, как окно Strings в IDA и Ghidra
import sys
import pe_info

MIN = 5                                   # строки короче — обычно шум


def ascii_strings(data, min_len=MIN):
    """Найти цепочки печатных байтов. Вернуть список (смещение, текст)."""
    found = []
    start = None                          # где началась цепочка
    for i, b in enumerate(data):
        if 0x20 <= b < 0x7F:              # печатный символ ASCII (глава 3)
            if start is None:
                start = i
        else:
            if start is not None and i - start >= min_len:
                found.append((start, data[start:i].decode("ascii")))
            start = None
    return found


def main():
    if len(sys.argv) < 2:
        sys.exit("zapusk: python strings.py fail.exe [chto_iskat]")
    info = pe_info.load(sys.argv[1])
    word = sys.argv[2] if len(sys.argv) > 2 else ""
    for off, text in ascii_strings(info["data"]):
        if word not in text:
            continue
        where = pe_info.off_to_rva(info, off)
        if where is None:
            print(f"{off:8X}  {'':8} {'':12}  {text}")
        else:
            name, rva = where
            print(f"{off:8X}  {name:8} {info['base'] + rva:12X}  {text}")


if __name__ == "__main__":
    main()
```

Новое:

- **`import pe_info`** — твой собственный модуль. Python ищет файл
  `pe_info.py` рядом со скриптом и подключает его функции:
  `pe_info.load`, `pe_info.off_to_rva`. Благодаря строке
  `if __name__ == "__main__"` из П6.8 его `main()` не запустится;
- **`enumerate(data)`** — перебирать сразу номер и значение: `i` —
  смещение, `b` — байт. Как `for (i = 0; …)` и `data[i]` вместе;
- **`start = None`** — «цепочки пока нет». Встретили печатный байт —
  запомнили начало. Встретили непечатный — если цепочка была длиной
  от `MIN`, сохраняем её;
- **`word not in text`** — фильтр: если второй аргумент задан, печатаем
  только строки, где он встречается. Большие и маленькие буквы
  различаются: по `Verno` найдётся `[+] Verno…`, а `[-] Neverno.` —
  нет.

мусор вроде такого:

Это не текст. Байты `5B 5E 5F 41 5C 41 5D 41 5E 41 5F 5D` случайно
печатные, а на деле это машинный код — конец функции:

```
5b       pop rbx
5e       pop rsi
5f       pop rdi
41 5c    pop r12
41 5d    pop r13
41 5e    pop r14
41 5f    pop r15
5d       pop rbp
```

Функция возвращает сохраняемые регистры (глава 12, П2.4), а следом
идёт `c3` — `ret`, байт непечатный, и цепочка обрывается. Такие
«строки» из кода выдаёт любой простой поиск. Опытный реверсер узнаёт
их с первого взгляда, теперь узнаешь и ты.

## П6.10. Проект: снять XOR

В главе 17 ты расшифровал пароль задачи 02, прочитав листинг: таблица
по адресу `140009000`, ключ `5Ah` из `xor eax, 5Ah`, длина `11h`
из `mov edx, 11h` перед вызовом `decrypt`. Теперь — инструмент,
который берёт эти три числа и сам достаёт текст из файла.

Файл `xor_dump.py`:

```python
# xor_dump.py — прочитать байты по адресу из дизассемблера и снять XOR
import sys
import pe_info


def main():
    if len(sys.argv) < 5:
        sys.exit("zapusk: python xor_dump.py fail.exe ADRES DLINA KLYUCH  (vsyo v hex)")
    info = pe_info.load(sys.argv[1])
    va = int(sys.argv[2], 16)             # адрес, как в IDA: 140009000
    size = int(sys.argv[3], 16)
    key = int(sys.argv[4], 16)
    off = pe_info.rva_to_off(info, va - info["base"])
    if off is None:
        sys.exit("takogo adresa v faile net")
    enc = info["data"][off:off + size]
    dec = bytes(b ^ key for b in enc)
    print("smeshchenie v faile:", hex(off))
    print("bylo:  ", enc.hex(" "))
    print("stalo: ", dec.hex(" "))
    print("tekst: ", dec.decode("ascii", "replace"))


if __name__ == "__main__":
    main()
```

```
python xor_dump.py 02_xor.exe 140009000 11 5A
```

```
smeshchenie v faile: 0x7600
bylo:   22 35 28 05 32 33 3e 3f 29 05 34 35 2e 32 33 34 3d
stalo:  78 6f 72 5f 68 69 64 65 73 5f 6e 6f 74 68 69 6e 67
tekst:  xor_hides_nothing
```

Путь числа тот же, что в главе 8: адрес из IDA → минус база → RVA →
по таблице секций → смещение в файле → байты → XOR. Раньше ты делал
каждый шаг руками, теперь их делает программа, и ошибиться на шаге
нельзя.

Ошибёшься с ключом — `5B` вместо `5A` — получишь бессмыслицу
`yns^ihedr^onuihof`. Это тоже ответ: значит, ключ не тот. Ошибёшься
с адресом — программа скажет `takogo adresa v faile net`, а не
прочитает чужие байты молча.

Однобайтовый XOR постоянно встречается в разборах вредоносов: это
самый дешёвый способ спрятать строки от поиска (глава 17). Поэтому
такой скрипт — не игрушка, а заготовка для работы. Что делать, если
ключ неизвестен, — упражнение П6.4.
