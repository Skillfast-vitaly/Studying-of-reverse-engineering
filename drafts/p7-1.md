## П7.1. Зачем реверсеру C++

Программу на C ты уже читаешь: функции, переменные, указатели,
структуры. C++ добавляет к этому **классы** — структуры, у которых есть
свои функции. И почти каждая возможность C++ оставляет в машинном коде
узнаваемый след:

| В исходнике C++ | Что видно в листинге |
|---|---|
| метод класса | функция, у которой первый аргумент `RCX` — адрес объекта |
| `new` | вызов `operator new` с размером объекта |
| виртуальная функция | вызов через таблицу: `call qword ptr [rax+…]` |
| имя метода | длинное «искажённое» имя: `?name@Dog@@UEBAPEBDXZ` |
| класс с виртуальными функциями | строка `.?AVDog@@` в данных |
| `throw` | вызов `_CxxThrowException` |

Реверсер C++-программы восстанавливает **классы**: какие функции
принадлежат какому классу, какие поля лежат по каким смещениям, кто
от кого наследует. Это та же работа, что ты делал с задачами, только
единица разбора крупнее: не функция, а класс.

## П7.2. Чем собирать: g++ и Visual Studio

Собирать примеры можно двумя компиляторами, и полезно уметь оба.

**g++ из w64devkit** у тебя уже есть (глава 6): это C++-брат `gcc`.
В консоли w64devkit:

```
g++ -O1 -o zoo.exe zoo.cpp
./zoo.exe
```

**Visual Studio 2026 Community** — компилятор, которым собрано
большинство программ Windows. Она всё равно понадобится в главе 29
для драйверов. Если ещё не ставил — поставь сейчас только шаг 1 из
раздела 29.4: рабочая нагрузка **Desktop development with C++**,
без WDK. Собирать удобно из особой консоли: в меню «Пуск» набери
`x64 Native` и открой **x64 Native Tools Command Prompt for VS…**
(«командная строка x64 с инструментами»). Имя ярлыка кончается
по-разному в разных версиях — ищи по началу. В ней:

```
cd C:\reverse\work\cpp
cl /O1 /EHsc zoo.cpp
zoo.exe
```

`cl` — компилятор C и C++ от Microsoft. `/O1` — оптимизация, `/EHsc` —
включить исключения C++ (о них в П7.9). Получится `zoo.exe`.

Зачем два компилятора? Чужие программы чаще собраны Visual Studio — их
приметы и надо знать. А твои учебные — g++. И один и тот же исходник
они превращают в разный машинный код: в П7.5 ты увидишь, что даже
размер объекта у них разный. Реверсер всегда сначала узнаёт
компилятор (глава 7), а потом читает листинг по его правилам.

## П7.3. Класс и скрытый аргумент `this`

Вот программа, на которой построено всё приложение. Создай папку
`C:\reverse\work\cpp` и в ней файл `zoo.cpp`:

```cpp
#include <stdio.h>

class Animal {
public:
    Animal(int legs) : legs_(legs) {}
    virtual ~Animal() {}
    virtual const char *name() const { return "zver"; }
    virtual int speak() const { return puts("..."); }
    int legs() const { return legs_; }
protected:
    int legs_;
};

class Dog : public Animal {
public:
    Dog() : Animal(4), bones_(0) {}
    const char *name() const override { return "sobaka"; }
    int speak() const override { return puts("gav!"); }
    void give_bone() { bones_++; }
private:
    int bones_;
};

class Bird : public Animal {
public:
    Bird() : Animal(2) {}
    const char *name() const override { return "ptica"; }
};

int count_legs(Animal **zoo, int n)
{
    int total = 0;
    for (int i = 0; i < n; i++)
        total += zoo[i]->legs();
    return total;
}

void talk(const Animal *a)
{
    puts(a->name());
    a->speak();
}

void feed(Dog *d)
{
    d->give_bone();
}

int main()
{
    Animal *zoo[2] = { new Dog(), new Bird() };
    for (int i = 0; i < 2; i++)
        talk(zoo[i]);
    feed(static_cast<Dog *>(zoo[0]));
    printf("nog vsego: %d\n", count_legs(zoo, 2));
    delete zoo[0];
    delete zoo[1];
    return 0;
}
```

Вывод:

```
sobaka
gav!
ptica
...
nog vsego: 6
```

Не пугайся, разберём по кусочку. Сначала — первые строки класса
`Animal` («животное»):

- **`class Animal { … };`** — класс. Это структура из главы 5 и П1.4,
  в которой, кроме полей, есть функции. Функции класса называются
  **методами** (method `[мéсод]`);
- **`int legs_;`** — поле, как в структуре. Подчёркивание в конце —
  просто привычка многих программистов помечать поля, языку оно
  безразлично;
- **`public:`** и **`protected:`** — кому можно трогать то, что ниже:
  `public` («открыто») — всем, `protected` («защищено») — только самому
  классу и его наследникам, `private` («закрыто») — только самому
  классу. Это правила для компилятора: в машинном коде их нет;
- **`int legs() const { return legs_; }`** — метод: «вернуть число
  ног». `const` после скобок обещает, что метод не меняет объект.

Главное — как метод узнаёт, **чьи** ноги вернуть? Объектов `Animal`
может быть сколько угодно. Ответ: компилятор тайно передаёт методу
адрес объекта. Этот скрытый аргумент называется **`this`** `[зис]`,
«этот». В Windows x64 он идёт **первым аргументом, в `RCX`** (глава 12).
Запись `legs_` внутри метода значит `this->legs_`.

То есть метод — это обычная функция C из П1, которой передали
указатель на структуру:

```c
/* как метод выглядит «изнутри», на языке C */
int Animal_legs(const struct Animal *this) { return this->legs_; }
```

Посмотрим на настоящий машинный код. Метод `give_bone` («дать кость»)
у собаки увеличивает поле `bones_`. В отладочной сборке, где компилятор
ничего не встраивает (у Visual Studio это сборка Debug), он выглядит так:

```
Dog::give_bone:
    push    rax
    mov     [rsp], rcx              ; сохранить this
    mov     rax, [rsp]              ; rax = this
    mov     ecx, [rax+10h]          ; ecx = this->bones_
    add     ecx, 1
    mov     [rax+10h], ecx          ; this->bones_ = ecx
    pop     rax
    retn
```

Ни одного явного аргумента у метода нет, а `RCX` используется — это
и есть `this`. Поле `bones_` лежит по смещению `10h` от начала объекта.
Почему именно там — в П7.5.

А в сборке с оптимизацией (`-O1`, у Visual Studio — Release) компилятор
**встроил** метод прямо в функцию `feed`:

```
feed:
    inc     dword ptr [rcx+10h]     ; d->bones_++
    retn
```

Одна инструкция. Узнать в ней вызов метода по листингу нельзя — видно
только «увеличить поле по смещению `10h` у объекта из `RCX`». Так
и восстанавливают классы: по смещениям от `this` собирают, какие поля
у объекта есть.

> а имена функций расшифровал: в настоящем файле они будут длинными
> искажёнными (П7.7). Комментарии после `;` — мои.
