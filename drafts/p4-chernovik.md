# Приложение П4. Читаем документацию Intel

> **Приложения к курсу**
> Когда проходить: после [приложения П3](p3-gonki-i-blokirovki.md)
> и **до главы 35**. Опирается на главы [9](09-processor.md),
> [33](33-sistemnye-registry.md), [34](34-preryvaniya.md) и на
> приложения [П2](p2-assembler-pishem-sami.md) и П3.

Брат, это последнее приложение из проверки курса на полноту. И,
пожалуй, самое важное для твоей мечты.

Вот честная правда. Ни один курс, ни этот, ни любой другой, не
расскажет про процессор **всё**. Гипервизор — это сотни полей, битов
и правил, и каждое где-то описано. Где? В двух огромных книгах:
**документации Intel** и **документации AMD**. Все, кто пишет
гипервизоры, — авторы Hyper-V, VMware, KVM, учебных гипервизоров с
GitHub — сидят с этими книгами открытыми. Когда в главе 33 я писал
«бит 13 `CR4` — это `VMXE`», я брал это оттуда.

Проблема в том, что книги на английском, их тысячи страниц и язык
в них особый, юридически точный. С английским A2 это кажется стеной.
Это приложение — лестница через неё. Мы не будем учить английский
вообще. Мы выучим **язык этих книг**: около сотни слов и оборотов,
устройство страниц и способ читать, не теряя смысла.

После приложения ты будешь уметь:

- находить нужную книгу и нужный том у Intel и у AMD;
- читать страницу любой инструкции по частям: таблица, описание,
  псевдокод, исключения;
- понимать псевдокод Intel: стрелки, `IF … FI`, записи вроде
  `EDX:EAX` и `EBX[31:24]`;
- знать сотню слов, на которых держится документация, и их
  **точный** смысл (`set`, `clear`, `reserved`, `must`, `may`…);
- пользоваться переводчиком так, чтобы он не исказил смысл;
- находить место в книге на 5000 страниц за минуту;
- проверять по первоисточнику всё, что прочитал в курсе, в статье или
  на форуме.

Приложение около 800 строк. Проходи **в три захода**:

| Заход | Разделы | О чём |
|---|---|---|
| 1 | П4.1–П4.4 | какие бывают книги, как устроена страница инструкции |
| 2 | П4.5–П4.7 | псевдокод, проверка знаний по документации, словарь |
| 3 | П4.8–П4.12 | переводчик, поиск, AMD, порядок чтения, итоги |

Одна оговорка про примеры. Страницы, которые я цитирую, взяты из
зеркала справочника инструкций Intel на GitHub (проект `x86doc`,
HTML-версия томов 2). Это **не самая свежая ревизия**: сайт Intel
из моего облака недоступен. Текст описаний инструкций между ревизиями
почти не меняется, а вот **номера глав и таблиц меняются**. Об этом —
раздел П4.9.

## П4.1. Почему первоисточник

Представь цепочку. Инженер Intel описал бит в документации. Автор
статьи прочитал и пересказал. Блогер прочитал статью и пересказал ещё
раз. Ты читаешь блогера. На каждом шаге кто-то мог ошибиться,
упростить или взять старую ревизию.

В реверсе и в системном программировании ошибка в одном бите — это
синий экран. Поэтому у профессионалов правило:

> **Любой факт о процессоре проверяется в документации производителя.**
> Статьи, книги, этот курс — чтобы понять идею. Документация — чтобы
> узнать точно.

Этот курс тоже не исключение. В главе 33 я честно помечал «не
проверено» там, где не мог сверить. После этого приложения ты сможешь
сверить сам.

И ещё одно. Документация Intel написана очень точно. Каждое слово
выбрано. Когда там сказано `must`, это значит «обязательно, иначе
сломается». Когда `may`, это значит «процессор вправе, но не обязан».
Разница между этими словами — разница между работающим гипервизором
и сломанным. Поэтому слова мы будем учить **точно**, а не «примерно».

## П4.2. Какие книги и где их взять

### Intel

Официальное название: **Intel® 64 and IA-32 Architectures Software
Developer's Manual**. Сокращённо — **SDM** `[эс-ди-э́м]`, «руководство
разработчика программ». Когда в статьях пишут «см. SDM», имеют в виду
её.

- **Intel 64** — это x86-64 в терминах Intel, то есть 64-битный режим
  из главы 33. **IA-32** — старое 32-битное имя. Книга одна на оба.
- Где взять: на сайте Intel есть страница **Intel® 64 and IA-32
  Architectures Software Developer Manuals**. Найди её поиском по
  словам `Intel SDM`. Там лежат PDF-файлы: и весь комплект одним
  файлом (**Combined Volumes**, «объединённые тома», около 5000
  страниц), и тома по отдельности.
- Книга обновляется несколько раз в год. У каждой версии свой номер
  **ревизии** (revision `[ривúжен]`) в конце номера документа, вида
  `325462-0xxUS`. Бери **самую свежую**, это важно для новых
  процессоров вроде твоего 13400F. Номер текущей ревизии я не смог
  проверить, сайт Intel из облака закрыт. **Проверь на сайте сам.**

Удобная копия для ежедневной работы — сайт **felixcloutier.com/x86**.
Это неофициальная HTML-версия справочника инструкций Intel (томов 2),
по странице на инструкцию. Искать там быстрее, чем в PDF. Но помни:
это пересказ, а не первоисточник. В спорном случае открывай PDF Intel.

### AMD

Официальное название: **AMD64 Architecture Programmer's Manual**.
Сокращённо — **APM** `[эй-пи-э́м]`, «руководство программиста». Лежит
на сайте AMD, найдёшь поиском по словам `AMD64 Architecture
Programmer's Manual`. Там несколько томов, нам нужны два:

- **Volume 2: System Programming** (номер документа 24593) —
  системное программирование: режимы, страничная память, прерывания
  и **SVM**, то есть AMD-V (глава 33);
- **Volume 3: General-Purpose and System Instructions** (24594) —
  справочник инструкций.

У AMD тоже есть ревизии, вида `3.4x`. Бери свежую, и тоже **проверь
на сайте**.

Какую книгу читать тебе? **Обе**. У тебя два компьютера: на Intel
твой гипервизор будет работать через VT-x, на Ryzen — через AMD-V.
Про общие вещи (инструкции, страничная память) книги говорят одно
и то же, а про виртуализацию — разное.

## П4.3. Как устроена книга Intel

Комплект Intel делится на четыре тома, а тома — на части с буквами:

| Том | Название (англ.) | Перевод | Что там | Нам нужно |
|---|---|---|---|---|
| 1 | Basic Architecture | базовая архитектура | регистры, типы данных, режимы — как в главах 9–10 | для повторения |
| 2A–2D | Instruction Set Reference | справочник инструкций | по странице на каждую инструкцию, по алфавиту | **постоянно** |
| 3A–3D | System Programming Guide | руководство по системному программированию | страничная память, защита, прерывания, **виртуализация VMX** | **главное для гипервизора** |
| 4 | Model-Specific Registers | регистры, зависящие от модели | список всех MSR (глава 33) по номерам | когда нужен MSR |

Том 3 — это, по сути, продолжение наших глав 32–34 на тысячу страниц.
Страничная память, системные регистры, прерывания, TSS — всё там,
только подробно. А в части **3C** — всё про **VMX**, то есть VT-x. Это
твоя главная книга на годы вперёд.

Внутри каждого тома — главы (Chapter), разделы (Section) с номерами
вида `8.1.2`, рисунки (Figure) и таблицы (Table) с номерами вида
`Table 2-2`. В начале PDF — оглавление (Contents), в самом PDF —
закладки (Bookmarks), по ним удобно прыгать.

## П4.4. Страница инструкции по частям

Самое частое, что ты будешь открывать, — страница одной инструкции
в томе 2. Все они устроены одинаково. Разберём настоящую страницу
**RDTSC** — ту самую инструкцию, для которой ты писал обёртку в П2.8.

### Заголовок

```
RDTSC—Read Time-Stamp Counter
```

Имя инструкции и расшифровка: «прочитать счётчик отметок времени».
Отсюда и буквы: **R**ea**D** **T**ime-**S**tamp **C**ounter.

### Таблица кодов

```
Opcode*  Instruction  Op/En  64-Bit Mode  Compat/Leg Mode  Description
0F 31    RDTSC        NP     Valid        Valid            Read time-stamp counter into EDX:EAX.
```

| Столбец | Перевод | Что значит |
|---|---|---|
| **Opcode** | код операции | байты машинного кода: у `rdtsc` это `0F 31`. Их ты видишь в x64dbg слева от инструкции |
| **Instruction** | инструкция | как её пишут на ассемблере |
| **Op/En** | Operand Encoding, кодирование операндов | ссылка на маленькую таблицу ниже: как закодированы операнды. `NP` — операндов нет |
| **64-Bit Mode** | 64-битный режим | `Valid` — работает, `N.E.` (Not Encodable) — в этом режиме так закодировать нельзя, `Invalid` — не работает |
| **Compat/Leg Mode** | режим совместимости и старые режимы | то же для 32-битных режимов |
| **Description** | описание | одна фраза, что делает |

Сравни с тем, что ты уже знаешь. В П2.8 ты писал: «`rdtsc` отдаёт
счётчик в `EDX:EAX`». Таблица говорит то же: *Read time-stamp counter
into EDX:EAX* — «прочитать счётчик в `EDX:EAX`».

У многих инструкций в таблице **несколько строк**: по строке на
каждый вариант операндов. Например, у `xchg` шестнадцать строк: обмен
двух регистров, регистра с памятью, байтов, слов и так далее.

### Описание (Description)

Самая важная часть. Вот её начало у `rdtsc` и перевод по предложениям:

> *Reads the current value of the processor's time-stamp counter
> (a 64-bit MSR) into the EDX:EAX registers.*

«Читает текущее значение счётчика отметок времени процессора
(64-битного MSR) в регистры `EDX:EAX`». Заметь: счётчик — это MSR,
как в главе 33.

> *The EDX register is loaded with the high-order 32 bits of the MSR
> and the EAX register is loaded with the low-order 32 bits.*

«В регистр `EDX` загружаются **старшие** 32 бита MSR, а в `EAX` —
**младшие** 32 бита». **High-order** `[хай-óрдер]` — старшие,
**low-order** `[лóу-óрдер]` — младшие. Эти два слова будут везде.

> *(On processors that support the Intel 64 architecture, the
> high-order 32 bits of each of RAX and RDX are cleared.)*

«На процессорах с поддержкой Intel 64 старшие 32 бита у каждого из
`RAX` и `RDX` **обнуляются**». Вот оно, слово **cleared** — «сброшены
в 0». Не «очищены» в смысле «стали понятнее», а именно **стали нулями**.
Помнишь, в П2.8 я написал, что `rdtsc` обнуляет верхние половины?
Вот откуда я это взял.

> *The time stamp disable (TSD) flag in register CR4 restricts the use
> of the RDTSC instruction as follows. When the flag is clear, the
> RDTSC instruction can be executed at any privilege level; when the
> flag is set, the instruction can only be executed at privilege
> level 0.*

«Флаг запрета отметок времени (TSD) в регистре `CR4` ограничивает
использование `rdtsc` так. Когда флаг **сброшен** (равен 0), `rdtsc`
можно выполнять на любом уровне привилегий; когда флаг **установлен**
(равен 1) — только на уровне привилегий 0».

Здесь два слова-близнеца, самые важные во всей документации:

- **set** `[сет]` — бит **равен 1**;
- **clear** `[клир]` — бит **равен 0**.

Не «установить что-то» вообще и не «очистить», а ровно «1» и «0».
А **privilege level 0** — это кольцо 0 из главы 27. Значит, Windows
могла бы запретить программам `rdtsc`, подняв бит TSD в `CR4`. Она
этого не делает, поэтому твой `my_rdtsc` из П2 работает в кольце 3.

### Операция (Operation)

Псевдокод, точное описание на полуформальном языке. Разберём его
в П4.5.

### Флаги (Flags Affected)

Какие флаги (глава 9) меняет инструкция. У `rdtsc`: *None* — никакие.

### Исключения

Несколько разделов, по одному на каждый режим процессора. У `rdtsc`:

```
Protected Mode Exceptions
#GP(0)  If the TSD flag in register CR4 is set and the CPL is greater than 0.
#UD     If the LOCK prefix is used.
...
64-Bit Mode Exceptions
Same exceptions as in protected mode.
```

| Строка | Перевод |
|---|---|
| Protected Mode Exceptions | исключения в защищённом режиме |
| `#GP(0)` | общее нарушение защиты (глава 34, вектор 13) с кодом ошибки 0 |
| If the TSD flag in register CR4 is set and the CPL is greater than 0 | если флаг TSD в `CR4` установлен **и** текущий уровень привилегий больше 0 |
| `#UD` | недопустимая инструкция (вектор 6) |
| If the LOCK prefix is used | если использован префикс `lock` (П3.4) |
| 64-Bit Mode Exceptions — Same exceptions as in protected mode | исключения в 64-битном режиме — те же, что в защищённом |

**CPL** — Current Privilege Level, «текущий уровень привилегий», те
самые два младших бита `CS` из главы 27.

Этот раздел — чистое золото для реверсера. Он говорит **точно**, какое
исключение будет и когда. Помнишь таблицу векторов из главы 34? Здесь
она для каждой инструкции отдельно.
