
## П6.12. IDAPython в деле

В П5.12 ты запустил два первых скрипта: список функций и поиск
вызовов. Теперь — два скрипта, какие пишут на работе: первый ищет
подозрительное место в коде, второй сам подписывает расшифрованную
строку.

Два удобства, о которых в П5 не было (из описания IDAPython в SDK
IDA 9.2):

- **Shift+F2** — окно, куда можно вписать сразу несколько строк
  Python и выполнить их (в описании: «Execute Python statement(s)» —
  «выполнить команды Python»). Удобно пробовать кусок кода, не создавая
  файл;
- **Alt+F9** — недавние скрипты (View → Recent Scripts, «Вид →
  Недавние скрипты»): повторный запуск без поиска файла.

### Скрипт 1: какой `xor` подозрителен

Из главы 10 ты знаешь: `xor eax, eax` — просто обнуление. А вот `xor`
с числом или с другим регистром — возможная расшифровка (глава 17).
Пусть IDA сама пройдёт по всем функциям и покажет такие места.

Файл `p6_find_xor.py`:

```python
# p6_find_xor.py — найти xor, который НЕ обнуляет регистр
import idautils
import idc

count = 0
for func in idautils.Functions():
    for ea in idautils.FuncItems(func):
        if idc.print_insn_mnem(ea) != "xor":
            continue
        a = idc.print_operand(ea, 0)
        b = idc.print_operand(ea, 1)
        if a == b:
            continue                      # xor eax, eax — обнуление (глава 10)
        print("%X  %-12s xor %s, %s" % (ea, idc.get_func_name(ea), a, b))
        count += 1
print("najdeno: %d" % count)
```

Новые функции IDA (имена сверены с исходниками IDAPython 9.2):

- `idc.print_insn_mnem(ea)` — мнемоника инструкции по адресу
  (глава 9): `"xor"`, `"mov"`;
- `idc.print_operand(ea, n)` — операнд номер `n` текстом, как на
  экране: `0` — первый, `1` — второй;
- `continue` — «пропустить остаток тела цикла и взять следующий
  элемент», как в C.

Открой в IDA `02_xor.exe`, дождись `AU: idle` и запусти скрипт
(**Alt+F7**). У меня на той же сборке получилось так:

```
1400014FF  decrypt      xor eax, 5Ah
1400050CC  __gdtoa      xor eax, 1Fh
140005D82  __gdtoa      xor r12d, 1Fh
1400071B7  __b2d_D2A    xor edi, 1Fh
14000735D  __d2b_D2A    xor ecx, 1Fh
najdeno: 5
```

Имена функций у тебя могут быть другими — например, `sub_…`, если
IDA их не узнала. Адреса совпадут, если сборка та же.

Из почти 150 инструкций `xor` в файле фильтр оставил пять. Первая —
наша `decrypt` с ключом `5Ah`, попадание. Остальные четыре — в коде
библиотеки C, который печатает дробные числа. Там `xor` с `1Fh` (31)
стоит после инструкции `bsr` — «найти старший единичный бит».
`31 XOR номер_бита` — это счёт нулей перед ним, а вовсе не шифр.

Это и есть **ложное срабатывание** (false positive `[фолс пóзитив]`):
правило поймало то, что только похоже на искомое. Любой поиск по
приметам выдаёт и такое, поэтому скрипт не решает за тебя, а сужает
круг: вместо 150 мест глазами проверить пять.

### Скрипт 2: расшифровать и подписать

Второй скрипт делает то же, что `xor_dump.py` из П6.10, но внутри
IDA — и оставляет результат в базе комментарием.

Файл `p6_xor_comment.py`:

```python
# p6_xor_comment.py — расшифровать XOR под курсором и подписать
import idc

KEY = 0x5A                    # из инструкции xor eax, 5Ah
SIZE = 0x11                   # из main: mov edx, 11h перед call decrypt

ea = idc.here()               # курсор стоит на первом байте таблицы
data = idc.get_bytes(ea, SIZE)
if data is None:
    print("ne udalos prochitat %X" % ea)
else:
    text = bytes(b ^ KEY for b in data).decode("ascii", "replace")
    idc.set_cmt(ea, "XOR %02Xh: %s" % (KEY, text), 1)
    print("%X  %s" % (ea, text))
```

- `idc.get_bytes(ea, size)` — прочитать байты из базы. Вернёт
  `bytes` или `None`, если адреса нет;
- `idc.set_cmt(ea, текст, 1)` — поставить комментарий. Последний
  аргумент: `0` — обычный, `1` — **повторяемый** (П5.7). Повторяемый
  IDA покажет ещё и везде, где на этот адрес ссылаются.

Как запустить: в `decrypt` дважды щёлкни по имени таблицы в строке
с `lea` — IDA перейдёт к первому байту зашифрованного пароля. Не сдвигая
курсор, нажми **Alt+F7** и выбери `p6_xor_comment.py`. В Output
появится:

```
140009000  xor_hides_nothing
```

А в листинге рядом с таблицей — комментарий `XOR 5Ah:
xor_hides_nothing`. Вернись в `decrypt` (Esc): благодаря повторяемому
комментарию расшифровка видна и у строки с `lea`. Теперь любой, кто
откроет базу — ты через месяц или коллега, — сразу увидит, что здесь
спрятано.

Скрипт ничего не меняет в программе: ни в файле, ни в байтах базы.
Он только читает и подписывает. Убрать подпись можно, как в П5.7:
курсор на строку, клавиша `;`, стереть текст.

Так работают и большие скрипты вирусных аналитиков: найти все места,
где вызывается функция расшифровки, взять её аргументы, расшифровать
и подписать каждое. Разница только в том, что их ключи и адреса
находит сам скрипт, а не человек.

## П6.13. Ghidra на Python: PyGhidra

В Ghidra 12 Python 3 подключается через **PyGhidra** `[пай-гúдра]`:
настоящий Python соединяют с Java, на которой написана Ghidra.
Старый встроенный Python 2 (Jython) в Ghidra 12 по умолчанию больше
не включён — его можно доставить отдельным расширением, но учиться
на нём не стоит.

### Запуск Ghidra с Python

Ghidra нужно запускать особым способом (сверено по файлу
`GettingStarted.md` в исходниках Ghidra 12.1.4):

1. Открой папку Ghidra, в ней папку `support`.
2. Запусти **`pyghidraRun.bat`**.
3. В первый раз программа предложит поставить модуль `pyghidra` —
   соглашайся.

`pyghidraRun.bat` берёт Python командой `py` — то есть твою версию
по умолчанию. Ghidra 12.1.4 понимает 3.9–3.14. Если, кроме 3.13,
у тебя стоит и 3.15, по умолчанию будет она, и Ghidra не запустится.
Тогда скажи установщику, какую версию брать по умолчанию: заведи
переменную окружения `PYTHON_MANAGER_DEFAULT` со значением `3.13`
(так описано в документации Python для Windows).

### Скрипт: тот же XOR в Ghidra

Скрипты Ghidra лежат в папке `%USERPROFILE%\ghidra_scripts` — той же,
куда ты клал подсказчик (`tools/hints/README.md`). Создай там файл
`P6XorComment.py`:

```python
# Расшифровать XOR под курсором и подписать (приложение П6)
# @category: Kurs
# @runtime PyGhidra

KEY = 0x5A
SIZE = 0x11

data = getBytes(currentAddress, SIZE)     # байты Java: от -128 до 127!
text = "".join(chr((b & 0xFF) ^ KEY) for b in data)
setEOLComment(currentAddress, "XOR %02Xh: %s" % (KEY, text))
print("%s  %s" % (currentAddress, text))
```

Строки с `@` в начале — служебные: `@category` — в какую папку
Script Manager положит скрипт, `@runtime PyGhidra` — выполнять
настоящим Python 3. Так записаны примеры, которые идут с самой
Ghidra.

- `currentAddress` — адрес под курсором, как `idc.here()` в IDA;
- `getBytes(адрес, сколько)` — прочитать байты;
- `setEOLComment(адрес, текст)` — комментарий в конце строки (EOL —
  end of line). Как `;` в листинге IDA.

Запуск: открой `02_xor.exe` в Ghidra, поставь курсор на первый байт
таблицы, открой **Window → Script Manager**, найди папку `Kurs` и дважды
щёлкни по `P6XorComment.py`.

### Ловушка: байты Java со знаком

Главное отличие от IDA — в комментарии к `getBytes`. В Java тип `byte`
**знаковый**: от −128 до 127 (сама документация Ghidra пишет: «an array
of signed bytes» — «массив байтов со знаком»). Байт `0xC8` придёт
в Python как `-56` — помнишь чтение байта со знаком из главы 3?

Поэтому в скрипте стоит `b & 0xFF`: маска из П6.3 возвращает
привычные 0–255. Без неё на байте `0xC8` получится
`-56 ^ 0x5A = -110`, и `chr(-110)` упадёт с ошибкой
`ValueError: chr() arg not in range(0x110000)` — «аргумент chr вне
допустимого диапазона». В пароле задачи 02 все байты меньше `0x80`,
поэтому без маски скрипт сработал бы. Но первый же файл с ключом
побольше его сломает. Маску ставь всегда.

Скрипт я проверил так: подставил вместо Ghidra функции с теми же
именами, а байты задачи 02 перевёл в знаковые, как это делает Java.
В настоящей Ghidra он ещё не запускался. Если увидишь ошибку —
пришли мне её текст из окна Console.
