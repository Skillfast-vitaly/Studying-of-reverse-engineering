
## П9.15. Python читает запись трафика

Wireshark — готовый инструмент. Но иногда нужно своё: разобрать сотню
записей разом, вытащить из них одно поле, разложить самодельный
протокол, которого Wireshark не знает. Напишем свой маленький
разборщик для протокола задачи 06. Заодно увидишь, что внутри файла
записи нет никакой магии: те же заголовки из П9.2, лежащие подряд.

**Сохрани запись в простом формате.** Формат `.pcapng` из П9.5 гибкий,
но сложный. У него есть старший брат — **pcap** `[пи-кэп]`: заголовок
файла и записи подряд. В Wireshark: **File → Save As**, тип файла
**Wireshark/tcpdump/... - pcap**.

Как устроен файл `.pcap`. Знакомо по главе 8: в начале заголовок,
в нём **магическое число** — как `MZ` у программы:

| Где | Сколько байт | Что |
|---|---|---|
| начало файла | 24 | заголовок файла: магическое число `d4 c3 b2 a1`, версия, … , на смещении 20 — тип канала |
| перед каждым пакетом | 16 | заголовок записи: время и длина сохранённых байтов |
| дальше | сколько сказано | сам пакет: все конверты из П9.2 |

**Тип канала** (link type) говорит, какой первый конверт. Для нашей
петли он равен 0 — **Null/Loopback**, те самые 4 байта из П9.5.
Для обычной сетевой карты он равен 1 — **Ethernet**, 14 байт с MAC-адресами.

Внутри пакета нам нужны три поля IP-заголовка и три поля TCP:

- байт 0 заголовка IP — `0x45`: старшая половина `4` — версия IPv4,
  младшая `5` — длина заголовка в четырёхбайтовых словах, 5 × 4 = 20;
- байт 9 — какой транспорт внутри: 6 — TCP, 17 — UDP;
- байты 2–3 — длина всего пакета IP (порядок сети!);
- в TCP: байты 0–1 и 2–3 — порты, старшая половина байта 12 — длина
  заголовка TCP в словах, байт 13 — флаги.

Флаги TCP — это биты одного байта:

| Бит | Флаг |
|---|---|
| 0x01 | FIN |
| 0x02 | SYN |
| 0x04 | RST |
| 0x08 | PSH |
| 0x10 | ACK |

Значит, `0x12` — это SYN и ACK вместе, второй шаг рукопожатия. А `0x18` —
PSH и ACK, обычный пакет с данными. Это та же работа с битами, что
в П1.2 и в главе 33 с регистрами процессора.

Сам разборщик. Всё в нём ты уже видел: `struct` из П6.6, срезы байтов,
цикл чтения кадров из П9.11.

```python
# p9_razbor.py — свой разборщик записи трафика для протокола задачи 06.
# Читает файл .pcap (Wireshark: File -> Save As, тип "Wireshark/tcpdump/... - pcap"),
# находит пакеты TCP с портом 7777, собирает поток каждой стороны
# и раскладывает его на кадры: длина (2 байта, порядок сети), тип, данные.
import struct
import sys

PORT = 7777

def packets(path):
    """Отдаёт по одному: байты пакета, начиная с заголовка IP."""
    data = open(path, 'rb').read()
    magic = data[:4]
    if magic in (b'\xd4\xc3\xb2\xa1', b'\x4d\x3c\xb2\xa1'):
        e = '<'                                  # файл записан младшим байтом вперёд
    elif magic in (b'\xa1\xb2\xc3\xd4', b'\xa1\xb2\x3c\x4d'):
        e = '>'
    else:
        sys.exit('eto ne pcap (pcapng nado peresohranit kak pcap)')
    linktype = struct.unpack_from(e + 'I', data, 20)[0]
    pos = 24                                     # заголовок файла — 24 байта
    while pos + 16 <= len(data):
        incl_len = struct.unpack_from(e + 'I', data, pos + 8)[0]
        pkt = data[pos + 16:pos + 16 + incl_len]  # заголовок записи — 16 байт
        pos += 16 + incl_len
        if linktype == 0:                        # Null/Loopback: 4 байта, семейство
            yield pkt[4:]
        elif linktype == 1 and pkt[12:14] == b'\x08\x00':   # Ethernet, внутри IPv4
            yield pkt[14:]

streams = {'C': b'', 'S': b''}                   # что сказал клиент и что сервер
for ip in packets(sys.argv[1]):
    if ip[0] >> 4 != 4 or ip[9] != 6:            # нужен IPv4 и TCP (протокол 6)
        continue
    ihl = (ip[0] & 0x0F) * 4                     # длина заголовка IP
    tcp = ip[ihl:]
    sport, dport = struct.unpack_from('>HH', tcp, 0)
    if PORT not in (sport, dport):
        continue
    doff = (tcp[12] >> 4) * 4                    # длина заголовка TCP
    total = struct.unpack_from('>H', ip, 2)[0]    # длина всего пакета IP
    payload = ip[ihl + doff:total]
    who = 'C' if dport == PORT else 'S'
    print('%5d -> %-5d  flagi %02x  dannyh %3d' % (sport, dport, tcp[13], len(payload)))
    streams[who] += payload

def frames(stream):
    pos = 0
    while pos + 3 <= len(stream):
        length = struct.unpack_from('>H', stream, pos)[0]
        yield stream[pos + 2], stream[pos + 3:pos + 2 + length]
        pos += 2 + length

key = None
print()
for t, d in frames(streams['S']):
    if t == 0x81:
        key = d[0]
for who, name in (('C', 'klient'), ('S', 'server')):
    for t, d in frames(streams[who]):
        if t == 0x81:
            text = 'klyuch 0x%02x, %s' % (d[0], d[1:].decode())
        elif t == 0x82 and key is not None:
            text = bytes(b ^ key for b in d).decode()
        else:
            text = d.hex(' ') if t == 0x02 else d.decode(errors='replace')
        print('%s: tip 0x%02x  %s' % (name, t, text))
```

Два места стоит разобрать. Магическое число бывает в четырёх видах:
файл могли записать младшим байтом вперёд или старшим, а время —
в микросекундах или наносекундах. Наш Wireshark на x86 пишет младшим
вперёд, поэтому в начале `d4 c3 b2 a1`. А `ip[ihl + doff:total]` берёт
данные ровно до конца пакета IP: на сетевой карте Ethernet иногда
добивает короткие пакеты нулями, и без `total` эти нули попали бы
в поток.

Запуск: `py p9_razbor.py zapis.pcap`. Вот вывод на записи нашего
разговора из П9.8. Порт клиента у тебя будет другой:

```

51514 -> 7777   flagi 10  dannyh   0

51514 -> 7777   flagi 18  dannyh   4

51514 -> 7777   flagi 18  dannyh   3
```

Как я проверял. Записать трафик на маке, где я пишу курс, нельзя:
для этого нужны права администратора. Поэтому файл `.pcap` я собрал
сам из настоящих байтов нашей пары программ, строго по описанию
формата. Потом проверил его чужим разборщиком, независимым от моего:
контрольные суммы всех пакетов и номера Seq/Ack сошлись. Разборщик
прогнан на таком файле с петли, на том же разговоре с заголовками
Ethernet и на файле `.pcapng`, где он должен отказаться. На твоей
настоящей записи прогони его сам и пришли вывод.

Чего наш разборщик **не** умеет. Если пакет потерялся и TCP отправил
его повторно, данные попадут в поток дважды. Если пакеты пришли
не по порядку, поток склеится неверно. На петле такого почти не бывает.
Wireshark это умеет: смотрит на Seq и выбрасывает повторы. Доработать
так свой разборщик — хорошее упражнение после приложения. Готовая
библиотека для работы с пакетами на Python — **Scapy** `[скéйпи]`
(ставится командой `py -m pip install scapy`). Её стоит открыть, когда
своё уже понятно до байта.

## П9.16. Сеть и гипервизор

Как это связано с твоей вершиной — гипервизором? Напрямую.

Гостевая Windows в виртуальной машине думает, что у неё есть своя
сетевая карта. Карты нет. Есть гипервизор, который **притворяется**
картой. Есть два способа.

**Эмуляция настоящей карты.** Гипервизор изображает известную модель,
для которой у Windows есть драйвер. Драйвер гостя пишет в регистры
«карты»: в порты ввода-вывода или в память устройства. Каждая такая
запись останавливает гостя, и управление переходит гипервизору. Это
**выход из ВМ** — VM exit, тот самый, о котором шла речь в главах
33 и 34 и о котором подробно будет глава 35. Гипервизор смотрит, что
гость хотел сделать с «картой», берёт пакет из памяти гостя и
отправляет его дальше — через настоящую карту или виртуальный
коммутатор. Работает с любым гостем, но медленно: на каждый пакет
по несколько выходов.

**Своя виртуальная карта.** Гость знает, что он в машине, и ставит
особый драйвер. Пакеты кладутся в общую с гипервизором память, в
очередь, а выходы случаются редко, только чтобы сказать «в очереди
есть новое». Так быстрее. Поэтому Hyper-V и VMware ставят в гостя
свои драйверы: у Hyper-V карта работает через его внутреннюю шину
VMBus, у VMware — своя модель карты.

Ты уже пользовался этим, не замечая. В главе 30 отладчик ядра говорил
с виртуальной машиной по сети через виртуальный коммутатор Hyper-V,
и каждый пакет KDNET проходил ровно этот путь.

Что берём в гипервизор:

- **разбор чужого формата по байтам**: заголовки, длины, порядок
  байтов. Структуры VMCS (глава 36) и таблицы EPT (глава 37) читаются
  так же — по документации и по смещениям;
- **граница «гость — гипервизор»** устроена как граница «клиент —
  сервер»: всё, что пришло от гостя, — враг, пока не проверено.
  Сервер задачи 06 проверяет длину кадра. Гипервизор так же обязан
  проверять всё, что гость кладёт в общую память;
- **очередь в общей памяти** — тот же поток с длинами, только без TCP.

## П9.17. Что запомнить

- **Протокол** — договорённость, как устроены сообщения. Данные идут
  «конвертом в конверте»: канальный уровень (Ethernet или Null/Loopback
  на петле) → IP → TCP или UDP → протокол программы.
- **IP-адрес** — компьютер, **порт** — программа на нём. `127.0.0.1` —
  петля, «сам себе», дальше ПК не уходит.
- Числа в сетевых заголовках — **старшим байтом вперёд** (порядок
  сети). Функции `htons`, `ntohs`, `htonl` переставляют байты. В Python —
  `struct` с форматом `>`.
- **TCP**: рукопожатие SYN → SYN, ACK → ACK. Seq — номер первого байта
  пакета, Ack — следующий ожидаемый. FIN — вежливое прощание, RST —
  обрыв. TCP передаёт **поток**, а не сообщения. Поэтому в протоколе
  есть длина впереди или разделитель, а в коде — `recv` в цикле.
- **Wireshark**: петлю пишет **Adapter for loopback traffic capture**.
  Фильтр отображения (`tcp.port == 7777`, `tcp.len > 0`, `dns`, `http`,
  `tls`) прячет лишнее. **Follow TCP Stream** (Ctrl+Alt+Shift+T) склеивает
  разговор: клиент красным, сервер синим.
- **Протокол без описания**: догадка → проверка на **всех** сообщениях.
  Трафик показывает, что программы **сказали**, код — что они **умеют**.
  Восстановленный протокол проверяют своим клиентом.
- **TLS** скрывает содержимое, но видны адреса, порты, имя сайта
  (SNI), время и объём. Своё содержимое реверсер берёт изнутри:
  отладчиком до шифрования.
- Где Wireshark нет — встроенный **pktmon**, потом `etl2pcap`
  в `.pcapng`.
- Записывай и разбирай **только свой** трафик.
