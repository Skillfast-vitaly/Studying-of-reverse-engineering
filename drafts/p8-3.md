
## П8.9. Имена функций Rust

Как у C++ в П7.7, у Rust свои **искажённые имена**: в них зашито, где
функция лежит. Вот одна и та же функция `zadacha::zamok::proverka`
(функция `proverka` в модуле `zamok` программы `zadacha`) у двух
версий компилятора. Оба имени настоящие:

| Компилятор | Имя в файле |
|---|---|
| rustc 1.96 и старше | `_ZN7zadacha5zamok8proverka17hfcd155372e8f6368E` |
| rustc 1.97 и новее | `_RNvNtCskLUh0hM8zwv_7zadacha5zamok8proverka` |

**Старый вид** похож на имена g++ из П7.7: начало `_ZN`, конец `E`,
внутри куски с длиной впереди — `7zadacha`, `5zamok`, `8proverka`.
Хвост `17h…` — это 17 знаков: буква `h` и 16 шестнадцатеричных цифр.
Это хеш, отпечаток функции, а не часть имени. Читать его не нужно.

**Новый вид** — v0 — начинается с `_R`. Rust перешёл на него
в версии 1.97 (июль 2026). Правило чтения то же: число перед словом —
его длина. `Nv` значит «функция», `Nt` — «модуль или тип»,
а `Cs…_` перед именем программы — её отпечаток.

Что делать на практике:

- в IDA и Ghidra имена обычно расшифровываются сами. В Ghidra
  за это отвечает анализатор **Demangler GNU**, у него есть формат
  **rust**. Если имена остались `_R…`, проверь его настройки.
  Как у тебя покажет IDA 9.2, я проверить не могу — пришли мне;
- если имена есть — тебе повезло, это отладочная сборка или рядом
  лежит файл `.pdb` (П7.8). В чужой релизной программе имён обычно
  нет, и выручают строки паник из П8.8;
- увидел имя с `_R` или с `17h…E` — перед тобой Rust, даже если DIE
  этого не сказал.

## П8.10. Где начинается твой main

В C путь до `main` ты прошёл в главе 13: стартовый код библиотеки C,
потом `main`. В Rust между ними есть ещё одна ступенька. Вот функция
`main`, которую rustc ставит в `.exe`, — **не твоя**, а служебная
(rustc 1.99, отладочная сборка):

```
main:
        sub     rsp, 40
        mov     r8, rdx
        movsxd  rdx, ecx
        lea     rcx, [rip + example::main]   ; адрес ТВОЕГО main
        xor     r9d, r9d
        call    std::rt::lang_start::<()>
        nop
        add     rsp, 40
        ret
```

Цепочка такая:

1. стартовый код библиотеки C (как в главе 13) вызывает `main`;
2. служебный `main` отдаёт адрес **твоей** функции в `std::rt::lang_start`
   («запуск языка»), в релизной сборке — сразу в
   `std::rt::lang_start_internal`;
3. `lang_start` готовит стандартную библиотеку — обработку паник,
   аргументы — и только потом вызывает твой `main`.

Без имён вторая ступенька узнаётся так: короткая функция, которая
грузит `lea` адрес другой функции и сразу вызывает третью. Адрес
из `lea` — это и есть твой `main`. Но обычно быстрее путь из главы 16:
найди строку программы и пройди по перекрёстной ссылке. Строки
у программы на Rust есть всегда.

## П8.11. Отладочная и релизная сборка

У `cargo build` и `cargo build --release` разница больше, чем у `-O0`
и `-O2` в gcc. Отладочная сборка Rust **проверяет переполнение**
чисел, релизная — нет. Функция

```rust
pub fn add(a: u32, b: u32) -> u32 {
    a + b
}
```

в отладочной сборке:

```
        mov     ecx, eax
        add     ecx, edx                 ; сложили
        mov     dword ptr [rsp + 44], ecx
        cmp     ecx, eax                 ; сумма меньше слагаемого?
        jb      .LBB0_2                  ; да — переполнение, паника
        …
.LBB0_2:
        lea     rcx, [rip + …]
        call    core::panicking::panic_const::panic_const_add_overflow
        ud2
```

в релизной — одна инструкция:

```
        lea     eax, [rcx + rdx]
        ret
```

Проверка «сумма меньше слагаемого» — классический признак переполнения
без знака: если при сложении число перевалило через максимум, оно стало
меньше (глава 3.6). Видишь много таких `cmp`/`jb` с вызовами
`panic_const_…_overflow` — это отладочная сборка Rust.

Сравнение строк тоже меняется. Возьмём проверку пароля:

```rust
fn check(s: &str) -> bool {
    s == "rust_ne_strashen"
}
```

**Отладочная сборка** честно вызывает функцию сравнения:

```
        lea     rcx, [rsp + 40]          ; наша строка: адрес и длина
        lea     rdx, [rip + …]           ; образец: адрес и длина
        call    <&str as core::cmp::PartialEq>::eq
```

Пароль лежит среди строк файла, и способ 1 из главы 16 его находит.

**Релизная сборка** проверяет длину и сравнивает все 16 байт одной
инструкцией SSE — **pcmpeqb** («сравнить упакованные байты на
равенство»):

```
        cmp     r9, 16                   ; длина 16?
        …
        pcmpeqb xmm0, xmmword ptr [rip + __xmm@6e656873617274735f656e5f74737572]
```

Имя константы `__xmm@6e65…7572` — её содержимое, 16 байт числом.
Прочитай его по главе 3.7, младшим байтом вперёд: `72 75 73 74 5f 6e
65 5f 73 74 72 61 73 68 65 6e`. А это `rust_ne_strashen`. Пароль
спрятался в имени константы, и это уже уровень «тяжёлой сборки»
из главы 16.6.

И ещё одна примета релизной сборки. Строку ввода программа обрезала
методом `trim()` — «убрать пробелы по краям». В машинном коде это
длинная функция со сравнениями с числами **133**, **5760**, **12288**.
Это пробельные символы Unicode: U+0085, U+1680 и U+3000. Встретил
эту тройку чисел — рядом обработка пробелов, а значит, ввод
пользователя.

## П8.12. Практика: Rust в IDA

Создай проект `cargo new zadacha_rust` и запиши в `src\main.rs`:

```rust
fn check(s: &str) -> bool {
    s == "rust_ne_strashen"
}

fn main() {
    let mut line = String::new();
    std::io::stdin().read_line(&mut line).unwrap();
    if check(line.trim()) {
        println!("Dostup razreshon!");
    } else {
        println!("Otkazano.");
    }
}
```

Собери обе сборки: `cargo build` и `cargo build --release`. Проверь,
что программа работает: `target\debug\zadacha_rust.exe`, ввод
`rust_ne_strashen` — ответ `Dostup razreshon!`.

Теперь задание. Открой **релизную** сборку в IDA. Когда IDA предложит
загрузить файл `.pdb` с именами, откажись: представь, что программа
чужая. Сделай по шагам:

1. **Опознание.** Что скажет DIE (глава 7)? Какой у файла размер?
2. **Строки.** Найди `Dostup razreshon!` и `Otkazano.`. Слиплись ли
   они с соседними строками (П8.5)? Есть ли среди строк пароль?
3. **Пути.** Найди строки с `/rustc/`. Какой у твоего компилятора хеш?
   Сверь с `rustc -vV`.
4. **main.** По перекрёстной ссылке со строки `Dostup razreshon!` выйди
   на свою функцию `main`. Найди служебный `main` и `lang_start`
   (П8.10).
5. **Сравнение.** Найди проверку длины `16` и сравнение 16 байт.
   Достань пароль из константы, как в П8.11.

Потом открой **отладочную** сборку, уже с `.pdb`. Сравни: как IDA
показала имена, на месте ли `<&str as core::cmp::PartialEq>::eq`,
сколько стало вызовов `panic_const_…`. Пришли мне, что увидел:
вид окон и имён IDA для Rust я сверить не могу.

## П8.13. Rust на дороге к гипервизору

Драйверы на Rust — уже не эксперимент. Набор **windows-drivers-rs**
от Microsoft подключает Rust к WDK из главы 29: `cargo-wdk` создаёт
проект драйвера, `wdk-sys` даёт прямой доступ к функциям ядра, `wdk` —
обёртки поудобнее. Значит, и гипервизор, который загружается драйвером
(глава 35), можно написать на Rust. Такие проекты есть.

Что из этого приложения тебе там пригодится:

- в ядре стандартной библиотеки нет: код пишут с пометкой `#![no_std]`,
  без `String` и `println!`;
- паника в ядре — это синий экран, как с `win32kbase_rs.sys` в П8.1.
  Поэтому в коде ядра ошибки возвращают через `Result`, а не через
  `unwrap`;
- взаимодействие с Windows идёт через `extern "C"` и `extern "system"`:
  там действуют правила главы 12, а не внутреннее соглашение Rust.

Писать гипервизор будем на C, как и задумано в курсе. Но читать
чужие драйверы и гипервизоры на Rust ты теперь сможешь.

**Где учить язык дальше.** Официальная книга «The Rust Programming
Language» бесплатна на сайте **doc.rust-lang.org/book**. Есть её
русский перевод «Язык программирования Rust» — **doc.rust-lang.ru/book**. Для чтения кода хватит глав
о владении, о `struct` и `enum`, об обработке ошибок.

## Что запомнить

- **Срез** (`&[T]`, `&str`) — два значения: адрес и длина. В аргументах —
  два регистра, у `&str` нет нуля в конце, строки лежат вплотную.
- **Проверка границ**: `cmp` с длиной → прыжок → `panic_bounds_check` →
  `ud2`. В `ECX` — номер, в `RDX` — длина.
- **Vec и String** — три поля по 8 байт. Порядок не обещан:
  у rustc 1.99 вместимость +0, адрес +8, длина +16. Проверяй по коду.
- **Option<&T>** — указатель или 0. **Option<u32>** — метка и значение.
  `unwrap` → `unwrap_failed` и паника.
- **Паники** оставляют в файле `src\…`, `/rustc/<хеш>/…` и строки
  сообщений — подсказки даже без имён.
- **Имена**: старые `_ZN…17h…E`, с версии 1.97 — `_R…`. Числа перед
  словами — длины.
- **main**: служебный `main` → `lang_start` → твой `main`.
- **Отладочная сборка** проверяет переполнение (`panic_const_…_overflow`),
  релизная сжимает код: 16 байт сравниваются одной `pcmpeqb`.
- Правила главы 12 Rust соблюдает для `extern "C"`. Свои функции
  он вызывает по своим правилам — читай по коду.
