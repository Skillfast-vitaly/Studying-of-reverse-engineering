
## 29.6. Сборка

Наверху окна Visual Studio есть два выпадающих списка. Выбери
**Debug** («отладочная сборка») и **x64**. Потом меню **Build →
Build Solution** («сборка → собрать решение», клавиши **Ctrl+Shift+B**).

### Первая встреча с ошибкой, которая не ошибка

Попробуй ради опыта удалить строку `UNREFERENCED_PARAMETER(DriverObject);`
и собрать. Сборка **остановится**. В окне **Error List** («список
ошибок») будет примерно так:

```
warning C4100: 'DriverObject': unreferenced formal parameter
error C2220: the following warning is treated as an error
```

Перевод: «предупреждение C4100: `DriverObject` — неиспользуемый
формальный параметр» и «ошибка C2220: это предупреждение считается
ошибкой».

В проектах драйверов Visual Studio по умолчанию **строже**, чем в
обычных программах: самый подробный уровень предупреждений и режим
«предупреждение = ошибка» (Treat Warnings As Errors `[трит уóрнингз эз
э́рроз]`). Причина понятна после главы 27: в программе недосмотр
закрывает одну программу, в ядре — роняет систему. Лучше пусть
компилятор ворчит заранее. **Не выключай этот режим** — исправляй
код. Верни строку на место и собери снова.

Успешная сборка заканчивается в окне **Output** («вывод») строкой
вроде `Build: 1 succeeded, 0 failed` — «собрано: 1, ошибок: 0».

### Что получилось

Найди в папке проекта подпапку `x64\Debug`. Если файлов там много —
поищи в ней `Hello.sys` поиском Проводника. Нам важны два файла:

| Файл | Что это |
|---|---|
| `Hello.sys` | сам драйвер — PE-файл, как `.exe` и `.dll` |
| `Hello.pdb` | символы (глава 14): имена функций и переменных для отладчика. Пригодится в главе 30 |

Может оказаться и `Hello.cer` — это тестовый **сертификат**, которым
подписан драйвер. О нём — сейчас.

### Тестовая подпись

Помнишь правило из главы 27: 64-битная Windows не загружает в ядро
драйвер без цифровой подписи. **Цифровая подпись** (digital signature
`[дúджитал сúгнечер]`) — это зашифрованная отметка внутри файла:
«этот файл выпустил такой-то, и после этого в нём не изменён ни
один байт». Настоящие драйверы подписывает Microsoft после проверки.

Для разработки есть **тестовая подпись** (test signing `[тест
сáйнинг]`). Visual Studio сама создаёт сертификат с именем вроде
`WDKTestCert твоё_имя,...` и подписывает им Debug-сборку. Где это
настроено: правый клик по проекту → **Properties** → **Driver
Signing** → **General** → **Sign Mode: Test Sign** («режим подписи:
тестовая»). Трогать ничего не нужно, просто знай, где это.

Проверить подпись можно в самом Проводнике: правый клик по `Hello.sys`
→ **Свойства** → вкладка **Цифровые подписи**. Там должен быть
`WDKTestCert`. Нет такой вкладки — значит файл не подписан, и Windows
его не загрузит даже в тестовом режиме.

Обычная Windows такой подписи **не верит**: сертификат выдал ты сам
себе, а не Microsoft. Чтобы Windows ей поверила, машину переводят
в тестовый режим.

## 29.7. Тестовый режим в виртуальной машине

Всё дальше — **внутри виртуальной машины**. Не перепутай окна:
на основной машине тестовый режим нам не нужен.

Открой командную строку от имени администратора: **Win**, набери
`cmd`, правый клик по «Командная строка» → **Запуск от имени
администратора**. Введи:

```
bcdedit /set testsigning on
```

`bcdedit` `[би-си-ди-эдит]` — программа, которая правит настройки
загрузки Windows (BCD, Boot Configuration Data — «данные конфигурации
загрузки»). Команда означает: «при следующей загрузке разрешить
драйверы с тестовой подписью». Ответ должен быть «Операция успешно
завершена» (The operation completed successfully).

Если вместо этого ругается, что значение **защищено политикой Secure
Boot** (protected by Secure Boot policy) — ты не выключил Secure Boot
в настройках виртуальной машины. Вернись к шагу 5 раздела 29.3.

Перезагрузи виртуальную машину. После загрузки в правом нижнем углу
рабочего стола появится надпись **«Тестовый режим»** (Test Mode)
с номером сборки Windows. Это Windows честно предупреждает: «защита
ослаблена». Для лаборатории — ровно то, что нужно.

Сделай **новый снимок** машины: «тестовый режим». С этого снимка
ты будешь начинать все опыты с драйверами.

## 29.8. Загрузка: `sc` и DebugView

### DebugView — уши для ядра

Сообщения `DbgPrintEx` кто-то должен слушать. Взрослый путь — отладчик
ядра, глава 30. Пока возьмём **DebugView** `[дибáг вью]` из набора
Sysinternals (того же, что Process Monitor в главе 15). На сентябрь
2026 свежая версия — **5.02**.

Внутри виртуальной машины скачай DebugView с сайта Sysinternals
(найди поиском «DebugView Sysinternals»), распакуй в `C:\drivers\`
и запусти `Dbgview.exe`. Сообщения ядра он по умолчанию не слушает:
для этого нужен его **собственный драйвер** (подписанный Microsoft,
так что с ним всё в порядке). Включи: меню **Capture** («захват») →
**Capture Kernel** («захватывать сообщения ядра»). Windows спросит
права администратора — соглашайся.

Галочка **Capture Win32** («захватывать сообщения программ») нам
не мешает, но и не нужна.

### Регистрируем и запускаем

Скопируй `Hello.sys` с основной машины в `C:\drivers\` внутри
виртуальной (раздел 29.3). В командной строке администратора:

```
sc create Hello type= kernel binPath= C:\drivers\Hello.sys
```

`sc` `[эс-си]` — Service Control, «управление службами». Команда
`create` («создать») регистрирует службу с именем `Hello`, тип —
`kernel` (драйвер ядра), путь к файлу — `binPath`.

**Ловушка, на которой спотыкаются все:** после знака `=` обязателен
**пробел**, а перед ним пробела быть не должно. `type= kernel` —
правильно. `type=kernel` или `type = kernel` — `sc` не поймёт
и вместо работы выведет длинную справку о том, как им пользоваться.

Ответ примерно такой:

```
[SC] CreateService SUCCESS
```

«Служба создана». В реестре появился ключ
`HKLM\SYSTEM\CurrentControlSet\Services\Hello` — можешь найти его
в `regedit`. Драйвер пока **не загружен**, только записан. Запускаем:

```
sc start Hello
```

Ответ — примерно так (на русской Windows часть слов может быть
по-русски):

```
SERVICE_NAME: Hello
        TYPE               : 1  KERNEL_DRIVER
        STATE              : 4  RUNNING
                                (STOPPABLE, NOT_PAUSABLE, IGNORES_SHUTDOWN)
        WIN32_EXIT_CODE    : 0  (0x0)
        SERVICE_EXIT_CODE  : 0  (0x0)
        ...
```

`STATE: 4 RUNNING` — «состояние: работает», а `STOPPABLE` —
«можно остановить»: ядро увидело, что поле `DriverUnload` заполнено.

А в окне DebugView — **первые слова твоего кода в кольце 0**. Примерно
так, у тебя адреса будут другими:

```
Hello: privet iz kolca 0!
Hello: moy klyuch v reestre: \REGISTRY\MACHINE\SYSTEM\ControlSet001\Services\Hello
Hello: DriverEntry = FFFFF80712A31000, DriverObject = FFFFB60C4D2F3E30
Hello: PID = 4, IRQL = 0
```

Остановись здесь на минуту. Это не пример из книжки: это код, который
написал ты, и он выполнился на том же уровне, что и сердце Windows.

### Останавливаем и убираем

```
sc stop Hello
```

В DebugView появится `Hello: vygruzhayus. Poka!`, а `sc` покажет
`STATE: 1 STOPPED` — «остановлена». Ядро позвало нашу `HelloUnload`
и выгрузило драйвер из памяти.

Когда драйвер больше не нужен совсем:

```
sc delete Hello
```

— служба удалена, ключ реестра исчез.

### Цикл разработки

Дальше ты будешь ходить по кругу — и с гипервизором тоже:

1. правка кода и сборка на основной машине;
2. `sc stop Hello` в виртуальной (старая версия выгружена —
   иначе файл занят и не заменится);
3. копирование нового `Hello.sys` в `C:\drivers\` с заменой;
4. `sc start Hello` и чтение DebugView.

`sc create` повторять не нужно: служба уже записана, меняется только
файл.

### Когда что-то пошло не так

`sc` сообщает об ошибке номером — это код ошибки Win32 из главы 28.
Самые частые:

| Номер | Что `sc` пишет (перевод) | Что это значит |
|---|---|---|
| 2 | Не удаётся найти указанный файл | опечатка в `binPath` или файл не скопирован |
| 577 | Windows не удаётся проверить цифровую подпись этого файла | тестовый режим не включён или файл не подписан |
| 1052 | Запрошенный управляющий код недопустим для данной службы | ты сказал `sc stop`, а у драйвера нет `DriverUnload` |
| 1056 | Одна копия службы уже запущена | `sc start` второй раз подряд |
| 1073 | Указанная служба уже существует | `sc create` второй раз подряд |

Если `DriverEntry` вернёт не `STATUS_SUCCESS`, а код ошибки, `sc
start` тоже сообщит ошибку, а драйвер в памяти не останется. Как
`NTSTATUS` превращается в номер Win32 — ты знаешь из главы 28.
Проверишь в упражнении 29.4.
