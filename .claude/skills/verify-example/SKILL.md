# Проверка примера

В реверсе цифра решает всё. Ученик сверяет свой экран с главой, и неверное
число в тексте заставит его думать, что ошибся он. Память модели о выводе
компилятора ненадёжна: регистры, смещения и размер кадра стека меняются
от версии и флагов. Поэтому все числа в главах берутся только из настоящей
сборки, как это сделано в главах 2–5.

## Одна команда

```bash
bash .claude/skills/verify-example/scripts/build_win.sh пример.c --run "ввод" --asm main
```

Что делает скрипт:

1. если кросс-компилятора нет — ставит его (`apt-get`, команда из
   `CLAUDE.md`, раздел 4);
2. ищет привычные ловушки курса (список ниже);
3. собирает два `.exe`: `-O0` (как в задачах) и `-O2 -s` («тяжёлый
   режим», как `make hard`);
4. печатает настоящие факты: `ImageBase`, `AddressOfEntryPoint`,
   `Subsystem`, секции с адресами и размерами, импорт по DLL;
5. кладёт ассемблер `-O0` в синтаксисе Intel в `build-check/имя.O0.s`,
   а с `--asm` показывает машинный код функции с адресами;
6. собирает тот же исходник под Linux и прогоняет его с `--run`.

Можно передать несколько файлов (`main.c pte.c` или `main.c my.s`).
Папка `build-check/` в `.gitignore`, её не коммитят.

## Без кросс-компилятора: MinGW gcc через godbolt

На макбуке ученика кросс-компилятора нет (ставить — только с его
согласия, `CLAUDE.md`, раздел 5). Тогда компиляцию и листинги даёт
настоящий MinGW gcc — gcc под Windows, как в w64devkit, — через API
сайта Compiler Explorer:

```bash
python3 .claude/skills/verify-example/scripts/godbolt_mingw.py пример.c
python3 .claude/skills/verify-example/scripts/godbolt_mingw.py пример.c --flags=-O1 --asm check
```

Заголовки Windows (`windows.h`, `winsock2.h`) там есть, предупреждения
`-Wall -Wextra` — настоящие. Собрать `.exe` целиком и запустить его так
нельзя: это `build_win.sh` в облаке или ученик на ПК. 11.10.2026 этим
путём проверены листинги главы 5 (совпали с `-O1` до инструкции) и задача
06 (П9), 12.10.2026 — главы 9–12. Учти: gcc в листинге пишет числа
десятичными (`7777`, `90`), IDA и x64dbg показывают их в hex (`1E61h`, `5Ah`).

**Библиотека как у ученика.** godbolt собран с UCRT, а w64devkit — с
`msvcrt-os`. По умолчанию скрипт добавляет `-D__MSVCRT_VERSION__=0x700`,
и заголовки MinGW ведут себя как в w64devkit: `printf` в листинге
зовётся `__mingw_printf`. Ключ `--crt ucrt` — как на самом сайте godbolt,
которым ученик пользуется с главы 5 (там `call printf`). Код своих
функций в обоих режимах одинаковый; разница — в вызовах `printf` и родни.
`tools/check_examples.py --godbolt` собирает в режиме msvcrt.

**gcc 13 → gcc 16.** Листинги старых глав снимались gcc 13, у ученика
gcc 16.2. Что поменялось (проверено 12.10.2026 на 13.1, 14.3, 15.2, 16.2):
- растяжение 4 → 8 байт gcc 16 пишет `movsxd`, gcc 13–15 писали `movsx`;
- `char`/`short`-аргумент gcc 16 кладёт на стек прямо из `CL`/`CX`
  (gcc 13–15: `mov eax, ecx`, потом `AL`/`AX`);
- канарейка (`-fstack-protector-strong`) у gcc 16 — `sub rsp, 72` без
  `push rbx`, эталон перечитывается через `.refptr.__stack_chk_guard`.
`nop` после `call` прямо перед эпилогом ставят все эти версии: так
требует раскрутка стека Windows (комментарий «SEH unwinding can require
an extra nop» в `gcc/config/i386/i386.cc`). Сдвиг влево gcc пишет `sal`,
дизассемблеры — `shl`.

**Настоящий Visual Studio.** На godbolt есть и `cl`:
`--compiler vc_v19_latest_x64 --flags=/O2 --asm функция`
(`vc_v19_51_VS18_6_x64` — Visual Studio 2026). Скрипт сам не добавляет
ключи gcc и показывает функцию от `PROC` до `ENDP` вместе со строками
вида `buf$ = 32` — это смещения переменных от `RSP`; в главу их
переводи в числа (`[rsp+32]`), как покажет x64dbg. Так получена
канарейка `/GS` в 11.9. Для C++ (П7) это точнее clang в режиме MSVC.

## Что можно брать в главу

- **Листинг, факты PE, предупреждения компилятора** — настоящие, бери.
  Одна оговорка: в контейнере gcc 13 из пакетов Ubuntu 24.04, а у ученика
  w64devkit 2.10.0 с gcc 16.2. Листинг для главы снимай gcc 16.2 через
  godbolt (раздел выше) и подписывай в главе компилятор и ключи
  («MinGW gcc 16.2, `-O2`»), чтобы ученик мог повторить. Факты PE
  и адреса готового `.exe` godbolt не даёт — их бери из `build_win.sh`
  и пиши «у тебя адреса будут другими». Выводы строй на том, что
  от версии не зависит: логика, соглашение о вызовах, устройство файла.
- **Что программа покажет при запуске на Windows** — в контейнере
  не проверить (wine нет). Помечай: «примерно так, у тебя адреса будут
  другими». Выводы делай только из того, что от адресов не зависит.
  Попроси ученика прислать свой вывод (скилл `lesson`, часть В).
- **Число, которое не удалось проверить**, так и помечай: «не проверено,
  сверим в главе N». Так сделано с `CR0 = 80050033` в главе 33.

## Прогон логики под Linux

- **Обычный C без `windows.h`** скрипт прогоняет сам.
- **Свой ассемблер (`.s`, как в П2):** тот же файл без строк `.seh_`,
  а в C-обвязке прототипы с `__attribute__((ms_abi))`. Тогда функция
  вызывается по правилам Windows (глава 12), как на машине ученика.
- **Потоки и WinAPI (как в П3):** маленькая прокладка `windows.h` на
  pthreads и `__atomic`, только в scratchpad, в репозиторий её не клади.
  Она проверяет логику, а не времена: числа скорости бери с пометкой
  «у тебя будет по-другому».
- **Драйвер главы 29:** его можно только собрать и разобрать, загрузить
  здесь нельзя. Команды сборки записаны в `CLAUDE.md`, раздел 7а,
  в записи о главе 29.

## Ловушки, которые ищет скрипт

| Что нашёл | Почему плохо | Как правильно |
|---|---|---|
| `%zu` | в w64devkit `printf` — это `__mingw_printf`, она `%zu` понимает; но с `-D__USE_MINGW_ANSI_STDIO=0` печать уходит в `msvcrt.dll`, а там `%zu` нет | `%llu` и `(unsigned long long)` — работает везде |
| кириллица в строках | консоль Windows покажет кракозябры | сообщения транслитом, как в `crackmes/` |
| `long` | на Windows 32 бита, на Linux 64, прогоны разойдутся | `uint32_t`, `uint64_t` (П1) |
| чтение структур процесса через `gs:` | в примерах курса держимся документированного | функции WinAPI |

И то, что проверяется глазами:

- `1 << 31` — по стандарту C это ошибка (неопределённое поведение).
  При расширении до 64 бит gcc даёт `FFFFFFFF80000000`. Правильно —
  `1ULL << 31`;
- листинг в главе совпадает с тем, что выдал скрипт, до байта: адреса,
  смещения, порядок инструкций.

## Декомпилятор Ghidra

Вывод декомпилятора в главу бери только из настоящего Ghidra
(`support/analyzeHeadless`), а не по памяти. Сначала проверь, открыт ли
доступ:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' -I https://github.com
```

**403** — Ghidra в этой сессии не поставить (так было 10.10.2026). Тогда
покажи настоящий дизассемблер из скрипта. Что увидит ученик в Ghidra,
опиши словами и пометь «вывод Ghidra не проверен».

**200** — скачай релиз с GitHub (JDK 21 в контейнере есть) и запусти:

```bash
ghidra/support/analyzeHeadless /tmp/gp proj -import пример.exe \
  -scriptPath папка_скрипта -postScript Decompile.java main -deleteProject
```

Скрипт `Decompile.java` для этого:

```java
import ghidra.app.script.GhidraScript;
import ghidra.app.decompiler.DecompInterface;
import ghidra.app.decompiler.DecompileResults;
import ghidra.program.model.listing.Function;
import java.util.Arrays;
import java.util.List;

public class Decompile extends GhidraScript {
    @Override
    public void run() throws Exception {
        List<String> want = Arrays.asList(getScriptArgs());   // пусто — все функции
        DecompInterface ifc = new DecompInterface();
        ifc.openProgram(currentProgram);
        for (Function f : currentProgram.getFunctionManager().getFunctions(true)) {
            if (!want.isEmpty() && !want.contains(f.getName())) continue;
            DecompileResults r = ifc.decompileFunction(f, 60, monitor);
            if (r.decompileCompleted())
                println("// " + f.getName() + " @ " + f.getEntryPoint() + "\n"
                        + r.getDecompiledFunction().getC());
        }
    }
}
```

## Все примеры курса разом

`python3 tools/check_examples.py` собирает каждую полную программу
на C из глав (блоки с `main`). Без кросс-компилятора —
`python3 tools/check_examples.py --godbolt`: компиляция без компоновки
настоящим MinGW gcc 16.2 (как в w64devkit 2.10.0) через godbolt.org. 10.10.2026: 28 собираются, 8 — законные
исключения (вывод декомпилятора, фрагмент упражнения, части проектов
из нескольких файлов) с причинами в списке `SKIP`. Прогоняй после
любой правки кода в главах.

## Если пример в главе расходится с компилятором

Исправь главу точечной правкой и прогони `python3 tools/check_course.py`.
В сообщении коммита напиши, на чём споткнулся бы ученик: какое число
он увидел бы у себя и какое было в тексте.
