# Проверка примеров на C++, Rust и Python

Правило то же, что для C (скилл `verify-example`): цифры и листинги
в главу — только с настоящего компилятора. Память модели о том, как
компилятор раскладывает классы или срезы, ненадёжна, а ученик сверяет
главу со своей IDA.

## Одна команда

```bash
bash .claude/skills/verify-lang/scripts/build_lang.sh пример.cpp --fn имя [--opt 0|1|2] [--run "ввод"]
bash .claude/skills/verify-lang/scripts/build_lang.sh пример.rs  --fn имя
bash .claude/skills/verify-lang/scripts/build_lang.sh пример.py  --run "ввод"
```

Сборки ложатся в `build-check/` (она в `.gitignore`).

## C++: в стиле Visual Studio

Большинство программ Windows собрано Visual Studio (MSVC). У них свои
искажённые имена (`?count_legs@@YAHPEBUAnimal@@@Z`), свои таблицы
виртуальных функций (`??_7Dog@@6B@` = `Dog::vftable`) и деструкторы
(`scalar deleting dtor`). Именно это ученик увидит в IDA.

- Скрипт собирает объектный файл через `clang --target=x86_64-pc-windows-msvc`.
  Clang совместим с MSVC по ABI: имена, раскладка классов, vtable
  и соглашение о вызовах те же. Порядок и выбор инструкций может
  отличаться в мелочах — так и пиши: «у Visual Studio может отличаться
  в мелочах».
- **Заголовков Visual Studio в облаке нет.** Пример для разбора пиши
  без `#include`, нужное объявляй сам:
  `extern "C" int printf(const char *, ...);`. Если в примере есть
  `main`, скрипт ещё соберёт полный `.exe` через MinGW
  (`x86_64-w64-mingw32-g++`) и прогонит логику под Linux. У MinGW
  **другие** имена (`_ZN…`, как у GCC) и своя STL — в главу про MSVC
  их не бери.
- **STL Microsoft** (`std::string`, `std::vector`): раскладку бери
  из исходников `microsoft/STL` через
  `raw.githubusercontent.com/microsoft/STL/main/stl/inc/xstring`
  (и `vector`); проверено 10.10.2026. Пиши, на какой файл опираешься.
- RTTI выключено (`-fno-rtti`), чтобы не было ссылок на `type_info`.
  Для раздела про RTTI собирай без этого флага руками.

Пример настоящего вывода (10.10.2026, clang 18): виртуальный вызов
`a->legs()` — это `mov rax, [rcx]` (адрес vtable из объекта)
и `jmp [rax+8]` (второй слот: первый занят деструктором).

## Rust: под Windows MSVC

- Цель `x86_64-pc-windows-msvc` ставится официально через `rustup`
  (static.rust-lang.org открыт, проверено 10.10.2026). Скрипт ставит
  её сам.
- Учебные функции помечай `pub` и `#[inline(never)]`, иначе компилятор
  их выкинет или встроит, и в листинге будет пусто.
- Имена Rust в новом формате v0 (`_RNvCs…_1c5total`), `llvm-nm -C`
  расшифровывает их в `c::total`. Срез `&[T]` приходит двумя
  регистрами: адрес в RCX, длина в RDX.

## Python

Скрипт проверяет синтаксис и запускает. Для скриптов IDAPython
и Ghidra — правила скиллов `ru-hints` и `ida-mcp`: имена API только
из исходников IDA SDK 9.2 и Ghidra 12.1.4.

## На ПК ученика

clang и LLVM там скорее всего нет. C++ проверяется `g++` из w64devkit
(имена в стиле GCC — помни об этом), Rust — если ученик поставил
`rustup`. Зато программы можно запустить по-настоящему.

## Что можно брать в главу

Как в `verify-example`: листинг и имена — настоящие, бери; вывод
программы на Windows — «примерно так»; не проверенное — так и помечай.
