# Приложение П6. Python для реверсера

> **Приложения к курсу**
> Когда проходить: после [приложения П1](p1-si-pishem-sami.md)
> и [приложения П5](p5-ida-pro.md). Опирается на главы 3 (числа
> и байты), 5 (язык C), 8 (формат PE), 16–17 (разборы задач 1 и 2),
> 20 (своя виртуальная машина) и приложения П1 (биты и структуры)
> и П5 (IDA).

Брат, в П5 ты запустил первый скрипт в IDA и, наверное, заметил:
Python читается почти как C, только без точек с запятой и фигурных
скобок. Пора выучить его по-настоящему. Это рабочий язык реверсера:
на нём пишут скрипты для IDA и Ghidra, маленькие инструменты «на один
раз» и автоматизацию разбора. В вакансиях из главы 40 Python часто
стоит в требованиях рядом с IDA и языком C.

Учить с нуля не будем: C ты уже знаешь (глава 5, П1). Поэтому всё
приложение построено на сравнении «в C было так — в Python так».
И на твоих же задачах: числа из главы 3, заголовок PE из главы 8,
пароль под XOR из главы 17, байт-код из главы 20.

После приложения ты будешь уметь:

- ставить Python на Windows так, чтобы он работал и с IDA 9.2,
  и с Ghidra;
- считать в Python, как на калькуляторе реверсера: hex, маски, знак;
- переводить код с C на Python;
- работать с байтами: `bytes`, `int.from_bytes`, модуль `struct`;
- писать свои утилиты: паспорт файла PE, поиск строк, снятие XOR;
- видеть, что Python сам — стековая машина, как твоя из главы 20;
- писать скрипты для IDA и Ghidra, которые сами подписывают
  расшифрованные строки;
- раскладывать системный регистр на биты одной командой — это
  пригодится на дороге к гипервизору.

Приложение длинное, около 1750 строк, но почти половина — код и его
вывод. Проходи его **в три захода**
(между ними — хоть день перерыва):

1. **П6.1–П6.6** — установка, язык, байты;
2. **П6.7–П6.10** — свои инструменты: паспорт PE, строки, XOR;
3. **П6.11–П6.15** — Python внутри инструментов реверсера и на дороге

Весь код я запускал настоящим Python 3.13, а задачи собирал тем же
компилятором, что в главах 16–20 (gcc 13). Вывод скриптов на одинаковых
байтах у тебя будет таким же: Python одинаково считает на Linux и на
Windows. Но твои `.exe` собраны gcc 16.2 с MinGW 14 — код самих задач
тот же (я сверил), а адреса и код библиотеки C в файле другие, поэтому
числа, которые от них зависят, у тебя могут отличаться. Скрипты для IDA
и Ghidra я проверил на подставных функциях с теми же именами, что
в IDA 9.2 и Ghidra 12.1, — в настоящих программах они ещё не
запускались. Если у тебя что-то пойдёт иначе — пришли мне вывод.

## П6.1. Зачем реверсеру Python

Причин три, по важности.

**1. Скрипты внутри инструментов.** IDA и Ghidra выполняют Python
(П5.12). Всё, что ты делаешь руками — переименовать, найти вызовы,
расшифровать строку, — можно поручить скрипту. На задаче 01 это
не нужно. А в программе на десять тысяч функций скрипт за секунду
делает то, на что руками уйдёт день.

**2. Свои инструменты за десять минут.** В главе 20 ты написал
дизассемблер байт-кода на C — около 50 строк: открыть файл, `strtol`,
`fseek`, `fread`, закрыть. На Python тот же инструмент занимает
около 20 строк (упражнение П6.5). Реверсер постоянно пишет такие
программы «на один раз»: разобрать формат, перебрать ключи, сравнить
два дампа. Python для этого и придуман: меньше обвязки, больше дела.

**3. Язык профессии.** Многие инструменты реверса написаны на Python
или дают к себе доступ из Python: библиотека `pefile` для разбора PE,
сами IDAPython и PyGhidra. Отчёты, проверки, разбор тысяч файлов
подряд — всё это обычно Python.

**Чего Python не умеет.** Скажу честно: сам гипервизор на Python
не напишешь. Гипервизор работает ниже ядра, там нет ни интерпретатора,
ни библиотек — только твой машинный код. Его ты будешь писать на C
и ассемблере (П1, П2). Python — это твоя мастерская *вокруг*:
калькулятор, разбор логов и дампов, скрипты для дизассемблера.
В разделе П6.14 ты напишешь в этой мастерской первый инструмент для
дороги к гипервизору.

## П6.2. Поставить Python на Windows

### Сначала проверь, может, он уже есть

Для скриптов курса Python, возможно, уже стоит (README, раздел «Курс
у тебя на ПК»). Открой **PowerShell** — синее окно, найди его через
«Пуск» — и набери:

```
python --version
```

Если ответ вида `Python 3.13.5` — Python есть, смотри на номер версии
ниже. Если ошибка или открылся Microsoft Store — Python не установлен.

### Какая версия нужна

Тут есть подвох: IDA и Ghidra понимают не любой Python.

| Кто | Какие версии | Откуда знаю |
|---|---|---|
| IDA 9.2 | 3.11–3.13 | поддержку 3.13 Hex-Rays добавила в IDA 9.0 SP1 (заметки к выпуску). Нижнюю границу 3.11 называют руководства к плагинам, официального списка я не нашёл. О 3.14 и новее сведений нет: IDA 9.2 вышла раньше, чем Python 3.14 |
| Ghidra 12.1.4 | 3.9–3.14 | файл `GettingStarted.md` в исходниках Ghidra |
| скрипты этого приложения | 3.10 и новее | проверено на 3.13 |

Вывод простой: **ставь Python 3.13** — он подходит всем. Самая новая
ветка сейчас 3.15 (вышла 9 октября 2026 года), но для IDA 9.2
и Ghidra 12.1 она слишком новая. Номера версий в программах
меняются с обновлениями: если у тебя IDA новее, проверь у себя, какой
Python она понимает.

### Как поставить

Сейчас официальный способ — **Python Install Manager** `[пáйтон
инстóл мэ́неджер]`, «установщик Python». Это маленькая программа,
которая ставит нужные версии Python и переключается между ними
(сверено по документации Python, октябрь 2026). Старый установщик
`.exe` с python.org ещё выпускают, но с версии 3.16 его не будет.

1. Открой **Microsoft Store**, найди **Python Install Manager**
   и нажми **Установить** (Install; в некоторых версиях Store кнопка
   называется «Получить» — Get). Тот же установщик есть на
   python.org/downloads.
2. Открой новое окно PowerShell и поставь нужную версию:

   ```
   py install 3.13
   ```

   При первой установке программа может спросить, добавить ли папку
   `%LocalAppData%\Python\bin` в **PATH** — список папок, где Windows
   ищет программы. Соглашайся: тогда команды вроде `python3.13`
   заработают в любом окне.
3. Проверь:

   ```
   py list
   python --version
   ```

   `py list` (list — «список») покажет все установленные версии.
   Если версий несколько, нужную выбирают так:
   `py -V:3.13 имя_скрипта.py`.

Если `py install` отвечает непонятной ошибкой, значит, команду `py`
занял старый запускатель от прежней установки Python. Это не страшно,
но разбирать удобнее вместе: пришли мне текст ошибки.

### Подружить Python и IDA

IDA сама не знает, какой Python у тебя стоит. Для этого рядом с ней
лежит программа **idapyswitch** («переключатель Python для IDA»). Открой
консоль в папке, куда установлена IDA, и запусти:

```
idapyswitch
```

Она найдёт все Python на компьютере и предложит выбрать один —
выбери 3.13. Если Windows скажет, что не хватает прав, запусти консоль
от имени администратора (правый щелчок → «Запуск от имени
администратора»). После этого перезапусти IDA и посмотри в окно
**Output**: при запуске там появляется строка о Python. Пришли мне её
— я сверю с тем, что написано здесь.

Ghidra ищет Python сама, когда её запускают особым способом — об этом
в разделе П6.13.

### Первая программа

Заведи папку `C:\reverse\work\py` для скриптов этого приложения.
В PowerShell:

```
mkdir C:\reverse\work\py
cd C:\reverse\work\py
notepad hello.py
```

Блокнот спросит, создать ли новый файл, — соглашайся. Впиши одну
строку и сохрани (Ctrl+S):

```python
print("Privet, brat!")
```

Запусти:

```
python hello.py
```

В окне появится `Privet, brat!`. Сравни с C из главы 5: там нужны были
`#include <stdio.h>`, функция `main`, точка с запятой, компилятор
и отдельный запуск `.exe`. Здесь — одна строка и сразу результат.
Python не собирает `.exe`: **интерпретатор** (как в главе 20 —
программа, которая выполняет команды одну за другой) читает твой файл
и выполняет его прямо сейчас.

## П6.3. Калькулятор реверсера

Набери в PowerShell просто `python`, без имени файла. Появится
приглашение `>>>` (примерно так, номер версии у тебя свой):

```
Python 3.13.5 (tags/v3.13.5:...) [MSC v.1943 64 bit (AMD64)] on win32
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

Это **REPL** `[рэпл]` — Read–Eval–Print Loop, «прочитай — вычисли —
напечатай, и снова». Пишешь выражение, жмёшь Enter — Python сразу
показывает ответ. Выйти — `exit()`. Этим окном реверсеры пользуются
как калькулятором: оно всегда под рукой и понимает hex.

### Перевод систем счисления

```
>>> 0x34 + 0x12 * 256
4660
>>> hex(4660)
'0x1234'
>>> int("1234", 16)
4660
>>> bin(5)
'0b101'
>>> 0b101
5
```

Всё из главы 3, только считает машина:

- `0x34` — число в hex, как в C. `0b101` — в двоичной;
- `hex(число)` — показать в hex. Ответ в кавычках: это **строка**
  (string `[стринг]`) — текст, а не число;
- `int("1234", 16)` — прочитать текст как число по основанию 16,
  как `strtol` из главы 20;
- первая строка — байты `34 12` в little-endian, собранные руками:
  младший плюс старший, умноженный на 256 (глава 3).

### Первое большое отличие от C: у чисел нет размера

```
>>> 2 ** 64
18446744073709551616
>>> 0xFFFFFFFF + 1
4294967296
```

`**` — возведение в степень. В C переменная `uint32_t` хранит ровно
32 бита, и `0xFFFFFFFF + 1` даёт `0`: лишний бит отваливается
(глава 3). В Python целое число растёт сколько нужно и не
переполняется никогда.

Для обычной программы это удобно. А реверсеру нужно считать **как
процессор**, с его 8, 32 или 64 битами. Поэтому лишнее отрезают
маской — операцией И с нужным числом единиц (П1.2):

```
>>> (0xFFFFFFFF + 1) & 0xFFFFFFFF
0
>>> (0xF0 + 0x20) & 0xFF
16
```

Запомни три маски: `0xFF` — байт, `0xFFFFFFFF` — `dword`,
`0xFFFFFFFFFFFFFFFF` — `qword`. Забытая маска — ошибка номер один,
когда переносишь вычисления процессора в Python.

### Отрицательные числа

```
>>> hex(-1)
'-0x1'
>>> hex(-1234 & 0xFFFFFFFF)
'0xfffffb2e'
>>> ~0
-1
```

В главе 3 ты видел: в памяти `-1` — это `FF FF FF FF`, дополнительный
код. Python же показывает минус, а не биты: у его чисел нет размера,
и непонятно, сколько единиц рисовать. Наложишь маску — увидишь
привычные байты процессора. `~` (тильда, «не» по битам, как в C) от
нуля даёт `-1` по той же причине.

Обратная задача: число из регистра надо прочитать как знаковое.
Своей функции у Python для этого нет, пишут её сами (как писать
функции — в П6.4):

```python
def signed32(x):
    return x - (1 << 32) if x & 0x80000000 else x
```

Если старший бит (бит 31) равен 1, число отрицательное: вычитаем
2³² — тот же приём «вычесть 256», что для байта в главе 3.
`signed32(0xFFFFFB2E)` даёт `-1234`.

### Деление: вторая ловушка

```
>>> 10 / 3
3.3333333333333335
>>> 10 // 3
3
>>> -10 // 3
-4
```

В C `10 / 3` у целых даёт `3`. В Python `/` всегда даёт дробь,
а целое деление пишется `//`. И ещё тонкость: `//` округляет вниз,
к минус бесконечности, поэтому `-10 // 3` — это `-4`, а в C было бы
`-3`. С отрицательными числами при переносе кода из C будь
внимателен. `%` — остаток, как в C: `10 % 3` даёт `1`.

### Как печатать числа

Самая удобная запись — **f-строка** `[эф-стринг]`: буква `f` перед
кавычками, а внутри фигурных скобок — что вставить и как:

```
>>> f"{4660:X}"
'1234'
>>> f"{4660:08X}"
'00001234'
>>> f"{5:08b}"
'00000101'
```

После двоеточия — формат, почти как у `printf` в C: `X` — hex
большими буквами, `08` — ширина 8 с нулями впереди, `b` — двоичная.
В П5 ты видел и старую запись `"%X" % 4660` — она тоже работает,
это прямо `printf`.

## П6.4. С языка C на Python

Главное отличие видно сразу: **отступы** (indentation `[индентéйшен]`)
вместо фигурных скобок. Что сдвинуто вправо под строкой с двоеточием,
то и есть тело `if`, цикла или функции. Обычно сдвигают на 4 пробела.
Сдвинул не так — Python откажется запускать файл и напишет
`IndentationError` («ошибка отступа»).

| В C | В Python | Заметка |
|---|---|---|
| `int x = 5;` | `x = 5` | тип не пишут: его знает само значение |
| `{ … }` | отступ | двоеточие в конце строки перед ним |
| `;` в конце | не нужна | одна строка — одна команда |
| `if (a == b) … else if … else` | `if a == b:` … `elif` … `else:` | скобки вокруг условия не нужны |
| `&&`, `\|\|`, `!` | `and`, `or`, `not` | словами |
| `for (i = 0; i < n; i++)` | `for i in range(n):` | `range(n)` — числа от 0 до n−1 |
| `while (x) { … }` | `while x:` | |
| `i++` | `i += 1` | `++` в Python нет |
| `10 / 3` (целые) | `10 // 3` | `/` даёт дробь |
| `printf("%X\n", x)` | `print(f"{x:X}")` | `print` сам переводит строку |
| `NULL`, `true`, `false` | `None`, `True`, `False` | с большой буквы |
| `/* … */`, `// …` | `# …` | комментарий до конца строки |
| `int a[3] = {1, 2, 3};` | `a = [1, 2, 3]` | **список** (list `[лист]`), растёт сам |
| `#include <string.h>` | `import struct` | подключить **модуль** — файл с функциями |
| `int f(int x) { … }` | `def f(x):` | `def` — define, «определить» |

Модуль (module `[мóдуль]`) — то же слово, что в x64dbg из главы 13,
только здесь это не DLL, а файл `.py` с готовыми функциями. Одни
модули приходят вместе с Python (`struct`, `sys`, `dis`), другие ставят
отдельно, третьи пишешь ты сам — в П6.9 ты подключишь свой.

### Одна функция на двух языках

Возьмём функцию расшифровки из задачи 02 (глава 17). На C она такая:

```c
static void decrypt(char *out, size_t n)
{
    for (size_t i = 0; i < n; i++)
        out[i] = (char)(ENC[i] ^ KEY);
    out[n] = '\0';
}
```

То же на Python — файл `c2py.py`:

```python
ENC = bytes([0x22, 0x35, 0x28, 0x05, 0x32, 0x33, 0x3E, 0x3F, 0x29,
             0x05, 0x34, 0x35, 0x2E, 0x32, 0x33, 0x34, 0x3D])
KEY = 0x5A


def decrypt(enc):
    out = bytearray()
    for b in enc:
        out.append(b ^ KEY)
    return bytes(out)


print(decrypt(ENC))
print(decrypt(ENC).decode())
```

Вывод (`python c2py.py`):

```
b'xor_hides_nothing'
xor_hides_nothing
```

Пароль из главы 17 — тот же, только расшифровала его твоя программа.
Что поменялось по сравнению с C:

- **Нет буфера `out` снаружи.** В C вызывающий готовил массив
  и передавал указатель. В Python функция создаёт результат сама
  и возвращает его через `return`. Об ошибке «массив мал» думать
  не нужно.
- **Нет нуля в конце.** Строке C нужен `'\0'`, чтобы знать, где она
  кончается (глава 5). Объект Python сам знает свою длину.
- **`for b in enc:`** — цикл без счётчика: «для каждого байта `b`
  в `enc`». Индекс `i` не нужен вовсе.
- **`bytearray()`** — пустой изменяемый набор байтов, `append` —
  «добавить в конец». В конце превращаем его в обычные `bytes`.
- **Первая строка вывода с буквой `b` и кавычками** — так Python
  печатает байты. `.decode()` превращает их в текст, и вторая строка
  выходит уже без `b'…'`. Разница между байтами и текстом — тема
  следующего раздела.

Опытные пишут то же самое в одну строку:

```python
print(bytes(b ^ KEY for b in ENC))
```

Читается справа налево: «для каждого `b` из `ENC` взять `b ^ KEY`,
а из всего вместе сделать `bytes`». Сразу так писать не обязательно:
длинная запись с циклом делает то же самое, а прочитать её легче.

## П6.5. Текст и байты

В C было просто: строка — это массив `char`, а `char` — это число
(глава 5). Python делит это на два разных вида данных, и реверсеру
важно их не путать:

- **`str`** (string, «строка») — **текст**: буквы любого языка.
  Пишется в кавычках: `"Hello"`;
- **`bytes`** (байты) — **числа от 0 до 255**, то, что лежит в файле
  и в памяти. Пишется с буквой `b`: `b"Hello"`.

```
>>> "Hello"[0]
'H'
>>> b"Hello"[0]
72
```

Квадратные скобки, как в C, берут элемент по номеру с нуля. Но
у текста элемент — буква `'H'`, а у байтов — **число** 72: код буквы
`H` из таблицы ASCII (глава 3). Перевести одно в другое:

```
>>> ord("H")
72
>>> chr(72)
'H'
```

`ord` — от слова order, «порядковый номер» символа, `chr` — от
character, «символ».

### Срезы

```
>>> b"Hello"[1:3]
b'el'
>>> b"Hello"[:2]
b'He'
>>> b"Hello"[-1]
111
```

`[1:3]` — **срез** (slice `[слайс]`): элементы с номера 1 **до** 3,
не включая 3. Пропущенное начало значит «с нуля», отрицательный
номер считает с конца. Главная запись этого приложения — кусок данных
по смещению и размеру:

```python
data[offset:offset + size]
```

Это то же самое, что `fseek` + `fread` из главы 20, только одной
строкой.

### Как Python показывает байты

```
>>> bytes.fromhex("34 12 00 00")
b'4\x12\x00\x00'
>>> bytes.fromhex("34 12 00 00").hex(" ")
'34 12 00 00'
```

`bytes.fromhex` делает байты из hex-текста — удобно переносить их
из HxD или IDA. А вот показал их Python странно: `4` вместо `34`?
Это не ошибка. Байт `0x34` — код цифры `4` в ASCII, и Python рисует
печатные байты буквами, а остальные — в виде `\x12`. Внутри лежит
то же самое число `0x34`. Хочешь видеть все байты одинаково, в hex, —
вызови `.hex(" ")`, в скобках разделитель.

### Текст в байты и обратно

```
>>> "Hi".encode()
b'Hi'
>>> "Hi".encode("utf-16-le")
b'H\x00i\x00'
>>> b"Hi".decode()
'Hi'
```

`encode` («закодировать») превращает текст в байты, `decode` — байты
в текст. По умолчанию — в кодировке UTF-8, где латинская буква занимает
один байт. Вторая строка — **UTF-16** в little-endian: по два байта
на символ, второй — ноль. Узнаёшь? Так в памяти выглядят строки для
функций с суффиксом `W` (глава 12) и `UNICODE_STRING` в драйвере
(глава 29). Искать такую строку в файле надо именно в этом виде —
обычный поиск ASCII её не найдёт.

### Поиск в байтах

```
>>> b"xxMZyy".find(b"MZ")
2
>>> b"xxMZyy".find(b"PE")
-1
>>> b"PE\0\0" in b"..PE\0\0.."
True
```

`find` («найти») возвращает смещение первой находки или `-1`, если
не нашёл. `in` отвечает просто да или нет. `\0` — нулевой байт, как
в C.

### Изменяемые байты

`bytes` менять нельзя — только создать новые. Для правки есть
`bytearray`:

```
>>> b = bytearray(b"abc")
>>> b[0] = 0x41
>>> b
bytearray(b'Abc')
```

Попробуешь то же с `bytes` — Python откажет:
`TypeError: 'bytes' object does not support item assignment` («объект
bytes не поддерживает присваивание элементу»). В `decrypt` из П6.4
мы потому и собирали результат в `bytearray`.

## П6.6. Числа из байтов: `int.from_bytes` и `struct`

Вот главная работа реверсера в Python: прочитать число, которое
лежит в файле байтами. Руками ты делал это в главах 3 и 8:
перевернуть порядок, склеить, перевести. Python делает это одной
командой.

### `int.from_bytes`

```
>>> int.from_bytes(b"\x34\x12\x00\x00", "little")
4660
>>> hex(int.from_bytes(b"\x34\x12\x00\x00", "big"))
'0x34120000'
>>> int.from_bytes(b"\x2e\xfb\xff\xff", "little", signed=True)
-1234
>>> (4660).to_bytes(4, "little")
b'4\x12\x00\x00'
```

- `"little"` — little-endian, младший байт первым, как у x86
  (глава 3). `"big"` — наоборот. Перепутаешь — получишь
  `0x34120000` вместо `0x1234`;
- `signed=True` — читать как знаковое. Без него те же байты
  `2E FB FF FF` дали бы `4294966062`;
- `to_bytes(4, "little")` — обратно: число в 4 байта.

### Модуль `struct`

Когда полей много, удобнее **модуль `struct`** `[стракт]` — от
слова structure, «структура». Ему дают строку формата и байты,
а он раскладывает их по полям, как структура в C (П1.4):

```
>>> import struct
>>> struct.unpack("<I", b"\x34\x12\x00\x00")
(4660,)
>>> struct.unpack("<I", b"\x34\x12\x00\x00")[0]
4660
>>> struct.unpack("<4sHH", bytes.fromhex("50 45 00 00 64 86 13 00"))
(b'PE\x00\x00', 34404, 19)
```

Последняя строка — начало PE-заголовка из главы 8: подпись, машина,
число секций. `34404` — это `0x8664`, x86-64, и 19 секций — всё как
там, только без ручного переворачивания.

`unpack` («распаковать») всегда возвращает **кортеж** (tuple
`[тьюпл]`) — несколько значений в круглых скобках. Даже если значение
одно, это кортеж из одного элемента, поэтому `[0]` — «взять первое».
Несколько значений можно сразу разложить по переменным:

```python
sig, machine, nsec = struct.unpack("<4sHH", data[0x80:0x88])
```

Буквы формата:

| Буква | Размер | Что читает | Как в C |
|---|---|---|---|
| `B` / `b` | 1 | байт без знака / со знаком | `uint8_t` / `int8_t` |
| `H` / `h` | 2 | `WORD` | `uint16_t` / `int16_t` |
| `I` / `i` | 4 | `DWORD` | `uint32_t` / `int32_t` |
| `Q` / `q` | 8 | `QWORD` | `uint64_t` / `int64_t` |
| `4s`, `8s` | 4, 8 | столько байтов как есть | `char[4]`, `char[8]` |

Большая буква — без знака, маленькая — со знаком. Первый символ
строки — порядок байтов: `<` — little-endian, `>` или `!` —
big-endian.

### Почему `<` обязателен

```
>>> struct.calcsize("<HI")
6
>>> struct.calcsize("HI")
8
```

`calcsize` — сколько байтов займёт формат. С `<` поля идут вплотную:
2 + 4 = 6. Без `<` Python раскладывает их так, как разложил бы
компилятор C, — с выравниванием, как в П1.4: после `WORD` два пустых
байта, чтобы `DWORD` стоял на кратном 4 адресе. В заголовках файлов
поля лежат так, как их записали, и чужое выравнивание всё собьёт.
Правило: **для форматов файлов всегда пиши `<`**.

И последнее: `unpack` требует ровно столько байтов, сколько в формате.
Дашь меньше — получишь ошибку
`struct.error: unpack requires a buffer of 4 bytes` («нужен буфер
в 4 байта»). Когда данных больше и нужно поле в середине, бери
**`struct.unpack_from(формат, данные, смещение)`**: он читает
с указанного смещения и не требует отрезать кусок. В следующем
разделе он станет главным инструментом.

## П6.7. Файлы и аргументы командной строки

Второй заход начинается здесь. Теперь у тебя есть всё, чтобы писать
свои инструменты. Нужны ещё две вещи: читать файл и получать
аргументы из командной строки.

### Прочитать файл целиком

```python
with open(path, "rb") as f:
    data = f.read()
```

- `open(path, "rb")` — открыть файл, как `fopen` в главе 20. `"rb"`
  значит то же самое: читать как байты;
- `with … as f:` — «пока работаешь с файлом `f`». Когда отступ
  кончится, Python сам закроет файл, даже если внутри случилась
  ошибка. Забыть `fclose` здесь невозможно;
- `f.read()` — прочитать всё. В `data` окажется объект `bytes`
  со всем файлом.

Файл задачи весит 250 КБ, а памяти у тебя 32 ГБ. Поэтому реверсеры
обычно читают файл целиком и дальше берут из `data` срезы: это проще,
чем прыгать по файлу через `seek`.

### Аргументы: `sys.argv`

В главе 20 программа получала `argc` и `argv`. В Python всё то же
лежит в модуле `sys` (system, «система»):

- `sys.argv` — список слов командной строки, все строками.
  `sys.argv[0]` — имя скрипта, дальше — аргументы;
- `len(sys.argv)` — сколько слов, вместо `argc`;
- `sys.exit("текст")` — напечатать текст и выйти с кодом ошибки 1.

### Свой маленький HxD

(глава 6). Файл `hexdump.py`:

- `range(0, len(chunk), 16)` — числа от 0 с шагом 16: начало каждой
  строки дампа;
- `"".join(…)` — склеить буквы в одну строку. Печатный байт
  становится буквой, остальные — точкой, как в правой колонке HxD;
- `:<47` — ширина 47 с выравниванием влево: столько занимают
  16 байтов с пробелами.

## П6.8. Проект: паспорт файла PE

Теперь соберём то, что в главе 8 делал PE-bear: заголовки, точку
входа, таблицу секций. Смещения полей — из главы 8 и документации
Microsoft «PE Format» (сверено по её исходнику, октябрь 2026).

Файл `pe_info.py`:

```python
# pe_info.py — паспорт файла PE, как вкладки PE-bear (глава 8)
import struct
import sys


def u16(data, off):
    return struct.unpack_from("<H", data, off)[0]


def u32(data, off):
    return struct.unpack_from("<I", data, off)[0]


def u64(data, off):
    return struct.unpack_from("<Q", data, off)[0]


def load(path):
    """Прочитать файл, разобрать заголовки, вернуть словарь."""
    with open(path, "rb") as f:
        data = f.read()
    if data[:2] != b"MZ":
        sys.exit("ne PE: v nachale net MZ")
    pe = u32(data, 0x3C)                  # e_lfanew (раздел 8.3)
    if data[pe:pe + 4] != b"PE\0\0":
        sys.exit("ne PE: net podpisi PE")
    fh = pe + 4                           # файловый заголовок, 20 байт
    opt = fh + 20                         # за ним — опциональный
    info = {
        "data": data,
        "machine": u16(data, fh),
        "nsections": u16(data, fh + 2),
        "magic": u16(data, opt),
        "entry": u32(data, opt + 16),
    }
    if info["magic"] == 0x20B:            # PE32+, 64 бита
        info["base"] = u64(data, opt + 24)
    else:                                 # PE32, 32 бита
        info["base"] = u32(data, opt + 28)
    table = opt + u16(data, fh + 16)      # таблица секций
    info["sections"] = []
    for i in range(info["nsections"]):
        e = table + 40 * i                # запись секции — 40 байт
        name = data[e:e + 8].rstrip(b"\0").decode("ascii", "replace")
        vsize, va, rsize, raw = struct.unpack_from("<IIII", data, e + 8)
        flags = u32(data, e + 36)
        info["sections"].append((name, vsize, va, rsize, raw, flags))
    return info


def rva_to_off(info, rva):
    """RVA -> смещение в файле (раздел 8.7). None, если в файле этого нет."""
    for name, vsize, va, rsize, raw, flags in info["sections"]:
        if va <= rva < va + max(vsize, rsize):
            if rva - va >= rsize:
                return None               # в памяти есть, в файле нет: .bss
            return raw + (rva - va)
    return None


def off_to_rva(info, off):
    """Смещение в файле -> (имя секции, RVA). None вне секций (заголовки)."""
    for name, vsize, va, rsize, raw, flags in info["sections"]:
        if raw <= off < raw + rsize:
            return name, va + (off - raw)
    return None


def rights(flags):
    return (("R" if flags & 0x40000000 else "-") +
            ("W" if flags & 0x80000000 else "-") +
            ("X" if flags & 0x20000000 else "-"))


def main():
    if len(sys.argv) < 2:
        sys.exit("zapusk: python pe_info.py fail.exe")
    info = load(sys.argv[1])
    base = info["base"]
    print(f"mashina  {info['machine']:X}")
    print(f"magic    {info['magic']:X}")
    print(f"baza     {base:X}")
    print(f"vhod     RVA {info['entry']:X} = adres {base + info['entry']:X}")
    print(f"sekciy   {info['nsections']}")
    print()
    print("imya      v pamyati  RVA       v faile   smeshch.  prava")
    for name, vsize, va, rsize, raw, flags in info["sections"]:
        print(f"{name:9} {vsize:<10X} {va:<9X} {rsize:<9X} {raw:<9X} {rights(flags)}")


if __name__ == "__main__":
    main()
```

### Что нового в коде

- **Три маленькие функции** `u16`, `u32`, `u64` — чтобы не писать
  каждый раз `struct.unpack_from(…)[0]`. Имена — по размеру в битах:
  `WORD`, `DWORD`, `QWORD`.
- **Строка в тройных кавычках** сразу под `def` — описание функции
  (docstring `[дóкстринг]`, «строка документации»). Python её
  не выполняет, она для людей.
- **Словарь** (dictionary `[дúкшенери]`, коротко dict) — `info = {…}`.
  Это набор пар «ключ → значение»: `info["machine"]` достаёт машину,
  `info["base"] = …` добавляет новое поле. Похоже на структуру в C,
  только поля можно добавлять на ходу.
- **Список кортежей** `info["sections"]`: каждая секция — кортеж
  из шести чисел. Цикл `for name, vsize, va, rsize, raw, flags in …`
  сразу раскладывает кортеж по переменным.
- **`.rstrip(b"\0")`** — отрезать нули справа: имя секции дополнено
  нулями до 8 байтов (глава 8).
- **`None`** — «ничего», как `NULL` в C. `rva_to_off` возвращает его,
  если такого адреса в файле нет: например, у `.bss`, которая есть
  в памяти, но не в файле. Кто вызывает функцию, обязан это проверить.
- **`if __name__ == "__main__":`** — самая загадочная строка. Когда
  ты запускаешь `python pe_info.py`, Python кладёт в особую переменную
  `__name__` текст `"__main__"`, и `main()` срабатывает. А когда
  другой скрипт пишет `import pe_info`, в `__name__` будет
  `"pe_info"`, и `main()` не вызовется — подключатся только функции.
  Так один файл служит и программой, и модулем. В П6.9 это пригодится.

Колонки: `v pamyati` — сколько секция занимает в памяти (VirtualSize),

`start`, что IDA показала в П5. Права обычные: ни одна секция
не открыта на запись и выполнение сразу, а это красный флаг
из раздела 8.6.

А что за `/4`, `/19` и дальше? У этих секций имя длиннее восьми букв
и в 8 байтов не влезло. Тогда в поле имени пишут косую черту
и номер — смещение настоящего имени в отдельной таблице имён в конце
файла. Это отладочная информация gcc (формат DWARF, П1.9).
По документации Microsoft длинных имён в `.exe` быть не должно,
а gcc их всё равно пишет: Windows на имена секций не смотрит.
Как достать настоящие имена — упражнение П6.2.

## П6.9. Проект: свой поиск строк

В главах 7 и 16 первое, что ты делал с незнакомой программой, — искал
строки. Напишем свой поиск: найти в файле все цепочки печатных байтов
длиной от пяти. А заодно — подключим `pe_info` как модуль, чтобы
по смещению в файле сразу видеть адрес, как в IDA.

Файл `strings.py` положи в ту же папку, что `pe_info.py`:

```python
# strings.py — строки в файле, как окно Strings в IDA и Ghidra
import sys
import pe_info

MIN = 5                                   # строки короче — обычно шум


def ascii_strings(data, min_len=MIN):
    """Найти цепочки печатных байтов. Вернуть список (смещение, текст)."""
    found = []
    start = None                          # где началась цепочка
    for i, b in enumerate(data):
        if 0x20 <= b < 0x7F:              # печатный символ ASCII (глава 3)
            if start is None:
                start = i
        else:
            if start is not None and i - start >= min_len:
                found.append((start, data[start:i].decode("ascii")))
            start = None
    return found


def main():
    if len(sys.argv) < 2:
        sys.exit("zapusk: python strings.py fail.exe [chto_iskat]")
    info = pe_info.load(sys.argv[1])
    word = sys.argv[2] if len(sys.argv) > 2 else ""
    for off, text in ascii_strings(info["data"]):
        if word not in text:
            continue
        where = pe_info.off_to_rva(info, off)
        if where is None:
            print(f"{off:8X}  {'':8} {'':12}  {text}")
        else:
            name, rva = where
            print(f"{off:8X}  {name:8} {info['base'] + rva:12X}  {text}")


if __name__ == "__main__":
    main()
```

Новое:

- **`import pe_info`** — твой собственный модуль. Python ищет файл
  `pe_info.py` рядом со скриптом и подключает его функции:
  `pe_info.load`, `pe_info.off_to_rva`. Благодаря строке
  `if __name__ == "__main__"` из П6.8 его `main()` не запустится;
- **`enumerate(data)`** — перебирать сразу номер и значение: `i` —
  смещение, `b` — байт. Как `for (i = 0; …)` и `data[i]` вместе;
- **`start = None`** — «цепочки пока нет». Встретили печатный байт —
  запомнили начало. Встретили непечатный — если цепочка была длиной
  от `MIN`, сохраняем её;
- **`word not in text`** — фильтр: если второй аргумент задан, печатаем
  только строки, где он встречается. Большие и маленькие буквы
  различаются: по `Verno` найдётся `[+] Verno…`, а `[-] Neverno.` —
  нет.

## П6.10. Проект: снять XOR

В главе 17 ты расшифровал пароль задачи 02, прочитав листинг: таблица
по адресу `140009000` (из `lea rdx, [rip+0x7b0b]`), ключ `0x5A`

Файл `xor_dump.py`:

```python
# xor_dump.py — прочитать байты по адресу из дизассемблера и снять XOR

    main()
```

## П6.11. Python сам — стековая машина

Третий заход. Начнём с открытия, которое связывает это приложение
с главой 20.

Ты не задумывался, как Python выполняет твой файл? Он не переводит
его в машинный код процессора. Сначала он переводит текст в свой
**байт-код** (глава 20: программа для интерпретатора, записанная
байтами), а потом его интерпретатор выполняет этот байт-код —
команду за командой, со своим стеком. Ровно как твоя машина из
задачи 05. Посмотреть байт-код можно модулем `dis` (от слова
disassembler — да, это дизассемблер).

Файл `dis_demo.py`:

```python
# dis_demo.py — Python сам стековая машина, как машина задачи 05 (глава 20)
import dis


def check(x):
    return (x + 3) ^ 0x5A


dis.dis(check)
print(check.__code__.co_code.hex(" "))
print(check(0x1F))
```

Вывод на Python 3.13:

```
  5           RESUME                   0

  6           LOAD_FAST                0 (x)
              LOAD_CONST               1 (3)
              BINARY_OP                0 (+)
              LOAD_CONST               2 (90)
              BINARY_OP               12 (^)
              RETURN_VALUE
95 00 55 00 53 01 2d 00 00 00 53 02 2d 0c 00 00 24 00
120
```

Числа слева, `5` и `6`, — номера строк исходника. Положи рядом
листинг своей машины из главы 20:

| Python | Что делает | Твоя машина, глава 20 |
|---|---|---|
| `LOAD_FAST 0 (x)` | положить на стек аргумент `x` | `LOAD in[0]` |
| `LOAD_CONST 1 (3)` | положить на стек число 3 | `PUSH 0x03` |
| `BINARY_OP 0 (+)` | снять два, сложить, положить сумму | `ADD` |
| `LOAD_CONST 2 (90)` | положить 90 — это `0x5A` | `PUSH 0x5a` |
| `BINARY_OP 12 (^)` | снять два, XOR, положить | `XOR` |
| `RETURN_VALUE` | снять результат и вернуть | конец работы |

`RESUME` — служебная команда в начале каждой функции, на расчёт она
не влияет. Всё остальное — та же стековая машина: команды без адресов,
данные идут через вершину стека. Проверка: `check(0x1F)` =
(31 + 3) XOR 90 = 34 XOR 90 = 120, то есть `0x22 ^ 0x5A = 0x78`.

Строка байтов — сам байт-код. Каждая команда — два байта: номер
команды и её аргумент. `55 00` — `LOAD_FAST 0`, `53 01` —
`LOAD_CONST 1`, `24 00` — `RETURN_VALUE`. После каждой `BINARY_OP`
(`2d`) стоят ещё два нулевых байта: это место, которое интерпретатор
займёт во время работы своими подсказками для ускорения.

**Честное предупреждение.** Байт-код Python — внутренняя кухня
интерпретатора, а не стандарт. Номера команд и даже их имена меняются
от версии к версии: на Python 3.14 этот вывод будет другим. Поэтому
у себя запускай под 3.13 (`py -V:3.13 dis_demo.py`), если хочешь
увидеть то же, что здесь.

### Зачем это реверсеру

Вспомни главу 20: если программа — интерпретатор плюс байт-код,
изучать надо байт-код, а не интерпретатор. С программами на Python
так же. Python хранит скомпилированный байт-код в файлах `.pyc`,
и вместе с ним — имена переменных и константы (`x`, `3`, `90` ты видел
в выводе выше). Поэтому программу на Python восстанавливают почти
до исходника — гораздо легче, чем программу на C. Для этого есть
отдельные декомпиляторы байт-кода. Какой из них работает с какой
версией Python, меняется каждый год — проверяй по их сайтам, когда
понадобится.

### Программа на Python внутри `.exe`

Чтобы отдать программу на Python человеку без установленного Python,
её собирают в один `.exe`. Самый известный сборщик — **PyInstaller**
`[пáйинстóлер]`. Он кладёт в файл маленький загрузчик на C, а за ним —
архив: интерпретатор Python, библиотеки и байт-код программы. Так
собирают и обычные программы, и вредоносы, поэтому вирусному
аналитику (глава 40) важно узнавать такие файлы с первого взгляда.

Как узнать? В самом конце архива PyInstaller пишет **метку** — восемь
байтов `MEI\014\013\012\013\016` (это запись из исходника на C,
числа после `\` — восьмеричные), в hex: `4D 45 49 0C 0B 0A 0B 0E`.
За меткой — длины частей архива и имя библиотеки Python. Устройство
метки я взял из исходников PyInstaller (файлы `bootloader/src/pyi_archive.h`
и `PyInstaller/archive/writers.py`, октябрь 2026):

```c
struct ARCHIVE_COOKIE
{
    char magic[8];           /* 'MEI\014\013\012\013\016' */
    uint32_t pkg_length;     /* длина всего архива */
    uint32_t toc_offset;     /* где оглавление */
    uint32_t toc_length;     /* длина оглавления */
    uint32_t python_version; /* версия Python одним числом */
    char python_libname[64]; /* имя библиотеки Python */
};
```

В Python тот же формат записан строкой `!8sIIII64s`. Узнаёшь буквы
из П6.6? `8s` — восемь байтов как есть, четыре `I` — по `DWORD`,
`64s` — 64 байта имени. А `!` впереди — порядок байтов **big-endian**,
не little: так решили авторы PyInstaller. Вот где пригодится
знание, что `<` и `!` — разные.

Файл `pyi_check.py`:

```python
# pyi_check.py — не собран ли .exe из программы на Python (PyInstaller)
import struct
import sys

MAGIC = b"MEI\014\013\012\013\016"      # метка в конце архива PyInstaller
COOKIE = "!8sIIII64s"                   # '!' — порядок байтов big-endian

with open(sys.argv[1], "rb") as f:
    data = f.read()
pos = data.rfind(MAGIC)
if pos < 0:
    print("priznakov PyInstaller net")
else:
    magic, length, toc, toc_len, ver, lib = struct.unpack_from(COOKIE, data, pos)
    name = lib.rstrip(b"\0").decode("ascii", "replace")
    print(f"PyInstaller: metka na smeshchenii {pos:X}")
    print(f"Python {ver // 100}.{ver % 100}, biblioteka {name}")
```

`rfind` — как `find`, только ищет с конца: метка стоит в самом хвосте.
Версию PyInstaller записывает одним числом: 3.13 → `3 × 100 + 13` =
`313`. Отсюда `ver // 100` и `ver % 100`.

На задаче 01 программа честно скажет `priznakov PyInstaller net`.
А вот вывод на файле, который я склеил сам по исходнику PyInstaller,
приписав к `01_strings.exe` поддельный архив с меткой:

```
PyInstaller: metka na smeshchenii 3D86B
Python 3.13, biblioteka python313.dll
```

Настоящий `.exe` PyInstaller собирает только на Windows, в облаке
мне его не получить. Собери свой и проверь — это упражнение П6.6.

### Скрипт 1: какой `xor` подозрителен

Из главы 10 ты знаешь: `xor eax, eax` — просто обнуление. А вот `xor`
с числом или с другим регистром — возможная расшифровка (глава 17).
Пусть IDA сама пройдёт по всем функциям и покажет такие места.

Файл `p6_find_xor.py`:

```python
# p6_find_xor.py — найти xor, который НЕ обнуляет регистр
import idautils
import idc

count = 0
for func in idautils.Functions():
    for ea in idautils.FuncItems(func):
        if idc.print_insn_mnem(ea) != "xor":
            continue
        a = idc.print_operand(ea, 0)
        b = idc.print_operand(ea, 1)
        if a == b:
            continue                      # xor eax, eax — обнуление (глава 10)
        print("%X  %-12s xor %s, %s" % (ea, idc.get_func_name(ea), a, b))
        count += 1
print("najdeno: %d" % count)
```

Новые функции IDA (имена сверены с исходниками IDAPython 9.2):

- `idc.print_insn_mnem(ea)` — мнемоника инструкции по адресу
  (глава 9): `"xor"`, `"mov"`;
- `idc.print_operand(ea, n)` — операнд номер `n` текстом, как на
  экране: `0` — первый, `1` — второй;
- `continue` — «пропустить остаток тела цикла и взять следующий
  элемент», как в C.

Открой в IDA `02_xor.exe`, дождись `AU: idle` и запусти скрипт
(**Alt+F7**). У меня на той же сборке получилось так:

```
1400014FF  decrypt      xor eax, 5Ah
1400050CC  __gdtoa      xor eax, 1Fh
140005D82  __gdtoa      xor r12d, 1Fh
1400071B7  __b2d_D2A    xor edi, 1Fh
14000735D  __d2b_D2A    xor ecx, 1Fh
najdeno: 5
```

Имена функций у тебя могут быть другими — например, `sub_…`, если
IDA их не узнала. Адреса и число ложных срабатываний будут свои: код
библиотеки C в твоей сборке (MinGW 14) другой. А строка `decrypt …
xor eax, 5Ah` найдётся обязательно — код задачи у gcc 16.2 тот же.

Из почти 150 инструкций `xor` в файле фильтр оставил пять. Первая —
наша `decrypt` с ключом `5Ah`, попадание. Остальные четыре — в коде
библиотеки C, который печатает дробные числа. Там `xor` с `1Fh` (31)
стоит после инструкции `bsr` — «найти старший единичный бит».
`31 XOR номер_бита` — это счёт нулей перед ним, а вовсе не шифр.

Это и есть **ложное срабатывание** (false positive `[фолс пóзитив]`):
правило поймало то, что только похоже на искомое. Любой поиск по
приметам выдаёт и такое, поэтому скрипт не решает за тебя, а сужает
круг: вместо 150 мест глазами проверить пять.

### Скрипт 2: расшифровать и подписать

Второй скрипт делает то же, что `xor_dump.py` из П6.10, но внутри
IDA — и оставляет результат в базе комментарием.

Файл `p6_xor_comment.py`:

```python
# p6_xor_comment.py — расшифровать XOR под курсором и подписать
import idc

KEY = 0x5A                    # из инструкции xor eax, 5Ah
SIZE = 0x11                   # из main: mov edx, 11h перед call decrypt

ea = idc.here()               # курсор стоит на первом байте таблицы
data = idc.get_bytes(ea, SIZE)
if data is None:
    print("ne udalos prochitat %X" % ea)
else:
    text = bytes(b ^ KEY for b in data).decode("ascii", "replace")
    idc.set_cmt(ea, "XOR %02Xh: %s" % (KEY, text), 1)
    print("%X  %s" % (ea, text))
```

- `idc.get_bytes(ea, size)` — прочитать байты из базы. Вернёт
  `bytes` или `None`, если адреса нет;
- `idc.set_cmt(ea, текст, 1)` — поставить комментарий. Последний
  аргумент: `0` — обычный, `1` — **повторяемый** (П5.7). Повторяемый
  IDA покажет ещё и везде, где на этот адрес ссылаются.

Как запустить: в `decrypt` дважды щёлкни по имени таблицы в строке
с `lea` — IDA перейдёт к первому байту зашифрованного пароля. Не сдвигая
курсор, нажми **Alt+F7** и выбери `p6_xor_comment.py`. В Output
появится:

```
140009000  xor_hides_nothing
```

А в листинге рядом с таблицей — комментарий `XOR 5Ah:
xor_hides_nothing`. Вернись в `decrypt` (Esc): благодаря повторяемому
комментарию расшифровка видна и у строки с `lea`. Теперь любой, кто
откроет базу — ты через месяц или коллега, — сразу увидит, что здесь
спрятано.

Скрипт ничего не меняет в программе: ни в файле, ни в байтах базы.
Он только читает и подписывает. Убрать подпись можно, как в П5.7:
курсор на строку, клавиша `;`, стереть текст.

Так работают и большие скрипты вирусных аналитиков: найти все места,
где вызывается функция расшифровки, взять её аргументы, расшифровать
и подписать каждое. Разница только в том, что их ключи и адреса
находит сам скрипт, а не человек.

## П6.13. Ghidra на Python: PyGhidra

В Ghidra 12 Python 3 подключается через **PyGhidra** `[пай-гúдра]`:
настоящий Python соединяют с Java, на которой написана Ghidra.
Старый встроенный Python 2 (Jython) в Ghidra 12 по умолчанию больше
не включён — его можно доставить отдельным расширением, но учиться
на нём не стоит.

### Запуск Ghidra с Python

Ghidra нужно запускать особым способом (сверено по файлу
`GettingStarted.md` в исходниках Ghidra 12.1.4):

1. Открой папку Ghidra, в ней папку `support`.
2. Запусти **`pyghidraRun.bat`**.
3. В первый раз программа предложит поставить модуль `pyghidra` —
   соглашайся.

`pyghidraRun.bat` берёт Python командой `py` — то есть твою версию
по умолчанию. Ghidra 12.1.4 понимает 3.9–3.14. Если, кроме 3.13,
у тебя стоит и 3.15, по умолчанию будет она, и Ghidra не запустится.
Тогда скажи установщику, какую версию брать по умолчанию: заведи
переменную окружения `PYTHON_MANAGER_DEFAULT` со значением `3.13`
(так описано в документации Python для Windows).

### Скрипт: тот же XOR в Ghidra

Скрипты Ghidra лежат в папке `%USERPROFILE%\ghidra_scripts` — той же,
куда ты клал подсказчик (`tools/hints/README.md`). Создай там файл
`P6XorComment.py`:

```python
# Расшифровать XOR под курсором и подписать (приложение П6)
# @category: Kurs
# @runtime PyGhidra

KEY = 0x5A
SIZE = 0x11

data = getBytes(currentAddress, SIZE)     # байты Java: от -128 до 127!
text = "".join(chr((b & 0xFF) ^ KEY) for b in data)
setEOLComment(currentAddress, "XOR %02Xh: %s" % (KEY, text))
print("%s  %s" % (currentAddress, text))
```

Строки с `@` в начале — служебные: `@category` — в какую папку
Script Manager положит скрипт, `@runtime PyGhidra` — выполнять
настоящим Python 3. Так записаны примеры, которые идут с самой
Ghidra.

- `currentAddress` — адрес под курсором, как `idc.here()` в IDA;
- `getBytes(адрес, сколько)` — прочитать байты;
- `setEOLComment(адрес, текст)` — комментарий в конце строки (EOL —
  end of line). Как `;` в листинге IDA.

Запуск: открой `02_xor.exe` в Ghidra, поставь курсор на первый байт
таблицы, открой **Window → Script Manager**, найди папку `Kurs` и дважды
щёлкни по `P6XorComment.py`.

### Ловушка: байты Java со знаком

Главное отличие от IDA — в комментарии к `getBytes`. В Java тип `byte`
**знаковый**: от −128 до 127 (сама документация Ghidra пишет: «an array
of signed bytes» — «массив байтов со знаком»). Байт `0xC8` придёт
в Python как `-56` — помнишь чтение байта со знаком из главы 3?

Поэтому в скрипте стоит `b & 0xFF`: маска из П6.3 возвращает
привычные 0–255. Без неё на байте `0xC8` получится
`-56 ^ 0x5A = -110`, и `chr(-110)` упадёт с ошибкой
`ValueError: chr() arg not in range(0x110000)` — «аргумент chr вне
допустимого диапазона». В пароле задачи 02 все байты меньше `0x80`,
поэтому без маски скрипт сработал бы. Но первый же файл с ключом
побольше его сломает. Маску ставь всегда.

Скрипт я проверил так: подставил вместо Ghidra функции с теми же
именами, а байты задачи 02 перевёл в знаковые, как это делает Java.
В настоящей Ghidra он ещё не запускался. Если увидишь ошибку —
пришли мне её текст из окна Console.

## П6.14. Python на дороге к гипервизору

Вспомни главу 30. Ты читал `r cr4`, получал `350ef8` и раскладывал
число на биты руками: цифра за цифрой, по таблице главы 33. Это
полезно сделать один раз, чтобы понять. А когда ты будешь отлаживать
свой гипервизор, такие числа пойдут десятками: `CR0`, `CR4`, `EFER`,
записи таблиц страниц. Руками — минуты на каждое и легко ошибиться.
Python сделает это за секунду.

Файл `bits.py`:

```python
# bits.py — разложить системный регистр на биты (главы 30 и 33)
import sys

NAMES = {
    "cr0": {0: "PE", 1: "MP", 2: "EM", 3: "TS", 4: "ET", 5: "NE",
            16: "WP", 18: "AM", 29: "NW", 30: "CD", 31: "PG"},
    "cr4": {0: "VME", 1: "PVI", 2: "TSD", 3: "DE", 4: "PSE", 5: "PAE",
            6: "MCE", 7: "PGE", 8: "PCE", 9: "OSFXSR", 10: "OSXMMEXCPT",
            11: "UMIP", 12: "LA57", 13: "VMXE", 14: "SMXE", 16: "FSGSBASE",
            17: "PCIDE", 18: "OSXSAVE", 20: "SMEP", 21: "SMAP", 22: "PKE",
            23: "CET"},
    "efer": {0: "SCE", 8: "LME", 10: "LMA", 11: "NXE", 12: "SVME",
             13: "LMSLE", 14: "FFXSR", 15: "TCE"},
}


def main():
    if len(sys.argv) < 3 or sys.argv[1].lower() not in NAMES:
        sys.exit("zapusk: python bits.py cr0|cr4|efer ZNACHENIE_V_HEX")
    reg = sys.argv[1].lower()
    value = int(sys.argv[2].replace("`", ""), 16)   # WinDbg: 00000000`00000d01
    print(f"{reg} = {value:X}")
    for bit in range(64):
        if value & (1 << bit):
            print(f"  bit {bit:2}  {NAMES[reg].get(bit, '?')}")


if __name__ == "__main__":
    main()
```

Всё здесь тебе уже знакомо:

- `NAMES` — словарь словарей: имя регистра → (номер бита → имя
  бита). Имена битов — те, что в документации Intel и AMD; главные
  из них разобраны в главе 33. Номера я сверил по открытым исходникам,
  где эти биты записаны константами;
- `.get(bit, '?')` — взять из словаря, а если такого бита нет —
  вернуть `'?'`. Обычные квадратные скобки на неизвестном бите
  остановили бы программу с ошибкой;
- `value & (1 << bit)` — проверка бита, рецепт из П1.2;
- `.replace("`", "")` — WinDbg пишет 64-битные числа с обратной
  кавычкой посередине: `00000000`00000d01` (глава 30). Убираем её,
  и число читается как обычно.

Проверим на числах из глав 30 и 33:

```
python bits.py cr0 80050033
python bits.py cr4 350ef8
python bits.py efer '00000000`00000d01'
```

```
cr0 = 80050033
  bit  0  PE
  bit  1  MP
  bit  4  ET
  bit  5  NE
  bit 16  WP
  bit 18  AM
  bit 31  PG
cr4 = 350EF8
  bit  3  DE
  bit  4  PSE
  bit  5  PAE
  bit  6  MCE
  bit  7  PGE
  bit  9  OSFXSR
  bit 10  OSXMMEXCPT
  bit 11  UMIP
  bit 16  FSGSBASE
  bit 18  OSXSAVE
  bit 20  SMEP
  bit 21  SMAP
efer = D01
  bit  0  SCE
  bit  8  LME
  bit 10  LMA
  bit 11  NXE
```

Сверь с главой 30: в `CR4` те же двенадцать битов, что вышли там
руками (3, 4, 5, 6, 7, 9, 10, 11, 16, 18, 20, 21). Бита 13 (**VMXE**)
нет — рубильник твоего будущего гипервизора выключен, как и было
сказано в главе 33. `EFER = d01` — `SCE`, `LME`, `LMA`, `NXE`, тоже
как в главе 30.

Последнее число я вставил прямо из вывода WinDbg, с обратной кавычкой.
В PowerShell и в Git Bash обратная кавычка — особый символ, поэтому
число взято в одинарные кавычки. В старом окне cmd кавычки не нужны
и даже мешают: там пиши число без них.

Это маленький инструмент, но он из тех, что живут годами. В главах
о гипервизоре понадобятся ещё регистры, и ты будешь дописывать их
в `NAMES` по документации Intel (П4). Дописать словарь — пять минут,
а время, которое он сбережёт, — часы.

## П6.15. Что запомнить

1. **Python для реверсера** — калькулятор, мастерская своих
   инструментов и язык скриптов IDA и Ghidra. Сам гипервизор пишут
   на C и ассемблере.
2. **Версия:** для IDA 9.2 — Python 3.11–3.13, для Ghidra 12.1 —
   3.9–3.14. Ставь **3.13**: `py install 3.13`, потом `idapyswitch`.
3. **У чисел нет размера.** Считаешь как процессор — режь маской:
   для байта `& 0xFF`, для `dword` `& 0xFFFFFFFF`, для `qword` —
   шестнадцать `F`. `//` — целое деление, `/` — дробное.
4. **`str` — текст, `bytes` — числа 0–255.** `b"Hi"[0]` — это `72`.
   Срез `data[off:off + size]` — кусок по смещению и размеру.
5. **Числа из байтов:** `int.from_bytes(b, "little")` или
   `struct.unpack_from("<I", data, off)[0]`. В формате `struct` всегда
   пиши `<`, иначе Python вставит выравнивание, как компилятор C.
6. **Файл целиком:** `with open(path, "rb") as f: data = f.read()`.
   Аргументы — `sys.argv`. Свой модуль — `import pe_info`
   и `if __name__ == "__main__":`.
7. **Свои утилиты:** `hexdump.py`, `pe_info.py`, `strings.py`,
   `xor_dump.py`, `bits.py` — всё это теперь твоё и работает.
8. **Python — стековая машина**, как машина из главы 20: `dis`
   показывает байт-код. Программы на Python читаются почти до исходника.
   В `.exe` от PyInstaller в конце стоит метка `MEI\014\013\012\013\016`.
9. **IDAPython:** `print_insn_mnem`, `print_operand`, `get_bytes`,
   `set_cmt`. Поиск по приметам даёт ложные срабатывания — скрипт
   сужает круг, а решает человек.
10. **PyGhidra:** запуск через `support\pyghidraRun.bat`,
    `@runtime PyGhidra`, `currentAddress`, `getBytes`, `setEOLComment`.
    Байты Java — со знаком: всегда `b & 0xFF`.

**П6.2.** *(практика)* Допиши к `pe_info.py` расшифровку длинных имён
секций: вместо `/4` печатать настоящее имя. Подсказки из документации
Microsoft: в файловом заголовке по смещению `+8` лежит
`PointerToSymbolTable` — где начинается таблица символов, по `+12` —
`NumberOfSymbols`, сколько в ней записей. Каждая запись — 18 байт,
а сразу за таблицей начинается таблица имён. Число после `/` —
смещение имени от её начала, имя кончается нулевым байтом.

и во вкладке Imports в PE-bear (глава 8). Где лежит каталог импортов —
в документации Microsoft: запись №1 в каталогах данных, которые
начинаются со смещения 112 от начала опционального заголовка (для
64-битных файлов). Каждая запись каталога импортов — 20 байт,
последняя — вся из нулей. Проверь на `01_strings.exe`: сколько функций
из каждой DLL?
