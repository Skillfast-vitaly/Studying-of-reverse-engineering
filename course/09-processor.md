# Глава 9. Процессор x86-64: регистры и флаги

> **Часть IV. Язык машины**
> Предыдущая глава: [8. Формат PE](08-format-pe.md)

Начинается главная часть курса. Здесь ты научишься **читать машинный код** —
то, ради чего всё затевалось.

Предупреждение честное: эта часть тяжелее предыдущих. Застрять на неделю —
нормально. Но именно после неё программа перестаёт быть чёрным ящиком.

Начнём с исполнителя — процессора. В этой главе разберём его «руки»
(регистры) и его «память о последнем действии» (флаги).

---

## 9.1. Зачем это знать

Любая строка ассемблера — это действие над регистрами:

```asm
mov eax, DWORD PTR [rbp+16]
add eax, 1
```

Не зная, что такое `eax` и `rbp`, ты видишь шум. Зная — читаешь: «взять
переменную из памяти, прибавить единицу».

Регистров немного, флагов ещё меньше. Это конечный, обозримый набор — его
реально выучить за вечер и пользоваться годами.

## 9.2. Регистр — рука процессора

Вспомни главу 1: процессор не умеет работать с памятью напрямую. Чтобы
что-то сделать с числом, его надо сначала загрузить в **регистр** —
сверхбыструю ячейку внутри самого процессора.

Аналогия: память — это склад, регистры — верстак. Чтобы соединить две
детали, кладовщик приносит их на верстак, работает там и уносит результат
обратно. Верстак маленький — всего 16 мест.

Отсюда узнаваемый ритм почти всего машинного кода:

```
загрузить из памяти в регистр  →  поработать  →  выгрузить обратно
```

Когда впервые откроешь дизассемблер, 80% увиденного окажется этой вознёй.
Не пугайся объёма: смысла там меньше, чем строк.

## 9.3. Шестнадцать регистров

На x86-64 есть **16 регистров общего назначения**, каждый по 8 байт
(64 бита). Вот они, с расшифровкой английских названий — она объясняет
исторические роли:

| Регистр | Расшифровка | Историческая роль |
|---|---|---|
| `RAX` | **A**ccumulator — накопитель | Результат вычислений, возврат из функций |
| `RBX` | **B**ase — база | Хранение адресов |
| `RCX` | **C**ounter — счётчик | Счётчик циклов |
| `RDX` | **D**ata — данные | Дополнение к `RAX` |
| `RSI` | **S**ource **I**ndex — индекс источника | Откуда копировать |
| `RDI` | **D**estination **I**ndex — индекс приёмника | Куда копировать |
| `RBP` | **B**ase **P**ointer — указатель базы | Опора стекового кадра |
| `RSP` | **S**tack **P**ointer — указатель стека | Вершина стека |
| `R8`…`R15` | просто номера | Появились вместе с 64 битами |

Буква `R` в начале означает **R**egister и одновременно 64-битный размер.

Слово «историческая» существенно. Раньше роли были жёсткими: счётчик цикла
обязан был лежать в `CX`. Сейчас процессор почти не диктует, **но
договорённости остались**, и компиляторы им следуют. Поэтому, увидев `RCX`,
есть смысл заподозрить счётчик или первый аргумент функции — угадаешь чаще,
чем ошибёшься.

> Для нашей цели — реверса под Windows — самое важное запомнить пока это:
> **`RAX` обычно содержит результат**, а `RCX`, `RDX`, `R8`, `R9` — аргументы
> функций. Подробно разберём в главе 12.

## 9.4. Один регистр — четыре имени

Вот место, где новички спотыкаются чаще всего. Разберём внимательно.

Регистр `RAX` — 64 бита. Но к его **частям** можно обратиться отдельно,
и у каждой части своё имя:

```
         ┌───────────────────── RAX (64 бита) ─────────────────────┐
         │                                                          │
         │                         ┌────────── EAX (32 бита) ───────┤
         │                         │                                │
         │                         │              ┌── AX (16 бит) ──┤
         │                         │              │                 │
         │                         │              │   AH   │   AL   │
         └─────────────────────────┴──────────────┴────────┴────────┘
          63                      31             15       7        0
```

| Имя | Размер | Что это |
|---|---|---|
| `RAX` | 64 бита, 8 байт | весь регистр |
| `EAX` | 32 бита, 4 байта | младшая половина |
| `AX` | 16 бит, 2 байта | младшая четверть |
| `AL` | 8 бит, 1 байт | самый младший байт |
| `AH` | 8 бит, 1 байт | второй снизу байт |

**Это не разные регистры. Это одна и та же ячейка, просто взятая разными
кусками.** Записал что-то в `AL` — изменился и `RAX`, потому что `AL` внутри
него.

Так же устроены все остальные: `RBX`/`EBX`/`BX`/`BL`, `RCX`/`ECX`/`CX`/`CL`.
У новых `R8`–`R15` схема другая: `R8` / `R8D` (32) / `R8W` (16) / `R8B` (8).

### Зачем это нужно и что даёт реверсеру

Размер используемой части **выдаёт тип данных**. Смотри на настоящий вывод
компилятора — одна и та же функция «прибавить единицу», разные типы в C:

```asm
; char x  (1 байт)
mov  BYTE PTR [rbp+16], al       ; работает с AL

; short x (2 байта)
mov  WORD PTR [rbp+16], ax       ; работает с AX

; int x   (4 байта)
mov  DWORD PTR [rbp+16], ecx     ; работает с ECX
mov  eax, DWORD PTR [rbp+16]

; long long x (8 байт)
mov  QWORD PTR [rbp+16], rcx     ; работает с RCX
mov  rax, QWORD PTR [rbp+16]
```

Видишь закономерность? **По имени регистра и слову перед `PTR` сразу видно
размер данных:**

| В коде | Размер | Тип в C |
|---|---|---|
| `AL`, `BYTE PTR` | 1 байт | `char`, байт строки |
| `AX`, `WORD PTR` | 2 байта | `short`, символ UTF-16 |
| `EAX`, `DWORD PTR` | 4 байта | `int` — самое частое |
| `RAX`, `QWORD PTR` | 8 байт | указатель, `long long` |

Это бесплатная информация. Увидел `AL` и `BYTE PTR` — программа возится
с отдельными байтами, скорее всего со строкой. Увидел `RAX` и `QWORD PTR` —
работа с адресами.

## 9.5. Три особых регистра

Три регистра стоят особняком: формально они такие же, но трогать их
как попало нельзя — сломается выполнение программы.

### `RIP` — счётчик команд

**R**egister **I**nstruction **P**ointer. Мы встречали его в главе 1: в нём
лежит адрес **следующей** инструкции.

Это самый важный регистр в процессоре, потому что управление программой
сводится к управлению им:

- обычная инструкция → `RIP` сам увеличивается на её длину;
- `jmp адрес` → в `RIP` записывается новый адрес;
- `call адрес` → старое значение сохраняется на стеке, в `RIP` — адрес функции;
- `ret` → сохранённое значение снимается со стека обратно в `RIP`.

Записать в `RIP` напрямую (`mov rip, ...`) нельзя — только через переходы.
Это защита: иначе любая ошибка в вычислениях увела бы выполнение в никуда.

> Контроль над `RIP` = контроль над программой. Помнишь переполнение буфера
> из главы 4? Вся его суть — подменить сохранённый адрес возврата, чтобы
> `ret` записал в `RIP` чужое значение.

### `RSP` — указатель стека

**R**egister **S**tack **P**ointer. Хранит адрес вершины стека (глава 4).

Меняется сам при `push` и `pop`, а также при входе в функцию и выходе из
неё. Испортишь `RSP` — функция вернётся не туда, и программа рухнет.

Помни про направление: стек растёт **вниз**, поэтому `push` **уменьшает**
`RSP`, а `pop` увеличивает.

### `RBP` — указатель базы кадра

**R**egister **B**ase **P**ointer. Пока функция работает, `RBP` держит
неподвижную точку опоры на стеке, а локальные переменные адресуются
относительно неё:

```asm
mov  eax, DWORD PTR [rbp+16]    ; взять аргумент
mov  DWORD PTR [rbp-4], eax     ; положить в локальную переменную
```

Ты уже видел такое в главах 2 и 5. Теперь понятно, что это: `rbp` — опора,
число — смещение от неё. Положительные смещения обычно ведут к аргументам,
отрицательные — к локальным переменным.

Подробно стековый кадр разберём в [главе 11](11-stek-i-funkcii.md).

## 9.6. Флаги — память о последнем действии

Теперь вторая половина главы, и она объясняет, как процессор вообще умеет
принимать решения.

Есть отдельный регистр — **`RFLAGS`**. В нём не число, а набор отдельных
битов-признаков. Каждый бит отвечает на один вопрос о **результате
последней операции**.

Четыре флага, которые нужны постоянно:

| Флаг | Расшифровка | Поднимается, когда |
|---|---|---|
| **`ZF`** | **Z**ero **F**lag — флаг нуля | результат равен нулю |
| **`SF`** | **S**ign **F**lag — флаг знака | результат отрицательный (старший бит = 1) |
| **`CF`** | **C**arry **F**lag — флаг переноса | было переполнение **беззнакового** числа |
| **`OF`** | **O**verflow **F**lag — флаг переполнения | было переполнение **знакового** числа |

Работает это так: почти каждая арифметическая инструкция, кроме своего
основного дела, **попутно выставляет флаги**.

```asm
sub eax, 5      ; вычесть 5 из EAX
                ; если получился 0    → ZF = 1
                ; если отрицательное  → SF = 1
```

Флаги живут до следующей операции, которая их перезапишет. Поэтому условный
переход всегда стоит **сразу** за сравнением — иначе флаги уже не те.

## 9.7. Как процессор принимает решения

Соединим всё. Вот как `if` из языка C превращается в машинный код.

Исходник:

```c
int cmp_eq(int a, int b)
{
    if (a == b) return 100;
    return 200;
}
```

Настоящий вывод компилятора:

```asm
cmp_eq:
    cmp   eax, DWORD PTR [rbp+24]   ; сравнить a и b
    jne   .L2                       ; если НЕ равны — прыгнуть на .L2
    mov   eax, 100                  ; иначе вернуть 100
    jmp   .L3
.L2:
    mov   eax, 200                  ; вернуть 200
.L3:
    ret
```

Разберём по шагам — это и есть механизм, на котором стоит всякая проверка
пароля на свете.

**Шаг 1. `cmp eax, [rbp+24]`**

`cmp` (от **comp**are — сравнить) на самом деле **вычитает** второе из
первого. Но результат **никуда не записывает** — он нужен только затем,
чтобы выставить флаги.

```
если a == b  →  a - b = 0   →  ZF = 1
если a != b  →  a - b ≠ 0   →  ZF = 0
```

Вот и всё сравнение. Процессор не «сравнивает» в человеческом смысле — он
вычитает и смотрит на флаг нуля.

**Шаг 2. `jne .L2`**

`jne` (**j**ump if **n**ot **e**qual — прыгнуть, если не равно) смотрит на
`ZF`:

```
ZF = 0 (не равны)  →  прыгнуть на .L2
ZF = 1 (равны)     →  не прыгать, идти дальше
```

**Шаг 3.** Дальше просто: одна ветка кладёт в `EAX` число 100, другая — 200.
Помнишь, `RAX`/`EAX` — регистр результата? Значение, оставленное там, и
вернётся из функции.

### Главный вывод главы

```
     cmp  (вычесть, выставить флаги)
              ↓
     условный переход (посмотреть флаги, решить)
```

**Любая проверка в любой программе — это пара «сравнение + условный
переход».** Пароль, серийный номер, лицензия, срок действия — всё это
`cmp` и `j*` рядом.

Найти в программе нужный `cmp` — значит найти проверку. Понять, какой
переход за ним, — значит понять её логику. Этим мы и займёмся в части VI.

## 9.8. Условные переходы: полный набор

Переходов много, но они устроены логично. Имена — сокращения английских
слов, и, зная расшифровку, их не надо зубрить.

### Проверка на равенство

| Инструкция | Расшифровка | Прыгает, если |
|---|---|---|
| `je` / `jz` | **j**ump if **e**qual / if **z**ero | равно (`ZF = 1`) |
| `jne` / `jnz` | **j**ump if **n**ot **e**qual | не равно (`ZF = 0`) |

`je` и `jz` — **одна и та же инструкция** с двумя именами. Просто иногда
удобнее думать «равно», а иногда «ноль».

### Сравнение чисел: два набора

Вот место, которое замыкает главу 3. Помнишь: в байте не записано, знаковое
число или нет. Так вот — **это записано в инструкции перехода**.

**Для знаковых** чисел (могут быть отрицательными) — слова less и greater:

| Инструкция | Расшифровка | Условие |
|---|---|---|
| `jl` | **j**ump if **l**ess | меньше |
| `jle` | **l**ess or **e**qual | меньше или равно |
| `jg` | **j**ump if **g**reater | больше |
| `jge` | **g**reater or **e**qual | больше или равно |

**Для беззнаковых** (только положительные) — слова below и above:

| Инструкция | Расшифровка | Условие |
|---|---|---|
| `jb` | **j**ump if **b**elow | ниже |
| `jbe` | **b**elow or **e**qual | ниже или равно |
| `ja` | **j**ump if **a**bove | выше |
| `jae` | **a**bove or **e**qual | выше или равно |

**Это даёт тебе бесплатную информацию о типах.** Смотри:

```asm
cmp eax, 10
jl  метка        ; ← знаковое сравнение: в EAX может быть отрицательное
```

```asm
cmp eax, 10
jb  метка        ; ← беззнаковое: в EAX только положительное
```

Байты в `EAX` в обоих случаях одинаковые. Разный **только смысл**, и задаёт
его выбор инструкции. Вот он, ответ на вопрос из главы 3 «как понять,
знаковое число или нет» — посмотреть, каким переходом его проверяют.

### Почему это важно на практике

Путаница знакового и беззнакового — источник настоящих уязвимостей.
Классика:

```c
if (length < MAX_SIZE)     // length объявлена как int (знаковое)
    memcpy(buf, src, length);
```

Если атакующий подсунет `length = -1`, проверка пройдёт (−1 меньше
`MAX_SIZE`). А `memcpy` трактует размер как беззнаковый и увидит
4 294 967 295 — то есть скопирует гигабайты в маленький буфер.

В ассемблере эта ошибка видна как несоответствие: проверка через `jl`
(знаковое), а использование — как беззнаковое. Такие места ищут специально.

## 9.9. Что запомнить

1. **16 регистров общего назначения**, каждый по 8 байт. `RAX` — результат,
   `RCX`/`RDX`/`R8`/`R9` — аргументы функций в Windows.
2. **Один регистр — четыре имени:** `RAX` (64) / `EAX` (32) / `AX` (16) /
   `AL` (8). Это одна ячейка, взятая разными кусками.
3. **Размер выдаёт тип данных:** `AL`+`BYTE PTR` — байты и строки,
   `EAX`+`DWORD PTR` — `int`, `RAX`+`QWORD PTR` — указатели.
4. **`RIP`** — адрес следующей инструкции. Контроль над ним = контроль над
   программой.
5. **`RSP`** — вершина стека, **`RBP`** — опора кадра. Локальные переменные
   адресуются как `[rbp-смещение]`, аргументы как `[rbp+смещение]`.
6. **Флаги** — память о последней операции. Главный `ZF` (результат нулевой).
7. **`cmp` вычитает, но не сохраняет** — только выставляет флаги.
8. **Любая проверка = `cmp` + условный переход.**
9. **Знаковость определяется инструкцией перехода:** `jl`/`jg` — знаковые,
   `jb`/`ja` — беззнаковые.
