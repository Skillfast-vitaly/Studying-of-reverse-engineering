## 5.1. Инструмент, который заменяет установку

Прежде чем ставить настоящий компилятор (этим займёмся в главе 6), возьмём
инструмент, который вообще ничего не требует — работает в браузере и создан
будто специально для нас.

Он называется **Compiler Explorer**, живёт по адресу **godbolt.org**.

Слева ты пишешь код на C. Справа **мгновенно** появляется ассемблер, в
который его превратил компилятор. Для обычного программиста это диковинка.
Для реверсера — это тренажёр: ты своими глазами видишь мост между двумя
мирами, из которого и состоит вся наша работа.

Открой godbolt.org прямо сейчас. Настрой один раз:

1. Язык вверху слева — **C** (не C++).
2. Компилятор справа — выбери **x86-64 gcc** (любой свежей версии).
3. В окошко компилятора допиши флаги: `-O0 -masm=intel`
   - `-O0` — без оптимизации, ассемблер будет похож на исходник;
   - `-masm=intel` — синтаксис Intel, тот, что мы учим в этом курсе.

Всё. Теперь каждый пример из этой главы вставляй слева и смотри справа.
Даже если сейчас ассемблер непонятен — привыкай к его виду. В части IV он
станет родным.

> Настоящий компилятор под Windows поставим в главе 6. Пока godbolt.org
> удобнее: ничего не ломает, ничего не занимает, и сразу показывает главное.

## 5.2. Первая программа

Вот минимальная программа на C:

```c
#include <stdio.h>

int main(void)
{
    printf("Привет\n");
    return 0;
}
```

Разберём построчно — тут каждое слово потом всплывёт в реверсе.

**`#include <stdio.h>`** — «подключи набор готовых функций для ввода-вывода».
`printf` живёт там. Это команда препроцессора, помнишь конвейер из главы 2.

**`int main(void)`** — главная функция. С неё начинается выполнение. `int`
означает, что она вернёт целое число; `void` в скобках — что она не
принимает аргументов. **Любая программа на C начинается с `main`.** В реверсе
найти `main` — первый шаг анализа.

**`{ }`** — фигурные скобки очерчивают тело функции: всё, что она делает.

**`printf("Привет\n");`** — вызов функции печати. В кавычках — что напечатать.
`\n` означает «перевод строки». Точка с запятой в конце — так C отмечает
конец команды (инструкции языка).

**`return 0;`** — «закончить функцию и вернуть 0». Для `main` возврат нуля
означает «программа отработала без ошибок». Это тот самый код возврата,
который в главе 3 мелькал как `0xFFFFFFFF` при ошибке.

Каждая программа в этой главе будет такой формы. Меняться будет только
начинка `main`.

## 5.3. Переменные и типы

Переменная — это именованный кусочек памяти (мы разбирали в главе 4, теперь
в синтаксисе C):

```c
int age = 25;
```

Читается: «заведи переменную `age` типа `int`, положи в неё 25». Слово `int`
называется **типом** — оно говорит компилятору, сколько байт выделить и как
толковать содержимое.

Основные типы, которые встречаются в бинарниках постоянно:

| Тип | Размер | Что хранит | Диапазон |
|---|---|---|---|
| `char` | 1 байт | символ или маленькое число | −128…127 |
| `unsigned char` | 1 байт | байт без знака | 0…255 |
| `short` | 2 байта | небольшое число | −32768…32767 |
| `int` | 4 байта | обычное целое | ±2 миллиарда |
| `unsigned int` | 4 байта | целое без знака | 0…~4 млрд |
| `long long` | 8 байт | большое целое | огромный |
| `float` | 4 байта | дробное число | — |
| `double` | 8 байт | дробное число точнее | — |
| `<что-то> *` | 8 байт | **указатель** (адрес) | — |

Всё это — ровно те размеры 1/2/4/8 из главы 1. Тип в C — это, по сути,
ответ на два вопроса: сколько байт и знаковое ли число. В машинном коде
типов нет (глава 2), поэтому знаковость реверсеру приходится вычислять по
инструкциям — но об этом в части IV.

Заметь ключевое для нас: **`char` — это на самом деле число.** Буква и её
код (глава 3, ASCII) — одно и то же. Поэтому в C можно писать:

```c
char c = 'A';      // то же самое, что char c = 65;
c = c + 1;         // теперь в c лежит 66, то есть 'B'
```

Апострофы `'A'` — это просто удобная запись числа 65. Компилятор подставит
число. В ассемблере ты увидишь именно `65` (или `0x41`), никаких букв.

## 5.4. Ввод и вывод

Печать — `printf`. Внутри можно подставлять значения переменных через
«заполнители»:

```c
int age = 25;
printf("Мне %d лет\n", age);     // %d заменится на значение age → "Мне 25 лет"
```

`%d` — «сюда подставь целое число». Другие частые:

| Заполнитель | Что подставляет |
|---|---|
| `%d` | целое число (int) |
| `%c` | один символ |
| `%s` | строку |
| `%x` | число в шестнадцатеричном виде |
| `%p` | указатель (адрес) |

Ввод с клавиатуры — `scanf`. Тут важная деталь, которая объясняет добрую
половину указателей в чужом коде:

```c
int age;
scanf("%d", &age);       // прочитать число и положить В age
```

Видишь `&age` — «адрес age»? Функция `scanf` должна **изменить** твою
переменную, а сделать это она может, только зная её адрес (глава 4). Поэтому
почти всё, что читает данные, принимает адреса. Увидишь в реверсе, как перед
вызовом функции в регистр кладут адрес переменной, — скорее всего, туда будут
что-то записывать.

## 5.5. Условия

Развилка «если — то»:

```c
int password = 1337;

if (password == 1337) {
    printf("Верно\n");
} else {
    printf("Неверно\n");
}
```

`if (условие)` — если условие истинно, выполняется первый блок, иначе блок
после `else`. Условие — это сравнение.

Операторы сравнения (запомни — они прямо превращаются в инструкции):

| В C | Значение |
|---|---|
| `==` | равно |
| `!=` | не равно |
| `<` `>` | меньше, больше |
| `<=` `>=` | меньше-или-равно, больше-или-равно |
| `&&` | И (оба условия) |
| `\|\|` | ИЛИ (хотя бы одно) |
| `!` | НЕ (переворот) |

Осторожно с частой ловушкой: `==` это **сравнение**, а `=` это
**присваивание**. `if (x = 5)` не сравнивает, а кладёт 5 в x — источник багов.

Почему это центрально для нас: **любая проверка пароля, серийника, лицензии —
это `if` с каким-то сравнением.** Вся работа по «обходу защиты» сводится к
тому, чтобы найти нужный `if` в ассемблере и понять или изменить его. Мы
займёмся этим вплотную в части VI.

## 5.6. Циклы

Повторение. Две основные формы.

**`while`** — «пока условие истинно, повторяй»:

```c
int i = 0;
while (i < 5) {
    printf("%d\n", i);
    i = i + 1;
}
```

**`for`** — то же самое, но компактнее, когда есть счётчик:

```c
for (int i = 0; i < 5; i++) {
    printf("%d\n", i);
}
```

Три части в скобках `for`: начальное значение (`int i = 0`), условие
продолжения (`i < 5`), шаг (`i++`, что значит «увеличить i на 1»). Читается:
«начни с нуля, пока меньше пяти, каждый раз прибавляй один».

Циклы в реверсе узнаются мгновенно по одному признаку: **переход назад**.
В ассемблере это выглядит как прыжок (`jmp`, `jne`...) на адрес, который
**меньше** текущего — то есть «вернись и повтори». Увидел стрелку назад —
это цикл.

Где встречаются циклы, важные для нас: перебор символов строки (проверка
пароля посимвольно), расшифровка данных, обход массива. Почти всякая
проверка чего-то длинного — это цикл.

## 5.7. Функции

Функция — это кусок кода с именем, который можно вызывать. Мы уже видели
`main`, `printf`. Свою пишут так:

```c
int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    int result = add(3, 4);      // вызываем, result станет 7
    printf("%d\n", result);
    return 0;
}
```

Разбор:

- `int add(int a, int b)` — функция по имени `add`, принимает два `int`
  (называются `a` и `b`), возвращает `int`.
- `a` и `b` — **параметры**: значения, которые передают при вызове.
- `return a + b;` — вычислить и вернуть результат.
- `add(3, 4)` — вызов: `a` станет 3, `b` станет 4, вернётся 7.

Для реверса функции — основа основ, по трём причинам:

1. **Программа — это набор функций**, вызывающих друг друга. Анализ идёт
   по функциям, одна за другой.
2. **Вызов функции** в ассемблере — это инструкция `call` (глава 1). Найдя
   все `call`, ты видишь скелет программы.
3. **Как передаются аргументы** — строго по правилам (соглашение о вызовах,
   глава 12). Зная правила, ты читаешь любой вызов: что и куда положили.

Отдельно запомни: вызовы функций Windows (`CreateFileW`, `MessageBoxW` и
прочие из главы 2) выглядят в ассемблере точно так же, как вызов `add`. Это
и позволяет по ним понимать, что программа делает.

## 5.8. Массивы и строки

Массив — набор значений одного типа подряд (глава 4, теперь синтаксис):

```c
int numbers[5] = {10, 20, 30, 40, 50};
printf("%d\n", numbers[2]);      // напечатает 30 — счёт с нуля!
```

Квадратные скобки `[2]` — обращение к элементу по номеру (индексу). **Счёт
идёт с нуля**: первый элемент `[0]`, третий `[2]`. Это универсально для C и
для реверса — привыкай считать с нуля.

Строка в C — это массив символов, заканчивающийся нулевым байтом (глава 4):

```c
char name[] = "Reverse";
```

Компилятор сам добавит `\0` в конце. В памяти это `52 65 76 65 72 73 65 00`
(мы это уже разбирали). Работа со строками — это всегда цикл «пока не ноль».

Например, вот как выглядит подсчёт длины строки вручную — почти наверняка
встретишь похожее в бинарнике:

```c
int length(char *s)
{
    int n = 0;
    while (s[n] != 0) {      // пока текущий символ не нулевой
        n = n + 1;
    }
    return n;
}
```

Цикл идёт по строке, пока не упрётся в `0x00`. Именно так внутри устроена
стандартная функция `strlen`. Узнавать этот шаблон — ценный навык.

## 5.9. Указатели в синтаксисе C

Указатели мы подробно разобрали в главе 4 по смыслу. Теперь — как они
пишутся, потому что в чужом коде (и в декомпиляторе, глава 14) ты увидишь
именно этот синтаксис:

```c
int age = 25;         // обычная переменная
int *p = &age;        // p — указатель, в нём АДРЕС age
                      //   * при объявлении = "это указатель"
                      //   & = "взять адрес"

int value = *p;       // value = 25
                      //   * в коде = "сходи по адресу, возьми значение"
                      //   это называется разыменование

*p = 100;             // записать 100 ТУДА, куда указывает p
                      //   теперь age == 100 !
```

Три значка, которые надо различать намертво:

| Запись | Где | Значение |
|---|---|---|
| `int *p` | при объявлении | «p — указатель на int» |
| `&age` | в коде | «адрес переменной age» |
| `*p` | в коде | «значение по адресу из p» |

Путаница между `*p` (значение) и `p` (адрес) — самая частая ошибка новичков
и одновременно то, что постоянно приходится держать в голове, читая чужой
код. В ассемблере разница видна чётко: обращение по адресу пишется в
квадратных скобках — `[rax]` это «значение по адресу из rax», а `rax` без
скобок это сам адрес. Скобки в ассемблере = звёздочка в C.

## 5.10. Структуры

Структура — это несколько переменных, склеенных в одну именованную группу:

```c
struct User {
    int   id;         // 4 байта
    int   age;        // 4 байта
    char  name[16];   // 16 байт
};

struct User u;
u.id = 1;
u.age = 25;
```

В памяти поля лежат подряд, одно за другим:

```
смещение:   +0        +4        +8
           ┌────────┬────────┬──────────────────┐
           │  id    │  age   │  name[16]        │
           └────────┴────────┴──────────────────┘
```

Точка (`u.id`) — обращение к полю. Для реверса структуры важны тем, как они
выглядят в ассемблере: обращение к полю — это **база плюс смещение**.
`u.age` превратится в «адрес u плюс 4», потому что `age` лежит на 4 байта
дальше начала. Увидишь `mov eax, [rcx+4]` — это, скорее всего, чтение
второго поля структуры, лежащей по адресу из `rcx`.

Так устроен почти весь Windows изнутри: система передаёт программам огромные
структуры, и код только и делает, что читает `[регистр + смещение]`. Научишься
это распознавать — начнёшь понимать работу с системными объектами (это уже
дорога к части VIII, «Windows изнутри»).

## 5.11. Как всё это видит реверсер

Вот ради чего была глава. Возьмём простую функцию на C и посмотрим, во что
её превращает **настоящий** компилятор. Это не выдуманный пример — этот
ассемблер получен gcc прямо сейчас.

Код на C:

```c
int check(int x)
{
    if (x == 1337)
        return 1;
    return 0;
}
```

Во что превратилось (синтаксис Intel):

```asm
check:
    cmp   ecx, 1337      ; сравнить аргумент x с числом 1337
    sete  al             ; если равно — поставить 1, иначе 0
    movzx eax, al        ; расширить до полного результата
    ret                  ; вернуть
```

Смотри, что произошло. Проверка `x == 1337` стала инструкцией `cmp ecx, 1337`.
Число **1337 лежит прямо в коде, открытым текстом.** Это и есть та самая
«магическая константа», по которой ловят проверки. Если бы 1337 было
паролем — ты бы нашёл его, просто пролистав ассемблер.

Запомни соответствие, оно будет работать всегда:

| Конструкция C | Как выглядит в ассемблере |
|---|---|
| `if (a == b)` | `cmp a, b` + условный переход |
| `if (a < b)` | `cmp a, b` + переход по «меньше» |
| сравнение с числом | `cmp регистр, число` — число видно |
| цикл `for`/`while` | `cmp` + переход **назад** |
| вызов функции | `call адрес` |
| `return x` | значение кладётся в `eax`/`rax`, затем `ret` |
| поле структуры | `[регистр + смещение]` |
| элемент массива | `[регистр + индекс*размер]` |

Второй пример — цикл. Код:

```c
int sum(int n)
{
    int s = 0;
    for (int i = 0; i < n; i++)
        s += i;
    return s;
}
```

Ассемблер (существенная часть):

```asm
sum:
    ...
.L3:
    add   edx, eax       ; s += i    (edx — это s, eax — это i)
    add   eax, 1         ; i++
    cmp   ecx, eax       ; сравнить n и i
    jne   .L3            ; ↑ ЕСЛИ не равны — ПРЫГНУТЬ НАЗАД на .L3
    ...
    mov   eax, edx       ; положить s в возвращаемый регистр
    ret
```

Видишь `jne .L3`? Это переход **назад**, на метку выше. Вот он — цикл, как я и
обещал в разделе 5.6. Тело цикла (`s += i; i++`) повторяется, пока `i` не
дорастёт до `n`. Узнав этот силуэт — «cmp и прыжок назад» — ты будешь
опознавать циклы, даже не читая, что внутри.

**Не пытайся сейчас понять ассемблер до конца.** Задача этой главы скромнее:
чтобы ты увидел, что между C и ассемблером есть прямая, узнаваемая связь.
`if` не исчезает — он становится `cmp` + переход. Цикл становится прыжком
назад. Проверка пароля становится сравнением, где число видно. Всему этому
мы посвятим целую часть IV — но фундамент ты уже заложил.

## 5.12. Что запомнить

1. **C учим не чтобы писать, а чтобы читать** результат его компиляции.
2. **`main`** — точка старта, первое, что ищут в бинарнике.
3. **`char` — это число.** Буквы и коды ASCII — одно и то же.
4. **`if` со сравнением** — сердце любой проверки пароля/лицензии.
5. **Цикл** — это переход назад в ассемблере.
6. **`&` даёт адрес, `*` идёт по адресу.** Функции, меняющие переменную,
   берут её адрес.
7. **Структуры и массивы** превращаются в «база + смещение» и
   «база + индекс×размер».
8. **godbolt.org** — твой тренажёр: пиши C, смотри ассемблер.

Если хочется закрепить — не зубри, а поиграй на godbolt.org: меняй числа в
условиях, добавляй циклы, смотри, как меняется ассемблер справа. Полчаса
такой игры дают больше, чем перечитывание главы.

## Упражнения

**5.1.** В коде `if (x = 5)` — что здесь не так, и почему это опасная опечатка?

**5.2.** Программа объявляет `char c = 'Z';`. Какое число реально лежит в `c`?
(ASCII из главы 3 в помощь.)

**5.3.** Ты видишь в ассемблере `cmp eax, 0x1A0A` перед условным переходом.
Какому числу в десятичной равна эта константа, и о чём это говорит?

**5.4.** В функции есть `jne` на адрес **выше** текущей инструкции. Что это,
скорее всего, за конструкция?

**5.5.** Перед вызовом функции программа кладёт в регистр **адрес** локальной
переменной, а не её значение. Что это говорит о том, что функция будет
делать с переменной?

**5.6.** В ассемблере встретилось `mov eax, [rcx+8]`. Если `rcx` — это адрес
структуры, то что, скорее всего, читают?

**5.7.** (На godbolt.) Вставь функцию `check` из 5.11, поменяй `1337` на своё
число, поставь `-O0`. Найди своё число в ассемблере. Теперь включи `-O2` —
изменился ли код? Осталась ли константа видна?
