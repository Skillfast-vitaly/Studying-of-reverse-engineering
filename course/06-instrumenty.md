# Глава 6. Ставим инструменты

Новая часть — и смена жанра. До сих пор мы читали. С этой главы начинаем
**работать руками**. Сначала оборудуем рабочее место: поставим инструменты,

## 6.1. Обзор арсенала

У реверсера есть несколько типов инструментов, и важно не путать их
назначение. Вот карта — держи её в голове.

| Инструмент | Тип | Отвечает на вопрос |
|---|---|---|
| **Detect It Easy** | определитель | «Чем это собрано? Упаковано ли?» |
| **PE-bear** | просмотрщик PE | «Как устроен файл? Что импортирует?» |
| **HxD** | hex-редактор | «Какие байты внутри? Что за строки?» |
| **x64dbg** | отладчик | «Что происходит во время работы?» |
| **Ghidra** | декомпилятор | «Как выглядит код на языке, похожем на C?» |
| **компилятор** | сборщик | «Как мой C превращается в .exe?» |

Два главных инструмента — **x64dbg** (динамический анализ, глава 13) и
**Ghidra** (статический анализ, глава 14). Остальные — помощники. Но начнём
с самого нужного лично тебе: с компилятора, потому что весь курс построен на
том, что ты сам собираешь маленькие программы и смотришь, во что они
превращаются.

## 6.2. Важное предупреждение про антивирус

Прежде чем что-то качать — прочитай, это сэкономит тебе нервы.

**Инструменты реверса антивирусы часто помечают как подозрительные.**
x64dbg, отладчики, упаковщики — всё это «двойного назначения»: тем же самым
пользуются и аналитики, и злоумышленники. Windows Defender вполне может
удалить x64dbg или Ghidra «на всякий случай».

Что делать:

1. **Качай только с официальных источников** (я дам ссылки на каждый).
   Никаких «скачать x64dbg с сайта softportal-скачать-бесплатно». Там будет
   не x64dbg, а что-то другое.
2. Если Defender ругается на инструмент с **официального** источника — это
   ложное срабатывание. Можно добавить папку с инструментами в исключения.
3. **Заведи отдельную папку** для реверса, например `C:\reverse\`, и держи
   всё там. Так проще управлять исключениями и не потерять инструменты.

> Позже, когда дойдём до анализа реального вредоносного ПО (это уже
> продвинутый уровень), понадобится **виртуальная машина** — изолированная
> Windows внутри твоей Windows, чтобы зараза не вышла наружу. Но это не
> сейчас. Всё, что мы разбираем в ближайших главах, — твои собственные
> безобидные программы, их можно запускать прямо на основной системе.

## 6.3. Рабочая папка

Сделай сразу, один раз:

1. Создай папку `C:\reverse\`.
2. Внутри — три подпапки:
   - `C:\reverse\tools\` — сюда инструменты;
   - `C:\reverse\work\` — сюда файлы, которые разбираешь;
   - `C:\reverse\course\` — сюда склонируешь этот курс (покажу в 6.10).

Аккуратность окупается. Реверс — это десятки файлов: дампы, заметки,
патченные копии. Без порядка утонешь.

## 6.4. Компилятор под Windows

В главе 5 мы компилировали в браузере (godbolt.org). Это удобно для
экспериментов, но для настоящей работы нужен компилятор на своей машине —
чтобы собирать программы в `.exe` и тут же вскрывать их.

Для новичка под Windows самый простой путь — **w64devkit**. Это один архив:
распаковал — работает, ничего не прописывается в систему, не ломается.

**Установка:**

1. Открой официальную страницу: **github.com/skeeto/w64devkit**
2. Справа, в разделе **Releases** («Релизы»), скачай свежий файл вида
   `w64devkit-x64-2.10.0.7z.exe` — именно `x64`, для 64-битной Windows.
   Это **самораспаковывающийся архив**: программа, которая при запуске
   просто распаковывает сама себя.
3. Запусти его. Появится окошко с вопросом, куда распаковать. Укажи
   `C:\reverse\tools\` и нажми **Extract** («Распаковать»). Внутри появится
   папка `C:\reverse\tools\w64devkit\`.
4. В этой папке есть `w64devkit.exe` — это запуск консоли с готовым
   компилятором. Запусти его: откроется чёрное окно (терминал).

> На момент написания свежая версия — **2.10.0** от 14 сентября 2026.
> Номер у тебя может быть новее, это нормально. Проверь актуальность
> на странице релизов.

### Важно: это не обычная командная строка Windows

Консоль w64devkit — это **Unix-оболочка** `sh` (shell `[шелл]`, «оболочка» —
программа, которая принимает твои команды). Она похожа на командную
строку Windows (`cmd`), но у неё свои правила. Три отличия нужно знать
сразу, иначе команды будут загадочно не работать:

| Что | В `cmd` | В консоли w64devkit |
|---|---|---|
| Пути | `C:\reverse\work` | `C:/reverse/work` — косая черта **вправо** |
| Запуск программы из текущей папки | `hello.exe` | `./hello.exe` — с `./` впереди |
| Символ `#` в команде | обычный символ | начало комментария, дальше всё игнорируется |

Почему так: обратная косая черта `\` в этой оболочке — служебный символ,
и путь `C:\reverse\work` она превратит в бессмыслицу. А `./` значит «из
этой папки»: Unix-оболочки из соображений безопасности не ищут программы
в текущей папке, пока им явно не скажешь.

**Проверь, что работает.** В этом окне набери:

```
gcc --version
```

Если увидел строчку с версией gcc — компилятор готов. Поздравляю, у тебя на
машине появился инструмент, превращающий C в машинный код.

**Первая сборка.** Перейди в рабочую папку и открой Блокнот для нового
файла:

```
cd C:/reverse/work
notepad hello.c
```

Блокнот спросит, создать ли новый файл, — соглашайся. Впиши:

```c
#include <stdio.h>
int main(void) { printf("Reverse!\n"); return 0; }
```

Сохрани (`Ctrl+S`) и закрой Блокнот. Вернись в консоль:

```
gcc -O0 -o hello.exe hello.c
./hello.exe
```

Если на экране появилось `Reverse!` — ты только что скомпилировал и запустил
свою программу. Всё, ты собрал первый `.exe` своими руками.

Этим же способом будем создавать все учебные программы курса: `notepad
имя.c` — вписать код — сохранить — собрать `gcc` — запустить через `./`.

> Альтернативы w64devkit, если что-то не пошло: **MSYS2** (мощнее, но
> сложнее в установке) или **Dev-C++** (с графическим редактором). Но для
> курса w64devkit — самый беспроблемный вариант, рекомендую его.

## 6.5. Detect It Easy (DIE) — определитель

Первое, что делают с незнакомым файлом, — выясняют, **что это вообще
такое**: каким компилятором собрано, на каком языке написано, не упаковано
ли. Этим занимается **Detect It Easy**, сокращённо DIE.

Зачем это тебе с самого начала: если файл упакован (глава 2, глава 24), то
открывать его в декомпиляторе бесполезно — увидишь распаковщик, а не логику.
DIE предупредит об этом сразу и сэкономит часы.

**Установка:**

1. Официальный источник: **github.com/horsicq/DIE-engine/releases**
2. Скачай архив для Windows (`die_win64_portable_x.xx.zip` — portable-версия,
   без установки).
3. Распакуй в `C:\reverse\tools\die\`.
4. Запускай `die.exe`.

**Как пользоваться:** перетащи любой `.exe` в окно DIE. Он покажет:

- **компилятор** (например, «GCC» или «Microsoft Visual C++») — сразу
  понятно, на чём писали;
- **тип файла** (PE32 / PE64) — 32- или 64-битный;
- **упаковщик**, если есть (например, «UPX») — красный флаг;
- **энтропию** — меру беспорядка в данных. Если она близка к максимуму
  (8.0), данные, скорее всего, сжаты или зашифрованы, то есть упаковано.
  Подробно разберём в [главе 7](07-pervoe-vskrytie.md).

Проверь на своём `hello.exe` из 6.4: DIE должен показать GCC и PE64. А потом
на любой программе из `C:\Windows\System32\` — увидишь «Microsoft Visual
C++». Почувствуй разницу.

## 6.6. PE-bear — просмотрщик структуры файла

Помнишь карту памяти из главы 4 — секции `.text`, `.data`, `.rdata`,
таблицу импортов? **PE-bear** показывает всё это в удобном виде. Это твой
рентген для `.exe`: строение файла, не запуская его.

**Установка:**

1. Официальный источник: **github.com/hasherezade/pe-bear/releases**
2. Скачай архив для Windows, распакуй в `C:\reverse\tools\pe-bear\`.
3. Запускай `PE-bear.exe`.

**Что смотреть** (подробно разберём в главе 8, пока просто освойся):

- вкладка **Sections** — секции файла, их размеры и права;
- вкладка **Imports** — та самая таблица импортов: какие функции Windows
  зовёт программа. Это, как мы говорили в главе 2, лучшая подсказка о её
  назначении;
- поле **Entry Point** — адрес, с которого начнётся выполнение.

Открой в PE-bear свой `hello.exe` и найди в импортах что-то знакомое —
увидишь функции вроде `printf` или системные из `msvcrt.dll` / `KERNEL32.dll`.

## 6.7. HxD — шестнадцатеричный редактор

Иногда надо посмотреть на **сырые байты** файла — те самые пары hex-цифр из
главы 3. Или найти в файле текстовую строку. Или изменить один байт (патчинг,
глава 21). Для этого нужен hex-редактор. Лучший бесплатный — **HxD**.

**Установка:**

1. Официальный сайт: **mh-nexus.de/en/hxd/**
2. Скачай и установи (обычный установщик).

**Что умеет:**

- показывать файл как таблицу байтов (слева hex, справа — как текст);
- искать строки и последовательности байтов;
- **менять байты** и сохранять — это понадобится для патчинга;
- считать контрольные суммы.

Открой `hello.exe` в HxD. В самом начале увидишь байты `4D 5A` — это `MZ`,
подпись любого `.exe` (историческая, инициалы одного из создателей формата).
Пролистай вниз — найдёшь свою строку `Reverse!` открытым текстом. Вот так,
буквально глазами, ищется первое, что стоит искать в незнакомой программе.

## 6.8. Заметки — незаметный, но важный инструмент

Не смейся: **блокнот для заметок — один из главных инструментов реверсера.**
Анализ большой программы — это сотни мелких открытий: «функция по адресу
такому-то проверяет длину», «здесь сравнивается с 1337», «сюда приходит
ввод пользователя». Всё это невозможно удержать в голове.

Заведи привычку записывать. Подойдёт что угодно — обычный текстовый файл,
Obsidian, OneNote. Формат простой: адрес или имя функции — что ты про неё
понял. Со временем из этих заметок складывается карта программы.

В `C:\reverse\work\` под каждый разбираемый файл заводи свой `.txt` с
заметками. Это не бюрократия, это память, которая не помещается в голову.

## 6.9. Два больших инструмента: x64dbg и Ghidra

Эти два — сердце ремесла. Им посвящены отдельные главы (13 и 14), поэтому
здесь только поставим и убедимся, что запускаются. Разбираться будем позже,
не пугайся их сложного вида при первом открытии.

### x64dbg — отладчик

**Отладчик** (глава 4 уже упоминала его) позволяет запустить программу и
остановить её в любой точке, посмотреть регистры, память, пройти по коду
шаг за шагом. Это динамический анализ — наблюдение за живой программой.

**Установка:**

1. Официальный источник: **github.com/x64dbg/x64dbg/releases**
2. Скачай `snapshot_...zip`, распакуй в `C:\reverse\tools\x64dbg\`.
3. Внутри `release\` две папки: в `x64\` лежит `x64dbg.exe` (для 64-битных
   программ), в `x32\` — `x32dbg.exe` (для 32-битных). Наши учебные `.exe` —
   64-битные, значит `x64\x64dbg.exe`.

Запусти `x64dbg.exe`. Откроется окно с четырьмя панелями — код, регистры,
дамп памяти, стек. Сейчас оно выглядит устрашающе. К главе 13 станет
понятным. Пока просто убедись, что запускается.

### Ghidra — декомпилятор

**Ghidra** — бесплатный декомпилятор, разработанный АНБ США и выложенный в
открытый доступ. Он берёт машинный код и восстанавливает из него подобие
кода на C — читать это в разы легче, чем ассемблер. Это главный инструмент
статического анализа.

Ghidra написана на Java, поэтому ей нужна **JDK** (Java Development Kit).

**Установка:**

1. Сначала JDK. Официальный источник: **adoptium.net** — скачай Temurin JDK
   (версии 21 или новее), обычный установщик для Windows.
2. Потом Ghidra. Официальный источник: **github.com/NationalSecurityAgency/ghidra/releases**
3. Скачай архив `ghidra_x.y_PUBLIC_...zip`, распакуй в `C:\reverse\tools\ghidra\`.
4. Запускай `ghidraRun.bat` (двойной клик).

Первый запуск может занять минуту. Если Ghidra ругается, что не находит
Java, — значит JDK не установилась или не прописалась; переустанови JDK
и перезапусти.

Мы освоим Ghidra в главе 14 — там же ты увидишь чудо: как ассемблер
превращается обратно в почти-читаемый C.

## 6.10. Забираем курс и задачи на свою машину

Весь этот курс вместе с учебными задачами лежит в репозитории. Чтобы задачи
были под рукой, скопируй его себе.

Если установлен **Git** (если нет — качай с **git-scm.com**), в консоли
w64devkit или в командной строке:

```
cd C:/reverse/course
git clone https://github.com/Skillfast-vitaly/Studying-of-reverse-engineering .
```

Если с Git пока не хочешь возиться — можно скачать архивом: на странице
репозитория кнопка **Code** («Код») → **Download ZIP** («Скачать ZIP»).

**Собери учебные задачи.** В папке `crackmes/` лежат исходники и Makefile.
Но Makefile настроен под Linux-сборку. Под Windows с w64devkit собери
вручную, например первую задачу:

```
cd C:/reverse/course/crackmes
gcc -O0 -o 01_strings.exe src/01_strings.c
./01_strings.exe
```

Программа попросит пароль. Пока не знаешь — введи что угодно, получишь отказ.
В части VI мы вскроем её и найдём пароль, не зная его заранее. Собственно,
ради этого всё и затевалось.

- [ ] PE-bear открывается, показал секции и импорты
