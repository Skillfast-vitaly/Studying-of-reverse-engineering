## 10.1. Как устроена инструкция

Строка ассемблера выглядит так:

```asm
mov   eax, 5
 │     │    │
 │     │    └─ второй операнд (источник)
 │     └────── первый операнд (приёмник)
 └──────────── мнемоника — что делать
```

**Мнемоника** `[мнемóника]` — короткое имя операции. **Операнды** — то, над
чем она работает.

### Главное правило: читаем справа налево

Мы используем **синтаксис Intel** (его показывают x64dbg, Ghidra, IDA).
В нём порядок такой:

```
операция  КУДА, ОТКУДА
```

То есть:

```asm
mov eax, 5        ; положить 5 В eax      (не «eax в 5»!)
add eax, ebx      ; прибавить ebx К eax
```

Привыкнуть надо сразу, иначе будешь читать код наоборот. Мнемоника
для запоминания: **приёмник всегда первый**, как в математике `x = 5`.

> Существует второй синтаксис — **AT&T**, где порядок обратный
> (`mov $5, %eax`). Он встречается в Linux-инструментах. Мы его не
> используем, но знай, что он есть — иначе однажды удивишься.

### Какими бывают операнды

| Вид | Пример | Что значит |
|---|---|---|
| **Регистр** | `eax` | само значение регистра |
| **Число** | `5`, `0x41` | константа прямо в коде |
| **Память** | `[rbx]` | значение **по адресу** |

Квадратные скобки — ключевое различие, разберём отдельно в 10.3.

## 10.2. `mov` — самая частая инструкция

`mov` (от **mov**e — переместить) копирует данные. На неё приходится
примерно треть всего кода.

```asm
mov eax, 5              ; положить число 5 в eax
mov eax, ebx            ; скопировать ebx в eax
mov eax, [rbx]          ; загрузить из памяти по адресу rbx
mov [rbx], eax          ; сохранить eax в память по адресу rbx
```

Название обманывает: `mov` не перемещает, а **копирует** — источник
остаётся нетронутым.

Одно ограничение, которое стоит знать: **нельзя переслать из памяти сразу
в память**.

```asm
mov [rbx], [rcx]        ; ТАК НЕЛЬЗЯ
```

Приходится через регистр:

```asm
mov rax, [rcx]          ; сначала в регистр
mov [rbx], rax          ; потом в память
```

Отсюда и берётся тот ритм «загрузил — поработал — выгрузил» из главы 9.

### Родственники `mov`

Когда данные меньшего размера кладут в больший регистр, встаёт вопрос: чем
заполнить остаток? Для этого есть две инструкции:

```asm
movzx eax, BYTE PTR [rbx]   ; взять байт, остальное заполнить НУЛЯМИ
movsx rdx, eax              ; взять число, РАСШИРИТЬ ЗНАК
```

- **`movzx`** — **mov** with **z**ero e**x**tend. Для беззнаковых.
- **`movsx`** — **mov** with **s**ign e**x**tend. Для знаковых:
  если число отрицательное, старшие биты заполнятся единицами, чтобы
  значение осталось тем же.

Это снова подсказка о типах: `movzx` — данные беззнаковые, `movsx` —
знаковые.

## 10.3. Квадратные скобки: обращение к памяти

Место, где новички путаются постоянно. Правило простое:

> **Скобки означают «значение по этому адресу».**
> Без скобок — само значение.

```asm
mov rax, rbx        ; скопировать ЧИСЛО из rbx
mov rax, [rbx]      ; сходить по АДРЕСУ из rbx и взять, что там лежит
```

Если помнишь главу 5 — это ровно указатели в C:

| Ассемблер | C | Смысл |
|---|---|---|
| `rbx` | `p` | сам указатель (адрес) |
| `[rbx]` | `*p` | значение по адресу |

**Скобки в ассемблере = звёздочка в C.**

### Полная форма адресации

Внутри скобок может стоять не просто регистр, а целое выражение:

```
[база + индекс*масштаб + смещение]
```

Все части необязательны. Примеры:

```asm
[rbx]                 ; по адресу из rbx
[rbx+8]               ; на 8 байт дальше — поле структуры
[rcx+rdx*4]           ; элемент массива 4-байтовых чисел
[rbp-4]               ; локальная переменная
[rbp+16]              ; аргумент функции
```

**Масштаб** (1, 2, 4 или 8) — это размер элемента массива. Вот настоящий
пример: функция `a[i]` для массива `int`:

```asm
arr:
    movsx rdx, edx                  ; расширить индекс до 64 бит
    mov   eax, DWORD PTR [rcx+rdx*4]  ; a[i]
    ret
```

Читается так: `rcx` — начало массива, `rdx` — индекс, `4` — размер `int`.
Это ровно формула из главы 4: `адрес = начало + индекс × размер`.

**Множитель бесплатно выдаёт тип данных:**

| Множитель | Размер элемента | Что это скорее всего |
|---|---|---|
| `*1` или нет | 1 байт | строка, массив байтов |
| `*2` | 2 байта | `short`, текст UTF-16 |
| `*4` | 4 байта | массив `int` |
| `*8` | 8 байт | массив указателей |

## 10.4. `lea` — вычислить адрес, не ходя по нему

`lea` — **l**oad **e**ffective **a**ddress, «загрузить вычисленный адрес».

Разница с `mov` тонкая, но важная:

```asm
mov rax, [rbx+8]      ; СХОДИТЬ по адресу rbx+8 и взять значение
lea rax, [rbx+8]      ; ПОСЧИТАТЬ rbx+8 и положить сам АДРЕС
```

`lea` использует те же скобки, но **в память не лезет** — только считает
выражение.

В C это выглядело бы так:

```c
rax = *(rbx + 8);     // mov — взяли значение
rax = rbx + 8;        // lea — взяли адрес
```

### Трюк, который сбивает с толку

Компиляторы обожают использовать `lea` **не по назначению** — как быструю
арифметику. Смотри на настоящий пример, функция `x * 9`:

```asm
mul9:
    lea eax, [rcx+rcx*8]     ; x + x*8 = x*9
    ret
```

Никакой памяти здесь нет. Компилятор просто заметил, что `lea` умеет за одну
инструкцию сложить и умножить, и посчитал `x*9` быстрее, чем через `imul`.

Поэтому правило чтения: **увидел `lea` — посмотри, что внутри скобок.**
Если там похоже на адрес (регистр + маленькое смещение) — берут адрес.
Если арифметика с множителями — это просто вычисление.

## 10.5. Арифметика

| Инструкция | Расшифровка | Что делает |
|---|---|---|
| `add a, b` | **add** | `a = a + b` |
| `sub a, b` | **sub**tract | `a = a − b` |
| `inc a` | **inc**rement | `a = a + 1` |
| `dec a` | **dec**rement | `a = a − 1` |
| `imul a, b` | **i**nteger **mul**tiply | `a = a × b` (знаковое) |
| `neg a` | **neg**ate | `a = −a` |

Все они **выставляют флаги** (глава 9) — этим пользуются для проверок.

Деление (`idiv`) выглядит непривычно: делимое берётся из пары регистров
`RDX:RAX`, частное кладётся в `RAX`, остаток — в `RDX`. Увидев `idiv`, ищи
результат именно там.

> Важная деталь для реверса: деление на **константу** компилятор часто
> заменяет умножением. Деление — медленная операция, и вместо неё
> подставляется умножение на «магическое» число со сдвигом. Поэтому
> `x / 10` в ассемблере может выглядеть как умножение на что-то вроде
> `0x66666667` и сдвиг. Увидел такое — это деление, а не шифрование.
> Но не всегда: иногда компилятор оставляет настоящее деление. В главе 18,
> на crackme 03, ты увидишь оба варианта в двух сборках одной программы.

## 10.6. Логические операции и сдвиги

| Инструкция | Что делает |
|---|---|
| `and a, b` | побитовое И |
| `or a, b` | побитовое ИЛИ |
| `xor a, b` | побитовое исключающее ИЛИ |
| `not a` | инверсия всех битов |
| `shl a, n` | **sh**ift **l**eft — сдвиг влево на `n` битов |
| `shr a, n` | **sh**ift **r**ight — сдвиг вправо (беззнаковый) |
| `sar a, n` | **s**hift **a**rithmetic **r**ight — сдвиг вправо со знаком |

Что из этого важно знать наизусть:

**`xor`** — та самая операция из crackme 02. Её ключевое свойство:
применённая дважды с одним ключом, она возвращает исходное значение.
Поэтому на ней строят простейшее шифрование.

**Сдвиги — это умножение и деление на степени двойки:**

```asm
shl eax, 3      ; сдвиг влево на 3 = умножение на 8
shr eax, 2      ; сдвиг вправо на 2 = деление на 4
```

Процессор делает сдвиг за один такт, а умножение — за несколько, поэтому
компилятор заменяет `x * 8` на `shl eax, 3`. Увидев сдвиг, мысленно
переводи его в умножение или деление — так понятнее.

**`and` часто используется для «взять только нужные биты»:**

```asm
and eax, 0xFF   ; оставить только младший байт, остальное обнулить
and eax, 1      ; проверить, чётное ли число (остался ли младший бит)
```

## 10.7. Идиомы: узнавай в лицо

Есть конструкции, которые компилятор использует постоянно. Их надо не
разбирать каждый раз, а **узнавать целиком**, как слова при чтении.

### `xor eax, eax` — обнуление

```asm
xor eax, eax        ; eax = 0
```

Число, сложенное «исключающим ИЛИ» само с собой, всегда даёт ноль.
Зачем так вместо `mov eax, 0`? Короче в машинном коде: 2 байта против 5.

**Увидел `xor регистр, тот же регистр` — это просто обнуление.** Никакого
шифрования здесь нет.

### `test eax, eax` — проверка на ноль

```asm
test al, al
je   метка          ; прыгнуть, если ноль
```

`test` делает побитовое И, **результат выбрасывает**, оставляет только флаги
— как `cmp`, но для проверки на ноль.

`test x, x` даёт ноль тогда и только тогда, когда сам `x` равен нулю.
Поэтому эта пара читается просто: **«если значение ноль — прыгнуть»**.

Где встречается постоянно:

```c
if (p == NULL)      // проверка указателя
while (s[i] != 0)   // конец строки
if (result == 0)    // проверка кода возврата
```

### `cmp al, 65` — сравнение с символом

```asm
cmp al, 65          ; сравнить с 'A'
```

Помнишь ASCII из главы 3? `65` = `0x41` = `'A'`. Дизассемблер покажет
число, а не букву, — переводить придётся самому.

Полезные ориентиры: `48`–`57` (`0x30`–`0x39`) — цифры, `65`–`90` — заглавные,
`97`–`122` — строчные. Увидел сравнение с числом из этих диапазонов —
программа разбирает текст.

## 10.8. Стек: `push` и `pop`

Две инструкции для работы со стеком (глава 4):

```asm
push rax        ; положить rax на вершину стека (RSP уменьшается на 8)
pop  rax        ; снять с вершины в rax (RSP увеличивается на 8)
```

Помни: стек растёт **вниз**, поэтому `push` уменьшает `RSP`.

Где встречается:

- **в начале функции** — сохранить регистры, которые функция испортит;
- **в конце** — вернуть их обратно;
- при нехватке регистров — временно отложить значение.

Важное правило: `push` и `pop` в функции **обязаны быть сбалансированы**.
Сколько положил — столько сними, иначе `ret` возьмёт со стека не адрес
возврата, а мусор, и программа рухнет.

## 10.9. Переходы и вызовы

| Инструкция | Что делает |
|---|---|
| `jmp адрес` | безусловный переход |
| `je`, `jne`, `jl`, `ja`… | условные переходы (глава 9) |
| `call адрес` | вызов функции |
| `ret` | возврат из функции |

Разница между `jmp` и `call` принципиальная:

```asm
jmp  метка      ; просто уйти туда и всё
call функция    ; СОХРАНИТЬ адрес возврата на стеке, потом уйти
```

`call` кладёт на стек адрес следующей инструкции — чтобы `ret` знал, куда
вернуться. Это ровно тот адрес возврата, о котором шла речь в главе 4.

### Как узнать цикл

Ты уже знаешь признак из главы 5, теперь он получает точный смысл:

```asm
.L3:
    ...               ; тело цикла
    cmp  ecx, eax
    jne  .L3          ; ← ПЕРЕХОД НАЗАД, на метку выше
```

**Переход на адрес меньше текущего — это цикл.** Переход вперёд — обычно
`if` (перепрыгнуть блок).

В x64dbg и Ghidra такие переходы рисуются стрелками сбоку, и циклы видно
сразу, без чтения.

## 10.10. Разбор настоящей функции

Теперь главное. Возьмём функцию, скомпилированную по-настоящему, и
прочитаем её целиком. **Исходник ты увидишь только в конце** — сначала
разбираем как реверсер, вслепую.

```asm
check:
    push  rbp                        ; (1)
    mov   rbp, rsp                   ; (2)
    sub   rsp, 16                    ; (3)
    mov   QWORD PTR 16[rbp], rcx     ; (4)
    mov   DWORD PTR -4[rbp], 0       ; (5)
    jmp   .L2                        ; (6)
.L5:
    mov   eax, DWORD PTR -4[rbp]     ; (7)
    movsx rdx, eax                   ; (8)
    mov   rax, QWORD PTR 16[rbp]     ; (9)
    add   rax, rdx                   ; (10)
    movzx eax, BYTE PTR [rax]        ; (11)
    cmp   al, 65                     ; (12)
    je    .L3                        ; (13)
    mov   eax, 0                     ; (14)
    jmp   .L4                        ; (15)
.L3:
    add   DWORD PTR -4[rbp], 1       ; (16)
.L2:
    mov   eax, DWORD PTR -4[rbp]     ; (17)
    movsx rdx, eax
    mov   rax, QWORD PTR 16[rbp]
    add   rax, rdx
    movzx eax, BYTE PTR [rax]        ; (18)
    test  al, al                     ; (19)
    jne   .L5                        ; (20)
    mov   eax, 1                     ; (21)
.L4:
    add   rsp, 16                    ; (22)
    pop   rbp
    ret
```

Страшно? Разберём по частям — окажется, что смысла тут на четыре строки.

### Шаг 1: отбросить служебное

Строки (1), (2), (3) и (22) — это **пролог и эпилог** функции. Сохранили
опору, выделили 16 байт под локальные данные, в конце вернули обратно.
Подробно разберём в главе 11, а пока **просто пропускай их** — смысла в них
нет, они есть у каждой функции.

### Шаг 2: понять, где что лежит

- **(4)** `mov QWORD PTR 16[rbp], rcx` — аргумент из `rcx` сохранили на
  стек. Помнишь главу 9: `[rbp+16]` — положительное смещение, значит
  **аргумент**. Размер `QWORD` — 8 байт — значит это **указатель**.
- **(5)** `mov DWORD PTR -4[rbp], 0` — в локальную переменную (отрицательное
  смещение) положили ноль. Размер 4 байта — `int`.

Уже можно назвать переменные:

```
[rbp+16] → указатель, назовём его s
[rbp-4]  → счётчик типа int, назовём его i, начинается с 0
```

### Шаг 3: узнать цикл

Смотрим на (20): `jne .L5` — переход **назад**, на метку `.L5` выше.
**Это цикл.** Строка (6) `jmp .L2` в начале — прыжок сразу на проверку
условия, типичная схема для `while`.

### Шаг 4: разобрать повторяющийся блок

Строки (7)–(11) и (17)–(18) — **один и тот же код**. Разберём его:

```asm
mov   eax, DWORD PTR -4[rbp]    ; взять i
movsx rdx, eax                  ; расширить до 64 бит (знаковое)
mov   rax, QWORD PTR 16[rbp]    ; взять указатель s
add   rax, rdx                  ; s + i  ← вычисление адреса
movzx eax, BYTE PTR [rax]       ; взять БАЙТ по этому адресу
```

Это `s[i]`. Формула адреса из главы 4: начало + индекс. Размер `BYTE` —
один байт, значит это **строка** (`char *`).

### Шаг 5: прочитать проверки

**(19)–(20):** `test al, al` / `jne .L5` — идиома из 10.7:
«если символ **не** ноль — продолжить цикл». Нулевой байт — конец строки
(глава 4). Значит, цикл идёт по строке до конца.

**(12)–(13):** `cmp al, 65` / `je .L3`. Число 65 — это `'A'` в ASCII.
«Если символ равен `'A'` — прыгнуть на `.L3`».

**(14)–(15):** если не равен — `eax = 0` и выход. Помнишь главу 9: `EAX` —
регистр результата. Значит, **возврат 0**.

**(16)** `.L3`: `add DWORD PTR -4[rbp], 1` — это `i++`.

**(21):** когда строка кончилась — `eax = 1`, **возврат 1**.

### Шаг 6: собрать смысл

```
i = 0
пока s[i] != 0:
    если s[i] != 'A':  вернуть 0
    i++
вернуть 1
```

**Функция проверяет, что вся строка состоит из букв `'A'`.**

Вот исходник, из которого это получилось:

```c
int check(const char *s)
{
    int i = 0;
    while (s[i] != 0) {
        if (s[i] != 'A')
            return 0;
        i++;
    }
    return 1;
}
```

Сходится. **Ты только что прочитал машинный код и восстановил алгоритм** —
именно то, чем занимается реверсер.

### Метод, которым мы это сделали

Запомни порядок — он работает на любой функции:

```
1. Отбросить пролог и эпилог          — служебное, смысла нет
2. Найти аргументы [rbp+…] и локальные [rbp-…]
3. Найти переходы назад               — это циклы
4. Разобрать повторяющиеся блоки      — вычисления адресов
5. Прочитать cmp/test и переходы      — это условия
6. Собрать смысл словами
```

Не пытайся понимать инструкции по одной подряд. **Сначала структура, потом
детали** — иначе утонешь.

## 10.11. Что запомнить

1. **Синтаксис Intel: приёмник первый.** `mov eax, 5` — это «положить 5 в eax».
2. **Скобки — обращение к памяти.** `[rbx]` в ассемблере = `*p` в C.
3. **`[база + индекс*масштаб + смещение]`** — полная форма. Масштаб выдаёт
   размер элемента.
4. **`lea` считает адрес, но часто используется как быстрая арифметика.**
5. **Сдвиги — это умножение и деление** на степени двойки.
6. **Идиомы узнавай целиком:** `xor eax, eax` — обнуление,
   `test al, al` — проверка на ноль.
7. **`call` сохраняет адрес возврата, `jmp` — нет.**
8. **Переход назад — цикл**, переход вперёд — обычно `if`.
9. **Читай функцию сверху: структура → потом детали.**
