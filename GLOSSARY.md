# Словарь терминов

Все инструменты реверс-инжиниринга — на английском. Переводить их никто не
будет, поэтому термины придётся выучить. Хорошая новость: их немного, и
половину ты уже знаешь.

Формат записи:

> **English term** `[примерное произношение]` — перевод
> Объяснение по-русски.

Читай не подряд, а по мере надобности. Каждый раз, когда в главе встретится
незнакомое слово — возвращайся сюда.

---

## Самое основное

**bit** `[бит]` — бит
Наименьшая единица информации. Принимает значение `0` или `1`.

**byte** `[байт]` — байт
Восемь битов. Хранит число от 0 до 255. Базовая единица всего.

**binary** `[бáйнери]` — двоичный; двоичный файл
Два значения. У слова два смысла: «двоичная система счисления» и «бинарник»,
то есть сам файл программы. Фразу «открой бинарник» слышишь постоянно.

**hexadecimal**, сокращённо **hex** `[хексадéсимал, хекс]` — шестнадцатеричный
Система счисления с 16 цифрами: `0`–`9`, затем `A`–`F`. Весь реверс записывает
числа именно так.

**memory** `[мéмори]` — память
Оперативная память, где живёт запущенная программа.

**address** `[адрéс]` — адрес
Номер ячейки памяти.

**pointer** `[пóйнтер]` — указатель
Переменная, которая хранит адрес. Не само значение, а «где лежит значение».

**register** `[рéджистер]` — регистр
Сверхбыстрая ячейка внутри процессора. Их всего 16 штук.

**stack** `[стек]` — стек
Область памяти для временных данных и вызовов функций. Работает как стопка
тарелок: что положил последним, то снимешь первым.

**heap** `[хип]` — куча
Область памяти для данных, которые программа запрашивает по ходу работы.

## Файл программы

**executable** `[игзéкьютебл]` — исполняемый файл
Файл, который можно запустить. В Windows — `.exe`.

**PE (Portable Executable)** `[пи-и]` — «переносимый исполняемый»
Формат файлов `.exe` и `.dll` в Windows. Его устройство разбираем в главе 8.

**ELF (Executable and Linkable Format)** `[элф]`
То же самое, но в Linux. Нам понадобится только для сравнения.

**section** `[сéкшен]` — секция
Часть файла с определённым назначением. Основные: `.text` — код,
`.data` — изменяемые данные, `.rdata` — неизменяемые данные (сюда попадают
текстовые строки).

**header** `[хéдер]` — заголовок
Начало файла, где записано, что это за файл и как его загружать.

**entry point** `[éнтри пойнт]` — точка входа
Адрес первой инструкции, которую выполнит программа после запуска.

**import** `[импóрт]` — импорт
Функция из чужой библиотеки, которой пользуется программа. Таблица импортов —
первое, на что смотрят при анализе: она показывает, что программа умеет делать.

**export** `[экспóрт]` — экспорт
Наоборот: функция, которую библиотека отдаёт наружу.

**DLL (Dynamic Link Library)** `[ди-эл-эл]` — динамически подключаемая библиотека
Файл с функциями, общими для многих программ. Например, `kernel32.dll` —
базовые функции Windows.

**symbol** `[сúмбол]` — символ
Имя функции или переменной, сохранённое в файле. Сильно облегчает анализ.

**stripped** `[стрипт]` — «обрезанный», без символов
Из файла удалили все имена. Вместо `check_password` увидишь `sub_401000`.
Так выглядит большинство реального софта.

## Процессор и код

**CPU (Central Processing Unit)** `[си-пи-ю]` — центральный процессор

**instruction** `[инстрáкшен]` — инструкция, команда
Одно элементарное действие процессора.

**opcode (operation code)** `[óпкод]` — код операции
Число, которым инструкция записана в файле.

**assembly**, разговорно **asm** `[асéмбли, азм]` — ассемблер
Человекочитаемая запись машинного кода. `mov rax, 5` вместо `48 C7 C0 05 00 00 00`.

**disassembler** `[дисасéмблер]` — дизассемблер
Программа, превращающая машинный код обратно в ассемблер.

**decompiler** `[дикомпáйлер]` — декомпилятор
Идёт дальше: превращает ассемблер в подобие исходного кода на C. Не точно,
но читаемо. Главный инструмент современного реверса.

**flag** `[флэг]` — флаг
Бит-признак внутри процессора: «результат был нулём», «было переполнение».
На флагах строятся все условия.

**jump** `[джамп]` — переход, прыжок
Инструкция, меняющая порядок выполнения. Основа условий и циклов.

**call** `[кол]` — вызов
Инструкция вызова функции.

**return** `[ритёрн]` — возврат
Выход из функции обратно к тому, кто её вызвал.

**calling convention** `[кóлинг конвéншен]` — соглашение о вызовах
Правила: в каких регистрах передавать аргументы функции, кто убирает за собой
стек. В Windows свои правила, в Linux другие.

**endianness** `[эндиáннес]` — порядок байтов
В каком порядке записано многобайтовое число. x86 использует little-endian —
младший байт первым. Из-за этого число `0x12345678` в памяти выглядит как
`78 56 34 12`. Сбивает с толку первые сто раз.

## Анализ

**reverse engineering** `[ривёрс инжинúринг]` — обратная разработка
Наша тема: понять устройство программы, не имея исходного кода.

**static analysis** `[стáтик анáлисис]` — статический анализ
Изучение программы **без** запуска. Безопасно, видно всё сразу, но сложно.

**dynamic analysis** `[дайнáмик анáлисис]` — динамический анализ
Изучение программы **во время работы**. Нагляднее, но видно только тот путь,
по которому она реально пошла.

**debugger** `[дибáгер]` — отладчик
Программа, позволяющая остановить другую программу в любом месте и посмотреть
её внутренности. Главный инструмент динамического анализа.

**breakpoint** `[брéйкпойнт]` — точка останова
Метка: «останови программу, когда дойдёшь сюда».

**step over / step into** `[степ óвер / степ úнту]` — шаг с обходом / шаг с заходом
Два способа шагать по коду. `Over` — выполнить вызов функции целиком.
`Into` — зайти внутрь и смотреть, что там.

**dump** `[дамп]` — дамп, слепок
Снимок памяти или файла, сохранённый для изучения.

**patch** `[пэтч]` — патч, заплатка
Изменение байтов в готовом файле, меняющее его поведение.

**crackme** `[крэкми]` — «взломай меня»
Учебная программа, специально написанная для тренировки. В ней есть проверка
пароля, и задача — её пройти. Именно такие лежат в `crackmes/`.

**flag** `[флэг]` — флаг (второе значение)
В задачах CTF — секретная строка, которую нужно добыть. Не путай с флагом
процессора.

**CTF (Capture The Flag)** `[си-ти-эф]` — «захват флага»
Соревнование по компьютерной безопасности, где решают такие задачи.

## Защита программ

**obfuscation** `[обфускéйшен]` — обфускация, запутывание
Намеренное усложнение кода, чтобы его было тяжелее читать. Логику не меняет,
только цену анализа.

**packer** `[пáкер]` — упаковщик
Программа, которая сжимает или шифрует `.exe`, а при запуске распаковывает его
в памяти. Статический анализ упакованного файла бесполезен, пока не распакуешь.

**anti-debugging** `[анти-дибáгинг]` — защита от отладки
Приёмы, которыми программа замечает, что её изучают отладчиком, и меняет
поведение.

**virtual machine (VM) protection** `[вёрчуал машúн]` — защита виртуальной машиной
Самая серьёзная из массовых защит: логика переписывается в собственный
выдуманный язык, а в файле остаётся только интерпретатор.

**keygen (key generator)** `[кúджен]` — генератор ключей
Программа, создающая правильные серийные номера. Написать keygen для учебной
задачи — признак того, что ты полностью понял алгоритм проверки.

## Как учить

Не пытайся выучить словарь целиком — бесполезно. Термины оседают сами, когда
ты встречаешь их в деле по пятому разу.

Но одну вещь сделай прямо сейчас: прочитай раздел «Самое основное» и
«Процессор и код». Эти двадцать слов будут в каждой главе, и лучше, чтобы они
не тормозили чтение.
