# Словарь терминов

Все инструменты реверс-инжиниринга — на английском. Переводить их никто не
будет, поэтому термины придётся выучить. Хорошая новость: их немного, и
половину ты уже знаешь.

Формат записи:

> **English term** `[примерное произношение]` — перевод
> Объяснение по-русски.

Читай не подряд, а по мере надобности. Каждый раз, когда в главе встретится
незнакомое слово — возвращайся сюда.

---

## Самое основное

**bit** `[бит]` — бит
Наименьшая единица информации. Принимает значение `0` или `1`.

**byte** `[байт]` — байт
Восемь битов. Хранит число от 0 до 255. Базовая единица всего.

**binary** `[бáйнери]` — двоичный; двоичный файл
Два значения. У слова два смысла: «двоичная система счисления» и «бинарник»,
то есть сам файл программы. Фразу «открой бинарник» слышишь постоянно.

**hexadecimal**, сокращённо **hex** `[хексадéсимал, хекс]` — шестнадцатеричный
Система счисления с 16 цифрами: `0`–`9`, затем `A`–`F`. Весь реверс записывает
числа именно так.

**memory** `[мéмори]` — память
Оперативная память, где живёт запущенная программа.

**address** `[адрéс]` — адрес
Номер ячейки памяти.

**pointer** `[пóйнтер]` — указатель
Переменная, которая хранит адрес. Не само значение, а «где лежит значение».

**register** `[рéджистер]` — регистр
Сверхбыстрая ячейка внутри процессора. Их всего 16 штук.

**stack** `[стек]` — стек
Область памяти для временных данных и вызовов функций. Работает как стопка
тарелок: что положил последним, то снимешь первым.

**heap** `[хип]` — куча
Область памяти для данных, которые программа запрашивает по ходу работы.

## Файл программы

**executable** `[игзéкьютебл]` — исполняемый файл
Файл, который можно запустить. В Windows — `.exe`.

**PE (Portable Executable)** `[пи-и]` — «переносимый исполняемый»
Формат файлов `.exe` и `.dll` в Windows. Его устройство разбираем в главе 8.

**ELF (Executable and Linkable Format)** `[элф]`
То же самое, но в Linux. Нам понадобится только для сравнения.

**section** `[сéкшен]` — секция
Часть файла с определённым назначением. Основные: `.text` — код,
`.data` — изменяемые данные, `.rdata` — неизменяемые данные (сюда попадают
текстовые строки).

**header** `[хéдер]` — заголовок
Начало файла, где записано, что это за файл и как его загружать.

**entry point** `[éнтри пойнт]` — точка входа
Адрес первой инструкции, которую выполнит программа после запуска.
В заголовке PE записан как RVA (глава 8).

**import** `[импóрт]` — импорт
Функция из чужой библиотеки, которой пользуется программа. Таблица импортов —
первое, на что смотрят при анализе: она показывает, что программа умеет делать.

**export** `[экспóрт]` — экспорт
Наоборот: функция, которую библиотека отдаёт наружу.

**DLL (Dynamic Link Library)** `[ди-эл-эл]` — динамически подключаемая библиотека
Файл с функциями, общими для многих программ. Например, `kernel32.dll` —
базовые функции Windows.

**symbol** `[сúмбол]` — символ
Имя функции или переменной, сохранённое в файле. Сильно облегчает анализ.

**stripped** `[стрипт]` — «обрезанный», без символов
Из файла удалили все имена. Вместо `check_password` увидишь `sub_401000`.
Так выглядит большинство реального софта.

---

**linker** `[линкер]` — компоновщик
Программа, которая собирает готовые куски кода в один `.exe`
и расставляет им окончательные адреса. Глава 2.

## Процессор и код

**CPU (Central Processing Unit)** `[си-пи-ю]` — центральный процессор

**instruction** `[инстрáкшен]` — инструкция, команда
Одно элементарное действие процессора.

**opcode (operation code)** `[óпкод]` — код операции
Число, которым инструкция записана в файле.

**assembly**, разговорно **asm** `[асéмбли, азм]` — ассемблер
Человекочитаемая запись машинного кода. `mov rax, 5` вместо `48 C7 C0 05 00 00 00`.

**disassembler** `[дисасéмблер]` — дизассемблер
Программа, превращающая машинный код обратно в ассемблер.

**decompiler** `[дикомпáйлер]` — декомпилятор
Идёт дальше: превращает ассемблер в подобие исходного кода на C. Не точно,
но читаемо. Главный инструмент современного реверса.

**flag** `[флэг]` — флаг
Бит-признак внутри процессора: «результат был нулём», «было переполнение».
На флагах строятся все условия.

**jump** `[джамп]` — переход, прыжок
Инструкция, меняющая порядок выполнения. Основа условий и циклов.

**call** `[кол]` — вызов
Инструкция вызова функции.

**return** `[ритёрн]` — возврат
Выход из функции обратно к тому, кто её вызвал.

**calling convention** `[кóлинг конвéншен]` — соглашение о вызовах
Правила: в каких регистрах передавать аргументы функции, кто убирает за собой
стек. В Windows свои правила, в Linux другие.

**endianness** `[эндиáннес]` — порядок байтов
В каком порядке записано многобайтовое число. x86 использует little-endian —
младший байт первым. Из-за этого число `0x12345678` в памяти выглядит как
`78 56 34 12`. Сбивает с толку первые сто раз.

## Анализ

**reverse engineering** `[ривёрс инжинúринг]` — обратная разработка
Наша тема: понять устройство программы, не имея исходного кода.

**static analysis** `[стáтик анáлисис]` — статический анализ
Изучение программы **без** запуска. Безопасно, видно всё сразу, но сложно.

**dynamic analysis** `[дайнáмик анáлисис]` — динамический анализ
Изучение программы **во время работы**. Нагляднее, но видно только тот путь,
по которому она реально пошла.

**debugger** `[дибáгер]` — отладчик
Программа, позволяющая остановить другую программу в любом месте и посмотреть
её внутренности. Главный инструмент динамического анализа.

**breakpoint** `[брéйкпойнт]` — точка останова
Метка: «останови программу, когда дойдёшь сюда».

**step over / step into** `[степ óвер / степ úнту]` — шаг с обходом / шаг с заходом
Два способа шагать по коду. `Over` — выполнить вызов функции целиком.
`Into` — зайти внутрь и смотреть, что там.

**dump** `[дамп]` — дамп, слепок
Снимок памяти или файла, сохранённый для изучения.

**patch** `[пэтч]` — патч, заплатка
Изменение байтов в готовом файле, меняющее его поведение.

**crackme** `[крэкми]` — «взломай меня»
Учебная программа, специально написанная для тренировки. В ней есть проверка
пароля, и задача — её пройти. Именно такие лежат в `crackmes/`.

**flag** `[флэг]` — флаг (второе значение)
В задачах CTF — секретная строка, которую нужно добыть. Не путай с флагом
процессора.

**CTF (Capture The Flag)** `[си-ти-эф]` — «захват флага»
Соревнование по компьютерной безопасности, где решают такие задачи.

## Защита программ

**obfuscation** `[обфускéйшен]` — обфускация, запутывание
Намеренное усложнение кода, чтобы его было тяжелее читать. Логику не меняет,
только цену анализа.

**packer** `[пáкер]` — упаковщик
Программа, которая сжимает или шифрует `.exe`, а при запуске распаковывает его
в памяти. Статический анализ упакованного файла бесполезен, пока не распакуешь.

**anti-debugging** `[анти-дибáгинг]` — защита от отладки
Приёмы, которыми программа замечает, что её изучают отладчиком, и меняет
поведение.

**virtual machine (VM) protection** `[вёрчуал машúн]` — защита виртуальной машиной
Самая серьёзная из массовых защит: логика переписывается в собственный
выдуманный язык, а в файле остаётся только интерпретатор.

**keygen (key generator)** `[кúджен]` — генератор ключей
Программа, создающая правильные серийные номера. Написать keygen для учебной
задачи — признак того, что ты полностью понял алгоритм проверки.

## Числа и представление

**two's complement** `[туз кóмплимент]` — дополнительный код
Способ записи отрицательных чисел. Старший бит равен 1 — число
отрицательное. `0xFF` в одном байте это −1, а не 255. Глава 3.

**entropy** `[энтрóпи]` — энтропия
Мера беспорядка в данных, от 0 до 8. Обычный код около 5–6,
а 7.5 и выше означает сжатие или шифрование — признак упаковки. Глава 7.

---

**ASCII** `[áски]` — таблица ASCII
Договорённость, какой байт какой буквой считать: `0x41` — `A`,
`0x30` — `0`. Поэтому в памяти текст виден как числа. Глава 3.

**unsigned** `[ансáйнд]` — без знака, беззнаковый
Число, которое не бывает отрицательным: все биты — величина.
Противоположное — signed `[сайнд]`, знаковое (глава 3). В типах C:
`uint64_t` — беззнаковое на 64 бита (П1).

## Ассемблер

**mnemonic** `[мнемóник]` — мнемоника
Короткое имя инструкции: `mov`, `add`, `cmp`. Человеческая запись того,
что в файле лежит числом.

**operand** `[óперанд]` — операнд
То, над чем работает инструкция. В `mov eax, 5` операнды — `eax` и `5`.
У выдуманной машины задачи 05 так же: в `PUSH 0x1e` операнд — `0x1e`.
Главы 10, 20.

**immediate** `[имúдиэт]` — непосредственное значение
Константа, записанная прямо в инструкции, а не взятая из памяти.
Пятёрка в `mov eax, 5`.

**sign extend** `[сайн икстéнд]` — расширение знака
Перенос числа в регистр большего размера с сохранением знака.
Инструкции `movsx` и `movsxd` (4 байта → 8). Для беззнаковых
используется `movzx` — zero extend, расширение нулями.

**scale** `[скейл]` — масштаб
Множитель в адресации `[база + индекс*масштаб]`. Равен размеру элемента
массива и потому выдаёт тип данных: `*4` — массив `int`,
`*8` — массив указателей.

---

**rotate left, ROTL** `[рóутейт лефт]` — циклический сдвиг влево, вращение
Сдвиг, при котором вытолкнутые слева биты возвращаются справа.
Инструкции `rol` и `ror`. Глава 20.

## Функции и стек

**stack frame** `[стек фрейм]` — стековый кадр
Участок стека, принадлежащий одному вызову функции: её локальные
переменные, сохранённые регистры и адрес возврата. Глава 11.

**prologue** `[прóлог]` — пролог
Первые инструкции функции, создающие кадр:
`push rbp` / `mov rbp, rsp` / `sub rsp, N`.

**epilogue** `[эпилóг]` — эпилог
Последние инструкции, разбирающие кадр: `add rsp, N` / `pop rbp` / `ret`.
Иногда записывается одной инструкцией `leave`.

**return address** `[ритёрн адрéс]` — адрес возврата
Адрес, куда функция вернётся после завершения. Кладётся на стек
инструкцией `call`, снимается инструкцией `ret`. Главная мишень
при переполнении буфера.

**shadow space** `[шэдоу спейс]` — теневое пространство
32 байта, которые вызывающая функция обязана зарезервировать на стеке
перед вызовом — по 8 на каждый из четырёх регистровых аргументов.
Особенность Windows. Из-за него первый аргумент оказывается
по `[rbp+16]`. Глава 11.

**volatile** `[вóлатайл]` — «летучий», не сохраняемый
Регистр, который вызванная функция может испортить свободно:
`RAX`, `RCX`, `RDX`, `R8`–`R11`. Значению в нём нельзя доверять
после вызова.

**non-volatile** `[нон-вóлатайл]` — сохраняемый
Регистр, который функция обязана вернуть в исходном состоянии:
`RBX`, `RBP`, `RSI`, `RDI`, `R12`–`R15`. В таких регистрах держат
долгоживущие значения.

**call stack** `[кол стек]` — стек вызовов
Цепочка кадров: кто кого вызвал. Отладчик показывает её, когда
программа останавливается или падает.

---

**push, pop** `[пуш, поп]` — положить на стек, снять со стека
`push` кладёт значение на вершину стека, `pop` снимает его оттуда.
Глава 4, инструкции — глава 10.

**stack pointer** `[стэк пóйнтер]` — указатель вершины стека
Где сейчас вершина стека. У процессора это регистр `RSP` (глава 11),
у учебной машины главы 20 — своя переменная `sp`.

## Уязвимости и защита

**buffer overflow** `[бáфер оверфлóу]` — переполнение буфера
Запись данных за границы выделенной области. Классический случай —
затирание адреса возврата на стеке, после чего `ret` передаёт
управление атакующему. Главы 4 и 11.

**stack canary** `[стек канéри]` — канарейка на стеке
Секретное число между локальными переменными и адресом возврата.
Перед выходом проверяется: не совпало — программа аварийно завершается.
Защита от переполнения. Глава 11.

**DEP (Data Execution Prevention)** `[ди-и-пи]` — запрет исполнения данных
Защита, запрещающая выполнять код из областей, помеченных как данные.

**ASLR (Address Space Layout Randomization)** `[эй-эс-эл-ар]`
Случайный сдвиг адресов при каждом запуске, чтобы атакующий не мог
знать их заранее. Поэтому адреса в отладчике не совпадают с файловыми.

**use-after-free** `[юз áфтер фри]` — использование после освобождения
Обращение к памяти, которая уже возвращена системе. Частая и опасная
ошибка при работе с кучей.

## Формат PE подробнее

**RVA (Relative Virtual Address)** `[ар-ви-эй]` — относительный виртуальный адрес
Смещение от начала образа в памяти. В файле адреса записаны именно так,
потому что RVA не зависит от того, куда программу загрузят.
Настоящий адрес = база образа + RVA. Глава 8.

**image base** `[имидж бейс]` — база образа
Адрес, по которому загружается программа. У 64-битных `.exe` обычно
`0x140000000`. Из-за ASLR фактическая база отличается.

**IAT (Import Address Table)** `[ай-эй-ти]` — таблица адресов импорта
Таблица в памяти, куда загрузчик Windows записывает настоящие адреса
функций из библиотек. Поэтому вызов WinAPI выглядит как `call [адрес]`
в квадратных скобках. Глава 12.

**section alignment / file alignment** `[сéкшен / файл элáйнмент]` — выравнивание
Шаг, по которому располагаются секции: `0x1000` (страница) в памяти
и `0x200` (сектор) в файле. Из-за разницы данные лежат в файле и в памяти
по разным смещениям.

## Windows

**WinAPI (Windows Application Programming Interface)** `[вин-эй-пи-ай]`
Набор функций, через которые программа просит Windows сделать что-либо:
открыть файл, показать окно, выйти в сеть. Глава 12.

**handle** `[хэндл]` — дескриптор
Номер, который Windows выдаёт программе при открытии объекта — файла,
окна, процесса. Программа работает не с самим объектом, а с его номером.

**суффиксы `A` и `W`** — кодировка строк
`A` (ANSI) — однобайтовые строки, устаревший вариант.
`W` (Wide) — UTF-16, по два байта на символ, основной в современной
Windows. `CreateFileW` принимает строку в UTF-16 — искать её в памяти
надо соответственно.

**венгерская нотация** — способ именования параметров в документации
Microsoft: `h` — дескриптор, `lp` — указатель, `sz` — строка с нулём
на конце, `dw` — 4-байтовое число, `b` — да/нет.

## Отладчик изнутри

**exception** `[иксéпшен]` — исключение
Особая ситуация, при которой процессор прерывает обычную работу: деление
на ноль, обращение к запрещённой памяти, специальная инструкция. Под
отладкой Windows сообщает о каждом исключении отладчику. Глава 13.

**int3** `[инт три]` — инструкция останова, байт `CC`
Её единственная задача — вызвать исключение. Программная точка останова
устроена как подмена первого байта инструкции на `CC`. Глава 13.

**software breakpoint** `[сóфтвэр брéйкпойнт]` — программная точка останова
Точка останова через подмену байта на `CC`. Их можно ставить сколько
угодно, но программа может заметить изменённый байт в своём коде.

**hardware breakpoint** `[хáрдвэр брéйкпойнт]` — аппаратная точка останова
Адрес записывается в отладочный регистр процессора, код не меняется.
Умеет срабатывать на чтение и запись памяти. Их всего четыре.

**debug registers** `[дибáг рéджистерс]` — отладочные регистры `DR0`–`DR3`
Регистры процессора, в которые записывают адреса аппаратных точек
останова.

**TF (Trap Flag)** `[ти-эф, трэп флэг]` — флаг ловушки
Флаг в `RFLAGS`. Если он поднят, процессор после каждой инструкции
вызывает исключение. На этом построен пошаговый режим отладчика.

**system breakpoint** `[сúстем брéйкпойнт]` — системная точка останова
Первая остановка x64dbg: внутри загрузчика Windows в `ntdll.dll`, до
любого кода программы.

**entry breakpoint** `[éнтри брéйкпойнт]` — точка останова на входе
Остановка на точке входа из заголовка PE. Там ещё не `main`, а
стартовый код библиотеки C.

**TLS callback** `[ти-эл-эс кóлбэк]` — TLS-колбэк
Функция, которую Windows вызывает раньше точки входа. У программ,
собранных gcc, они служебные. В главе 23 увидишь, как ими пользуются
для анти-отладки.

**thunk** `[сáнк]` — переходник
Крошечная функция из одной инструкции `jmp [адрес из таблицы импортов]`.
x64dbg подписывает её как `JMP.&имя`. Ещё один вид вызова чужой функции
через таблицу импортов.

**label** `[лéйбл]` — метка
Имя, которое ты сам даёшь адресу или функции. В x64dbg — клавиша `:`.

**copy-on-write** `[кóпи он райт]` — копирование при записи
Хитрость Windows: страница общая для всех, пока в неё не записали; при
первой записи процесс получает свою копию. В карте памяти x64dbg —
буква `C`.

## Декомпилятор

**pseudocode** `[сю́доукоуд]` — псевдокод
То, что выдаёт декомпилятор: код, похожий на C, но не исходник автора.
Имена переменных и часть типов придуманы. Глава 14. Второе место, где
он встречается, — раздел Operation в документации Intel: `←` —
присвоить, `=` — сравнить, `IF … FI`, `EDX:EAX` — пара регистров,
`EAX[7:4]` — биты с 7 по 4 (приложение П4).

**cross-reference, XREF** `[кросс рéференс, экс-реф]` — перекрёстная ссылка
Запись «кто ссылается на это место»: какая инструкция вызывает функцию,
читает переменную или берёт адрес строки. Главный способ передвигаться
по незнакомой программе. Глава 14.

**signature** `[сúгнечер]` — сигнатура
«Паспорт» функции: тип результата, имя и параметры. Например,
`int square_plus(int x, int y)`. Неверная сигнатура в декомпиляторе
рождает фантомные параметры.

**cast** `[каст]` — приведение типа
Запись вида `(ulonglong)x` — «считать `x` другим типом». В псевдокоде
часто появляется как шум, когда декомпилятор не уверен в типе.

**strip, `-s`** `[стрип]` — «раздеть» файл
Удалить из `.exe` таблицу символов (имена функций) и отладочную
информацию: утилитой `strip` или ключом gcc `-s`. Так собирают
настоящие программы. После этого Ghidra называет функции `FUN_адрес`,
а x64dbg показывает просто адреса. В `crackmes/` так собирает
`make hard`. Главы 14, 16.

**inline** `[инлáйн]` — встраивание
Оптимизация: компилятор вставляет тело функции прямо в место вызова.
Функция как отдельный вызов исчезает из кода. Глава 14.

**dead code** `[дэд кóуд]` — мёртвый код
Код, который есть в файле, но никогда не выполняется: его никто
не вызывает.

**project** `[прóджект]` — проект
В Ghidra — папка, где хранятся результаты анализа и твои правки.
Сам `.exe` не меняется.

**Ghidra: имена по умолчанию**
`FUN_` — функция, `DAT_` — данные, `s_` — строка, `param_N` — параметр,
`local_XX` — ячейка стека, `uVar`/`iVar` — переменная в регистре,
`in_` — регистр, которому в функции ничего не присваивали.

---

**decompilation** `[дикомпилéйшен]` — декомпиляция
Перевод машинного кода обратно в подобие языка C. Получается
псевдокод, а не исходник автора. Глава 14.

**casts** `[кастс]` — преобразования типов
Скобки вида `(int)` и `(char *)` в псевдокоде: декомпилятор так
подгоняет типы. Самая частая странность псевдокода — научись смотреть
сквозь них. Глава 14.

**Ghidra** `[гúдра]` — Гидра
Бесплатный дизассемблер с декомпилятором от АНБ США. Читает файл, не
запуская его: находит функции, строки и связи между ними. Глава 14.

**IDA** `[áйда]` — Ай-Ди-Эй, «Айда»
Interactive DisAssembler, «интерактивный дизассемблер» от Hex-Rays,
с декомпилятором; стандарт индустрии, в вакансиях встречается
постоянно. Глава 14.12, приложение П5.

## Наблюдение за поведением

**behavioral analysis** `[бихéйвьерал анáлисис]` — анализ поведения
Наблюдение за программой снаружи: какие файлы, ключи реестра, процессы
и сетевые адреса она трогает. Глава 15.

**registry** `[рéджистри]` — реестр
База настроек Windows и программ. Устроен как дерево: **разделы** (keys)
и в них **значения** (values). `HKCU` (HKEY_CURRENT_USER) — ветка текущего
пользователя.

**Sysinternals** `[сисинтéрналс]` — набор бесплатных утилит Microsoft
Process Monitor, Process Explorer, TCPView и другие. Стандарт для
наблюдения за Windows.

**Process Monitor, Procmon** `[прóцесс мóнитор]`
Записывает все обращения программ к файлам, реестру, процессам и сети.
Работает через свой драйвер в ядре, поэтому просит права администратора.

**Process Explorer** `[прóцесс эксплóрер]`
Показывает процессы деревом, а для выбранного — открытые дескрипторы
и загруженные библиотеки.

**NAME NOT FOUND** `[нейм нот фаунд]` — «имя не найдено»
Результат в Procmon: программа искала файл или значение реестра, которого
нет. Подсказка о том, что программа ожидает найти.

**shell** `[шелл]` — оболочка
Программа, которая принимает твои команды в консоли. В w64devkit — Unix-
оболочка `sh`: пути пишут через `/`, программы из текущей папки
запускают через `./`. Глава 6.

## Практика: разбор задач

**make, Makefile** `[мейк, мейкфайл]` — сборщик и его правила
`make` читает файл `Makefile` и выполняет записанные там команды сборки.
В `crackmes/`: `make` — собрать задачи, `make hard` — оптимизированные
версии без имён. Глава 16.

**отчёт реверсера** (report `[рипóрт]`)
Короткий документ о результате анализа: находка, доказательства
(где и как проверено), адреса в RVA, открытые вопросы. Глава 16.

**XOR** `[эксóр]` — исключающее ИЛИ
Бит результата 1, если биты разные. `(текст ^ ключ) ^ ключ = текст` —
шифрование и расшифровка одна операция; `текст ^ шифр = ключ`.
В C пишется `^`. Глава 17.

**цикл расшифровки**
Рисунок в коде: взять байт из таблицы → `xor`/`add`/`sub` с ключом →
положить в буфер → счётчик → сравнение с длиной → прыжок назад.
Выписывай: откуда, сколько, ключ. Глава 17.

**known-plaintext attack** `[ноун плэйнтекст этáк]` — атака по известному тексту
Зная хотя бы кусок исходного текста, восстановить ключ. Для однобайтового
XOR достаточно одного символа.

**div / idiv** `[див / ай-див]` — деление
`div` — беззнаковое, `idiv` — знаковое. Делимое в `EDX:EAX` (поэтому
перед `div` часто `xor edx, edx`), частное — в `EAX`, остаток — в `EDX`.

**магическое деление** (magic number division)
Деление на константу, записанное умножением на большое число и сдвигом
вправо. Делитель ищи рядом: `x − q × D` — остаток от деления на `D`.
Или посчитай `2^(32+сдвиг) / число`. `0xCCCCCCCD` со сдвигом 35 —
беззнаковое деление на 10. Глава 18.

**идиома «это цифра?»**
`sub x, 0x30` / `cmp x, 9` / `jbe` — беззнаковое сравнение отсекает
символы и ниже, и выше цифр. Так раскрывается `isdigit`.

**movabs** `[мув-эбс]`
Так некоторые дизассемблеры называют `mov` с 8-байтовым числом.
Длинное число, все байты которого в диапазоне `0x20`–`0x7e`, — почти
наверняка текст в little-endian.

## Интерпретаторы и байт-код

**interpreter** `[интёрпретер]` — интерпретатор
Программа, которая читает команды выдуманного (или чужого) языка
и выполняет их одну за другой. Форма в коде: цикл → взять байт
по счётчику → `switch` по байту. Глава 20.

**bytecode** `[бáйткоуд]` — байт-код
Программа для интерпретатора, записанная байтами. Лежит в данных
(`.rdata`), а не в коде. Дизассемблер x86 её не покажет. Главы 2, 20.

**pc (program counter)** `[пи-си, прóуграм кáунтер]` — счётчик программы
Номер текущего байта байт-кода. Аналог `RIP` у настоящего процессора.

**stack machine** `[стэк машúн]` — стековая машина
Машина, команды которой берут числа с вершины стека и кладут результат
туда же. `PUSH 2`, `PUSH 3`, `ADD` → на стеке `5`.

**handler** `[хэ́ндлер]` — обработчик
Кусок кода, выполняющий одну команду машины (или одно событие).
В гипервизоре — обработчик одной причины VM exit.

**dispatcher** `[диспэ́чер]` — диспетчер
Место, где по номеру команды выбирают обработчик. Чаще всего —
`switch`, собранный в таблицу переходов.

**instruction set** `[инстрáкшен сет]` — система команд
Список всех команд машины: код, длина, действие. Первый результат
разбора любого интерпретатора.

**switch / case / default / break** `[свич / кейс / дифóлт / брейк]`
Конструкция C «выбор по значению». `case` — «случай», `default` —
«во всех остальных», `break` — «выйти из `switch`». Без `break`
выполнение проваливается в следующий `case`.

**jump table** `[джамп тэйбл]` — таблица переходов
Во что компилятор превращает `switch`: `cmp x, N` / `ja default` →
чтение `[таблица + x*4]` → `movsxd`/`cdqe` → `add` начало таблицы →
`jmp регистр`. Записи — знаковые расстояния от начала таблицы.

**cdqe, movsxd** `[си-ди-кью-и, мув-эс-экс-ди]` — растянуть со знаком
4-байтовое число до 8 байтов: отрицательное дополняется единицами,
положительное — нулями. `cdqe` — только `EAX` → `RAX`, `movsxd` —
любые регистры и память. `movsxd` — это `movsx` для случая «4 байта
→ 8»; так её пишут дизассемблеры и gcc 16 (gcc до 15-й версии писал
просто `movsx`). Главы 10 и 18 (`movsxd`), 20 (`cdqe`).

**rotate, rol / ror** `[рóутейт, рол / рор]` — вращение, циклический сдвиг
Как сдвиг, но вытолкнутые за край биты входят с другой стороны.
Ничего не теряется, поэтому `ror` на `n` отменяет `rol` на `n`.
В `-O0` выглядит как `(a << n) | (a >> (8 − n))`.

**cmovCC (cmove, cmovne…)** `[си-мув]` — условное перекладывание
`mov`, который срабатывает только при условии — тем же условиям, что
у `je`, `jne`, `jg`. Компилятор ставит его вместо короткого `if`.

**equal, EQ** `[и́квал]` — равно
Буква `e` в `je`, `jne`, `cmove` (глава 9). В машине задачи 05 —
команда `EQ`: снять два числа и сравнить (глава 20).

**tracer** `[трэ́йсер]` — трассировщик
Программа, которая выполняет чужой код в своей копии машины и ведёт
журнал. Сверяется с отладчиком на паре остановок. Глава 20.

**emulator** `[э́мьюлейтер]` — эмулятор
Программа, которая программно изображает целый процессор: разбирает
каждую его инструкцию своим диспетчером. Медленно, но работает где
угодно. В отличие от гипервизора, который даёт исполнять гостевой код
настоящему процессору.

## Windows изнутри

**process** `[прóцесс]` — процесс
То, что Windows создаёт при запуске программы: контейнер со своим
адресным пространством, открытыми дескрипторами, номером PID и минимум
одним потоком. Сам процесс ничего не выполняет. Глава 26.

**thread** `[тред]` — поток
Исполнитель внутри процесса: свой набор регистров, свой стек, свой номер
TID. Вся остальная память процесса у потоков общая. Глава 26.

**PID, TID (Process / Thread IDentifier)** `[пи-ай-ди, ти-ай-ди]` — номер процесса, номер потока
Выдаются при создании. В Windows делятся на 4.

**primary thread** `[прáймери тред]` — главный поток
Поток, который Windows создаёт вместе с процессом. Проходит путь от точки
входа до `main`.

**scheduler** `[шéдьюлер]` — планировщик
Часть ядра, которая раздаёт процессор потокам по очереди.

**quantum** `[квóнтум]` — квант
Отрезок времени (миллисекунды), на который планировщик даёт потоку
процессор.

**context, context switch** `[кóнтекст, кóнтекст свич]` — контекст, переключение контекста
Контекст — сохранённые регистры потока. Переключение контекста —
сохранить регистры одного потока и загрузить регистры другого.
Гипервизор делает то же для целых операционных систем.

**logical processor** `[лóджикал прóцессор]` — логический процессор
Исполнитель в процессоре, способный вести один поток. Ядро с технологией
SMT/Hyper-Threading даёт два логических процессора.

**user space / system space** `[юзер спейс / сúстем спейс]` — пользовательская / системная часть адресов
Нижние 128 ТБ (`0`–`00007FFFFFFFFFFF`) — своя у каждого процесса.
Верхняя часть (от `FFFF800000000000`) — ядро, одна на всех, программе
недоступна.

**free / reserved / committed** `[фри / ризёрвд / комúтид]` — свободна / зарезервирована / выделена
Три состояния страницы. Резерв занимает адреса без памяти, выделение
(commit) даёт память. Обращение к свободной или зарезервированной
странице — исключение.

**page file** `[пейдж файл]` — файл подкачки
Файл `pagefile.sys` на диске, куда Windows выгружает редко используемые
страницы.

**guard page** `[гард пейдж]` — сторожевая страница
Страница с флагом `PAGE_GUARD` (`0x100`). Касание вызывает сигнал для
системы; так растёт стек. В x64dbg — буква `G`.

**stack overflow** `[стек оверфлóу]` — переполнение стека
Поток израсходовал весь зарезервированный под стек объём. Не путать
с переполнением **буфера** (buffer overflow).

**allocation granularity** `[элокéйшен грэнюлéрити]` — гранулярность выделения
Новые области памяти начинаются с адресов, кратных 64 КБ (`0x10000`).
Поэтому их адреса кончаются на `0000`.

**image / mapped / private** `[úмидж / мэпт / прáйвет]` — образ / отображение / частная
Типы страниц: из `.exe`/`.dll`, из другого файла, выданная только этому
процессу (стеки, кучи, `VirtualAlloc`). В x64dbg — `IMG`, `MAP`, `PRV`.

**права страниц — числа**
`0x02` — чтение, `0x04` — чтение и запись, `0x08` — копирование при
записи, `0x20` — выполнение и чтение, `0x40` — **выполнение, чтение
и запись** (присмотрись!).

**VirtualAlloc / VirtualQuery / VirtualFree** — функции памяти
Зарезервировать и/или выделить память / узнать свойства памяти по
адресу / вернуть память. В `R8` у `VirtualAlloc`: `0x1000` — commit,
`0x2000` — reserve, `0x3000` — оба.

**EPROCESS, ETHREAD** `[и-прóцесс, и-тред]`
Записи о процессе и потоке в ядре Windows. Программе недоступны. Глава 30.

**PEB (Process Environment Block)** `[пи-и-би]` — блок окружения процесса
Сведения о процессе в его собственной памяти: база образа, загруженные
библиотеки, командная строка.

**TEB (Thread Environment Block)** `[ти-и-би]` — блок окружения потока
Сведения о потоке в памяти процесса: границы стека, TID, код последней
ошибки (его возвращает `GetLastError`).

**loader** `[лóудер]` — загрузчик
Код в `ntdll.dll`, который при старте процесса подгружает библиотеки,
заполняет IAT и вызывает TLS-колбэки. Второе значение — в IDA: модуль,
который умеет читать свой формат файлов (PE, ELF…); выбирается
в окне Load a new file (приложение П5).

**thread pool** `[тред пул]` — пул потоков
Служебные потоки Windows в процессе (`ntdll.dll!TppWorkerThread`).
Программа их сама не создавала.

**access violation, `C0000005`** `[áксесс вайолéйшен]` — нарушение доступа
Исключение при обращении к памяти, к которой нет доступа: нулевой
указатель, невыделенная страница, запись в страницу «только чтение».

**VMMap** `[ви-эм-мэп]`
Утилита Sysinternals: вся память процесса по типам, с резервом
и выделением отдельно.

## Режимы процессора и ядро

**protection rings** `[протéкшен рингз]` — кольца защиты
Четыре уровня привилегий процессора x86-64, от 0 (все права) до 3
(меньше всего прав). Windows использует только кольца 0 и 3. Глава 27.

**kernel mode / user mode** `[кёрнел мóуд / юзер мóуд]` — режим ядра / режим пользователя
Кольцо 0 — ядро Windows и драйверы. Кольцо 3 — все программы, даже
запущенные от администратора.

**CPL (Current Privilege Level)** `[си-пи-эл]` — текущий уровень привилегий
Номер кольца, в котором процессор работает сейчас. Хранится в двух
младших битах регистра `CS`: у программ `CS = 0x33` (кольцо 3), у ядра
`0x10` (кольцо 0).

**CS (Code Segment)** `[си-эс, коуд сéгмент]` — сегмент кода
Сегментный регистр. В 64-битном режиме его главная роль — хранить
номер текущего кольца. Подробно — глава 33.

**privileged instruction** `[прúвилиджд инстрáкшен]` — привилегированная инструкция
Инструкция, разрешённая только в кольце 0: `hlt`, `cli`, `sti`,
`mov cr…`, `rdmsr`, `wrmsr`, `lgdt`, `lidt`, `invlpg` (а в Windows
программам запрещены и `in`, `out`). Попытка выполнить, например,
`hlt` или `wrmsr` в кольце 3 — исключение `C0000096`
(`STATUS_PRIVILEGED_INSTRUCTION`).

**inline assembly** `[инлайн эссéмбли]` — ассемблерная вставка
Инструкция на ассемблере прямо в коде на C: `__asm__ volatile ("hlt");`.

**system call** `[сúстем кол]` — системный вызов
Законная просьба программы к ядру через инструкцию `syscall`. Одна из
трёх «дверей» в кольцо 0. Глава 28.

**hardware interrupt** `[хáрдвэр интерáпт]` — аппаратное прерывание
Сигнал от устройства (таймер, клавиатура, диск), который в любой момент
уводит процессор в ядро. Благодаря прерываниям таймера планировщик
может отнять процессор у любого потока. Глава 34.

**page fault** `[пейдж фолт]` — страничный сбой
Исключение при обращении к странице, которую процессор не может
использовать как есть. Часто ядро обрабатывает его молча — например,
подставляет физическую память при первом обращении.

**first chance / last chance exception** `[фёрст чанс / ласт чанс]` — исключение первого / последнего шанса
Под отладкой Windows показывает исключение отладчику дважды: сначала
до самой программы (первый шанс), потом — если программа его не
обработала (последний шанс).

**ntoskrnl.exe** `[эн-ти-оу-эс-кёрнел]` — ядро Windows
Файл ядра: планировщик, менеджер памяти, объекты, процессы. Обычный
PE-файл с Subsystem = 1 (Native). Не путать с `kernel32.dll` — та
работает в кольце 3.

**driver** `[дрáйвер]` — драйвер
Модуль `.sys`, который загружается в ядро и работает в кольце 0 наравне
с ним. Импортирует функции у `ntoskrnl.exe`. Глава 29.

**HAL (Hardware Abstraction Layer)** `[хэл]` — слой абстракции оборудования
Прячет от ядра различия между компьютерами. В 64-битной Windows встроен
в `ntoskrnl.exe`; `hal.dll` остался ради совместимости.

**Subsystem** `[сабсúстем]` — подсистема (поле заголовка PE)
`1` — Native (ядро, драйверы), `2` — программа с окнами, `3` — консольная.

**bug check / BSOD** `[баг чек / би-эс-оу-ди]` — аварийная остановка системы
Остановка всей Windows при ошибке в кольце 0. В народе «синий экран
смерти» (Blue Screen of Death); с Windows 11 24H2 экран чёрный.
Выполняется функцией `KeBugCheckEx`.

**hypervisor** `[хáйпервайзер]` — гипервизор
Программа, работающая в особом режиме процессора, старше кольца 0,
и управляющая целыми операционными системами — гостями. Неофициально —
«кольцо −1». Главы 35–39.

**guest** `[гест]` — гость
Операционная система, работающая под гипервизором со всеми своими
кольцами.

**VM exit / VM entry** `[ви-эм экзит / ви-эм энтри]` — выход из ВМ / вход в ВМ
Переход процессора из гостя в гипервизор (когда гость сделал то, что
велено перехватывать) и обратно.

**VT-x / AMD-V (SVM)** `[ви-ти-экс / эй-эм-ди-ви]` — аппаратная виртуализация
Расширения процессоров Intel и AMD для гипервизоров. Режимы Intel:
VMX root (гипервизор) и VMX non-root (гость). Глава 35.

**VBS (Virtualization-Based Security)** `[ви-би-эс]` — безопасность на основе виртуализации
Защита Windows, которая запускает под системой гипервизор Microsoft.
Если она включена, Windows сама работает гостем. Проверка — `msinfo32`.

**nested virtualization** `[нéстид вёрчуалайзéйшен]` — вложенная виртуализация
Виртуальная машина, внутри которой можно запустить ещё один гипервизор.
Так мы будем испытывать свой.

## Системные вызовы

**Native API** `[нéйтив эй-пи-áй]` — «родной» API Windows
Функции, которые понимает само ядро, с приставками `Nt` и `Zw`:
`NtCreateFile`, `NtClose`. Документированы частично (`winternl.h`).
WinAPI-функции в итоге зовут их. Глава 28.

**Nt / Zw** — приставки Native API
В кольце 3 — одна и та же заглушка в `ntdll.dll`. В ядре `Zw…`
говорит «параметры из ядра, им можно верить», поэтому драйверы зовут
`Zw…`. Буквы `Zw` ничего не значат.

**NTSTATUS** `[эн-ти стéйтус]` — код результата Native API
32-битное число в `RAX`: `0` — успех, `8…` — предупреждение,
`C…` — ошибка. Например, `C0000034` — имя не найдено. `kernelbase.dll`
переводит его в код Win32 для `GetLastError`. В x64dbg — строка
`LastStatus`.

**stub** `[стаб]` — заглушка
Короткая функция-переходник. Заглушка системного вызова в `ntdll.dll`:
`mov r10, rcx` / `mov eax, номер` / `syscall` / `ret`.

**SSN (System Service Number)** `[эс-эс-эн]` — номер системного вызова
Число в `EAX` перед `syscall`, индекс в таблице ядра. Меняется от
версии к версии Windows. Графические вызовы — от `0x1000`.

**SSDT (System Service Descriptor Table)** `[эс-эс-ди-ти]` — таблица системных сервисов
Таблица в ядре, где по номеру вызова находится адрес функции.

**MSR (Model-Specific Register)** `[эм-эс-áр]` — регистр настроек процессора
Особые регистры, читаются `rdmsr`, пишутся `wrmsr` — только в кольце 0.
В `LSTAR` записан адрес обработчика `syscall`. Глава 33.

**KiSystemCall64** — обработчик системных вызовов
Код ядра, куда процессор прыгает по `syscall`: переключает стек,
сохраняет регистры, находит функцию по номеру и вызывает её.

**trap frame** `[трэп фрейм]` — ловушечный кадр
Структура на стеке ядра, куда при входе в ядро сохраняются регистры
программы, чтобы потом вернуть поток точно на место.

**PreviousMode** `[прúвиэс мóуд]` — предыдущий режим
Поле потока: откуда пришёл вызов, из режима пользователя или ядра.
Если из пользователя, ядро проверяет все указатели и права.

**sysret** `[сис-рет]` — возврат из системного вызова
Привилегированная инструкция: `RIP` ← `RCX`, `RFLAGS` ← `R11`,
процессор возвращается в кольцо 3.

**KUSER_SHARED_DATA** `[кей-юзер шэрд дэйта]` — общая страница ядра
Страница по адресу `0x7FFE0000`, одинаковая во всех процессах. Ядро
кладёт туда общие сведения; по смещению `0x308` — флажок способа входа
в ядро.

**win32u.dll / win32k.sys** — графическая часть системных вызовов
`win32u.dll` — заглушки `NtUser…` и `NtGdi…` в кольце 3; `win32k…sys` —
окна и графика в ядре.

## Первый драйвер

**DriverEntry** `[дрáйвер э́нтри]` — точка входа драйвера
Функция, которую ядро вызывает один раз после загрузки `.sys`:
`DriverEntry(DriverObject, RegistryPath)`. Работает в процессе System
(PID 4) на `PASSIVE_LEVEL`. Возвращает `NTSTATUS`; ошибка — драйвер
выгружают, **не** вызывая функцию выгрузки. Глава 29.

**DRIVER_OBJECT** `[дрáйвер óбджект]` — объект драйвера
Структура-«паспорт» драйвера в ядре. Её создаёт ядро и передаёт
в `DriverEntry`. Поле `DriverUnload` (смещение `0x68` в x64) — адрес
функции выгрузки, дальше `MajorFunction` — таблица обработчиков запросов.

**DriverUnload** `[дрáйвер анлóуд]` — функция выгрузки
Функция обратного вызова: ядро зовёт её при `sc stop`. Не задана —
драйвер не выгрузить до перезагрузки (ошибка 1052).

**callback** `[кóлбэк]` — функция обратного вызова
Функция, адрес которой отдают кому-то другому, чтобы тот позвал её
потом. Драйвер — «набор функций обратного вызова». Приложение П1, глава 29.

**WDK (Windows Driver Kit)** `[дабл-ю-ди-кей]` — набор для разработки драйверов
Заголовки ядра (`ntddk.h`), библиотеки, шаблоны проектов для Visual
Studio, инструменты подписи. Версия WDK должна совпадать с версией
**SDK** (Software Development Kit).

**WDM / KMDF** `[дабл-ю-ди-эм / кей-эм-ди-эф]` — модели драйверов
WDM (Windows Driver Model) — прямая работа со структурами ядра.
KMDF (Kernel-Mode Driver Framework) — каркас поверх неё. Учебные
драйверы и гипервизоры обычно пишут на WDM.

**DbgPrintEx** `[дибáг принт экс]` — сообщение отладчику ядра
`DbgPrintEx(компонент, уровень, формат, ...)`. Проходит фильтр, если
`(1 << уровень) & маска` не ноль; маска по умолчанию `0x1`, поэтому
без правки реестра видно только `DPFLTR_ERROR_LEVEL`. Читать — в
DebugView или отладчике ядра.

**UNICODE_STRING** `[юникóуд стринг]` — строка ядра
Структура: `Length` (длина в **байтах**), `MaximumLength`, `Buffer`
(указатель на UTF-16). 16 байт в x64. Печатается форматом `%wZ`.

**SAL (`_In_`, `_Out_`)** `[сэл]` — пометки параметров
Source code Annotation Language: подсказки анализатору кода, читает
функция параметр или пишет в него. На сборку не влияют.

**test signing** `[тест сáйнинг]` — тестовая подпись
Подпись драйвера сертификатом, который создал сам разработчик
(`WDKTestCert`). Windows принимает её только в тестовом режиме:
`bcdedit /set testsigning on`, Secure Boot выключен.

**Secure Boot** `[сикьюэ бут]` — безопасная загрузка
Защита UEFI: при старте проверяет подписи всего, что загружается.
Пока включена, тестовый режим не включить.

**sc (Service Control)** `[эс-си]` — управление службами
Команда Windows: `sc create имя type= kernel binPath= путь`, `sc start`,
`sc stop`, `sc delete`. Пробел ставится **после** `=`.

**System (PID 4)** `[сúстем]` — системный процесс
Процесс без своей программы, в котором работают системные потоки
ядра. В нём выполняется `DriverEntry`.

**checkpoint / snapshot** `[чéкпойнт / снэ́пшот]` — снимок виртуальной машины
Сохранённое состояние машины; к нему можно вернуться за секунды.
Делай перед каждым опытом с ядром.

**crash dump** `[крэш дамп]` — дамп памяти после падения
Файл `MEMORY.DMP` или папка `Minidump`, куда Windows сохраняет память
при синем экране. Открывается в WinDbg (глава 30).

**double fetch** `[дабл фэтч]` — двойное чтение
Ошибка драйвера: поле из памяти программы проверено при одном
чтении, а использовано при другом, и между ними программа его
подменила. Лечится копированием к себе. Глава 29, приложение П3.

## Отладка ядра

**kernel debugger** `[кёрнел дибáгер]` — отладчик ядра
Отладчик, который останавливает всю систему целиком. Работает на
другой машине, потому что остановленное ядро не может обслуживать
сам отладчик. Глава 30.

**host / target** `[хóуст / тáргет]` — хост / цель
Хост — машина с отладчиком (у нас основная). Цель — отлаживаемая
машина (у нас виртуальная).

**WinDbg** `[вин-дéбаг]` — отладчик Microsoft
Отлаживает программы, ядро и дампы. Ставится через `winget install
Microsoft.WinDbg`. Команды — в окне **Command**.

**KDNET** `[кей-ди-нет]` — отладка ядра по сети
Настраивается в цели программой `kdnet.exe адрес_хоста порт`, которая
выдаёт **ключ** (key) для подключения. В WinDbg — Ctrl+K, вкладка Net.

**symbols, .pdb** `[сúмболз, пи-ди-би]` — символы
Файл с именами функций, переменных и номерами строк. Для Windows —
публичные символы с сервера Microsoft. Команды `.symfix`,
`.sympath+ папка`, `.reload`. Имена пишутся `модуль!имя`, ядро — `nt`.

**unresolved breakpoint (bu)** `[анризóлвд брéйкпойнт]` — неразрешённая точка останова
Точка по **имени** функции модуля, который ещё не загружен. Отладчик
ставит её сам, когда модуль появится: `bu Hello!DriverEntry`.

**extension** `[икстéншн]` — расширение отладчика
Команда с `!` (`!process`, `!pte`, `!idt`, `!analyze`), которая знает
устройство Windows, а не только процессора.

**PFN (Page Frame Number)** `[пи-эф-эн]` — номер физической страницы
Биты 12–51 записи таблицы страниц. Физический адрес = PFN × `0x1000`.
В выводе `!pte`: `pfn 3b2a1` → адрес `0x3B2A1000`.

**PXE / PPE** `[пи-экс-и / пи-пи-и]` — имена уровней в WinDbg
PXE = PML4E, PPE = PDPTE; дальше PDE и PTE, как в главе 32.

**W^X** `[дабл-ю ксор экс]` — запись исключает выполнение
Правило: страницу можно или менять (данные), или выполнять (код),
но не то и другое сразу. В `!pte`: у кода `R` и `E`, у данных `W`
и чёрточка вместо `E`.

**DirBase / DirectoryTableBase** `[дир-бейс]` — корень таблиц процесса
Значение `CR3` для процесса, поле `KPROCESS` (смещение `0x28`).
Показывается в `!process`.

**bug check parameters** `[баг чек парáметерз]` — параметры синего экрана
Четыре числа к коду bug check. Для `0x7E`: код исключения, адрес
инструкции, запись исключения, контекст.

**!analyze -v** `[энэлáйз]` — разбор падения
Главная команда для дампа или живого падения: показывает модуль
(`IMAGE_NAME`), функцию (`SYMBOL_NAME`), строку исходника
(`FAULTING_SOURCE_LINE`), если есть `.pdb`.

## Страничная память

**virtual address / physical address** `[вёрчуал / фúзикал эдрéс]` — виртуальный / физический адрес
Виртуальный видит программа (его показывает x64dbg), физический —
номер байта в микросхемах памяти. Первый во второй переводит процессор.
Глава 32.

**MMU (Memory Management Unit)** `[эм-эм-ю]` — блок управления памятью
Часть процессора, которая при каждом обращении к памяти переводит
виртуальный адрес в физический по таблицам страниц.

**paging / page tables** `[пéйджинг / пейдж тейблз]` — страничная память / таблицы страниц
Механизм перевода адресов страницами по 4 КБ. Таблицы пишет Windows,
читает процессор. В x86-64 это дерево из четырёх уровней.

**PML4, PDPT, PD, PT** `[пи-эм-эл-фо, пи-ди-пи-ти, пи-ди, пи-ти]` — уровни таблиц страниц
Page Map Level 4 → Page Directory Pointer Table → Page Directory →
Page Table. В каждой таблице 512 записей по 8 байт — ровно одна страница.
Адрес режется так: 9 + 9 + 9 + 9 битов индексов и 12 битов смещения.

**PTE (Page Table Entry)** `[пи-ти-и́]` — запись таблицы страниц
Запись о конкретной странице: физический адрес и флажки. Записи других
уровней — PML4E, PDPTE, PDE.

**CR3** `[си-ар-три]` — корень таблиц страниц
Управляющий регистр с физическим адресом таблицы PML4. У каждого
процесса свой. Писать можно только в кольце 0. Подробнее — глава 33.

**CR2** `[си-ар-ту]` — адрес страничного сбоя
Сюда процессор кладёт адрес, обращение к которому вызвало страничный сбой.

**P, R/W, U/S, XD (NX)** — главные биты записи таблицы
Бит 0 — страница есть (Present); бит 1 — можно писать (Read/Write);
бит 2 — доступна из кольца 3 (User/Supervisor); бит 63 — нельзя
выполнять (Execute Disable у Intel, No eXecute у AMD, основа DEP).
Права складываются по всем уровням, побеждает строгое.

**Accessed / Dirty** `[э́ксесст / дёрти]` — биты «обращались» / «писали»
Их ставит сам процессор. По ним Windows решает, какие страницы
выгружать в файл подкачки.

**demand paging** `[диманд пéйджинг]` — выделение по требованию
Физическая страница выдаётся не при `VirtualAlloc`, а при первом
касании — через страничный сбой, который ядро обрабатывает молча.

**working set** `[вёркинг сет]` — рабочий набор
Страницы процесса, у которых сейчас есть физическая память.
Поле `WorkingSetSize` в `GetProcessMemoryInfo`.

**canonical address** `[кэнóникал эдрéс]` — канонический адрес
Адрес, у которого биты 48–63 — копия бита 47. Отсюда две половины
адресов (процесс и ядро) и «дыра» между ними. Неканонический адрес
вызывает #GP.

**#GP (general protection fault)** `[дженерал протéкшен фолт]` — общее нарушение защиты
Исключение процессора при нарушении правил, например при
неканоническом адресе. В программе Windows — `C0000005`.

**large page** `[лардж пейдж]` — большая страница
Страница 2 МБ (бит PS в записи PD) или 1 ГБ (в PDPT). Спуск по дереву
короче, экономится TLB. В Linux — huge page.

**TLB (Translation Lookaside Buffer)** `[ти-эл-би]` — кэш переводов адресов
Запоминает готовые переводы, чтобы не спускаться по таблицам каждый
раз. После правки таблиц устаревшее сбрасывают (`invlpg`, запись в CR3).

**5-level paging (LA57)** `[файв лéвел пéйджинг]` — пятиуровневая страничная память
Ещё одна таблица, PML5, над PML4: адрес становится 57-битным.
В Windows — отдельное ядро `ntkrla57.exe`.

**EPT / NPT** `[и-пи-ти / эн-пи-ти]` — второй этаж перевода для гипервизора
Extended Page Tables (Intel) и Nested Page Tables (AMD): переводят
гостевой «физический» адрес в настоящий. Устроены как обычные таблицы,
но с отдельными битами чтения, записи и выполнения. Глава 37.

**EPT violation** `[и-пи-ти вайолéйшен]` — нарушение EPT
VM exit, когда гость обратился к памяти так, как EPT не разрешает.
Аналог страничного сбоя, только уровнем ниже.

## Системные регистры

**system registers** `[сúстем рéджистерс]` — системные регистры
Регистры, которые управляют самим процессором: `CR0`–`CR4`, `CR8`, MSR,
`GDTR`, `IDTR`. Трогать их может только кольцо 0. Глава 33.

**control register (CR)** `[контрóул рéджистер]` — управляющий регистр
`CR0` — главные рубильники (PE, WP, PG), `CR2` — адрес страничного
сбоя, `CR3` — корень таблиц страниц, `CR4` — рубильники расширений,
`CR8` — приоритет прерываний.

**PE / PG / WP** — биты CR0
Protection Enable (бит 0) — защищённый режим; Paging (бит 31) —
страничная память; Write Protect (бит 16) — запрет записи в страницы
«только чтение» действует и на ядро.

**real mode / protected mode / long mode** `[рил / протéктид / лонг мóуд]` — реальный / защищённый / длинный режим
16-битный режим старта процессора без защиты; режим с кольцами
(после `CR0.PE = 1`); 64-битный режим (после `EFER.LME = 1`
и `CR0.PG = 1`).

**VMXE** `[ви-эм-экс-и]` — разрешение VT-x
Бит 13 регистра `CR4`. Пока он 0, `vmxon` не работает.

**SMEP** `[смэп]` — запрет ядру выполнять код программ
Бит 20 `CR4`: кольцо 0 не может выполнять страницы с U/S = 1.

**rdmsr / wrmsr** `[рид-эм-эс-áр / райт-эм-эс-áр]` — чтение и запись MSR
Номер MSR в `ECX`, значение в `EDX:EAX`. Только кольцо 0.

**EFER** `[эфер]` — регистр включения расширенных возможностей
MSR `C0000080`: SCE — `syscall`, LME/LMA — 64-битный режим, NXE — бит
XD, SVME (бит 12) — разрешение AMD-V.

**IA32_FEATURE_CONTROL** — разрешение VT-x от прошивки
MSR `3A` у Intel. Бит 0 — замок, бит 2 — VT-x разрешена. Ставит прошивка.

**VM_CR** — запрет AMD-V от прошивки
MSR `C0010114` у AMD. Бит 4 (SVMDIS) = 1 — прошивка запретила AMD-V.

**cpuid** `[си-пи-ю-ай-ди]` — опознание процессора
Разрешённая всем инструкция: номер вопроса (лист) в `EAX`, ответ
в `EAX`, `EBX`, `ECX`, `EDX`. Лист 1, `ECX` бит 5 — VT-x, бит 31 —
«работаешь гостем». Под гипервизором Intel всегда вызывает VM exit.

**leaf** `[лиф]` — лист (номер вопроса к cpuid)
Число в `EAX` перед `cpuid`. Лист `0` — производитель, `40000000` —
имя гипервизора.

**intrinsic** `[интрúнсик]` — встроенная функция компилятора
Функция, которую компилятор превращает прямо в инструкцию процессора:
`__cpuidex` из `intrin.h` становится `cpuid`.

**segment / selector / descriptor** `[сéгмент / силéктор / дискрúптор]` — сегмент / селектор / дескриптор
Селектор — 16-битное число в сегментном регистре: номер записи (биты
3–15), таблица (бит 2), кольцо RPL (биты 0–1). Дескриптор — 8-байтовая
запись в GDT: кольцо (DPL), разрядность (L), права.

**GDT (Global Descriptor Table)** `[джи-ди-ти]` — глобальная таблица дескрипторов
Таблица сегментов. Адрес дескриптора = база GDT + index × 8. Адрес
таблицы хранит регистр `GDTR`, загружает `lgdt`.

**RPL / DPL** `[ар-пи-эл / ди-пи-эл]` — запрошенное / назначенное кольцо
RPL — два младших бита селектора (у `CS` это текущее кольцо, CPL).
DPL — в дескрипторе: для какого кольца сегмент.

**WoW64** `[вау-сúксти-фор]` — 32-битные программы в 64-битной Windows
Windows 32-bit on Windows 64-bit. Код таких программ выполняется
с `CS = 0x23`, системный — с `CS = 0x33`.

**swapgs** `[свóп-джи-эс]` — поменять базы GS местами
Меняет местами MSR `IA32_GS_BASE` и `IA32_KERNEL_GS_BASE`. Первая
инструкция обработчика `syscall` в ядре. Только кольцо 0.

**VMCS / VMCB** `[ви-эм-си-эс / ви-эм-си-би]` — структура управления виртуальной машиной
У Intel — VMCS, у AMD — VMCB. Хранит системные регистры гостя
и гипервизора и настройки перехватов. Глава 36.

## Прерывания

**interrupt vector** `[интерáпт вéктор]` — вектор прерывания
Номер события 0–255. Векторы 0–31 — исключения процессора, 32–255 —
раздаёт система. Глава 34.

**#DE, #DB, #BP, #UD, #DF, #GP, #PF** — главные исключения
Векторы 0, 1, 3, 6, 8, 13, 14: деление на ноль, отладка, точка
останова, недопустимая инструкция, двойной сбой, общее нарушение
защиты, страничный сбой.

**fault / trap / abort** `[фолт / трэп / эбóрт]` — сбой / ловушка / авария
Сбой сохраняет адрес той же инструкции (её повторят), ловушка —
следующей, авария — продолжать нельзя.

**IDT (Interrupt Descriptor Table)** `[ай-ди-ти]` — таблица дескрипторов прерываний
256 шлюзов по 16 байт; адрес шлюза = база + вектор × 16. Адрес
таблицы — в `IDTR`, загружает `lidt`.

**gate** `[гейт]` — шлюз
Запись IDT: адрес обработчика, селектор, тип (прерывания или
ловушки), DPL — кто может вызвать `int n`, IST — особый стек.

**iretq** `[ай-рет-кью]` — возврат из прерывания
Снимает со стека `RIP`, `CS`, `RFLAGS`, `RSP`, `SS` — возвращает
поток туда, где его застали.

**error code** `[э́ррор коуд]` — код ошибки
Число, которое процессор кладёт на стек для некоторых исключений
(#GP, #PF, #DF…). Для #PF — биты причины.

**TSS (Task State Segment)** `[ти-эс-эс]` — сегмент состояния задачи
В 64 битах — таблица стеков: `RSP0` для входа в кольцо 0 и IST1–7.
Селектор в Windows — `0x40`, регистр `TR`, инструкция `ltr`.

**IST (Interrupt Stack Table)** `[ай-эс-ти]` — таблица особых стеков
Стеки для опасных событий (#DF, NMI, #MC): процессор переключается
на них всегда, даже из кольца 0.

**APIC** `[эй-пик]` — контроллер прерываний
Локальный APIC у каждого ядра (там же таймер) и I/O APIC для
устройств. После обработки — EOI, «конец прерывания».

**NMI (Non-Maskable Interrupt)** `[эн-эм-ай]` — немаскируемое прерывание
Вектор 2. Флаг `IF` его не останавливает.

**IPI (Inter-Processor Interrupt)** `[ай-пи-ай]` — межпроцессорное прерывание
Прерывание, которое одно ядро посылает другому. Например, для сброса
TLB — TLB shootdown.

**IRQL (Interrupt Request Level)** `[ай-ар-кью-эл]` — уровень запроса прерывания
Приоритет в Windows, хранится в `CR8`. `PASSIVE_LEVEL` (0) — обычный
код, `DISPATCH_LEVEL` (2) — нельзя трогать выгружаемую память
и переключать потоки.

**exception bitmap** `[иксéпшен битмэп]` — битовая карта исключений
Поле VMCS: по биту на векторы 0–31. Бит 1 — исключение гостя вызывает
VM exit.

**event injection** `[ивéнт инджéкшен]` — вброс события
Гипервизор заставляет процессор доставить гостю исключение или
прерывание при следующем VM entry.

## Си для системного программиста

**fixed-width types** `[фикст видс тайпс]` — типы точного размера
`uint8_t`, `uint16_t`, `uint32_t`, `uint64_t` из `<stdint.h>`. В Windows:
`UCHAR`, `USHORT`, `ULONG` (4 байта!), `ULONG64`. Приложение П1.

**LLP64** `[эл-эл-пи-сúксти-фор]` — модель типов 64-битной Windows
`long` — 4 байта, `long long` и указатели — 8. В Linux `long` — 8 байт.

**bit mask** `[бит маск]` — битовая маска
Число, где единицы стоят на нужных битах. Маска на n битов —
`(1ULL << n) - 1`.

**padding** `[пэ́ддинг]` — выравнивание, набивка
Пустые байты, которые компилятор вставляет в структуру, чтобы поля
лежали по адресам, кратным их размеру.

**bit field** `[бит филд]` — битовое поле
Поле структуры шириной в биты: `uint64_t present : 1;`. Первое поле —
в младших битах (так делают MSVC и gcc на x86-64).

**union** `[ю́ньон]` — объединение
Несколько полей в одном и том же месте памяти: разные взгляды на одни
байты. Вместе с битовыми полями описывает записи таблиц страниц.

**header / prototype** `[хéдер / прóутотайп]` — заголовок (второе значение: файл `.h`) / прототип
`.h`-файл с описаниями; прототип — имя и параметры функции без тела.
`#pragma once` — вставлять заголовок один раз.

**undefined reference** `[андифáйнд рéференс]` — неопределённая ссылка
Ошибка компоновщика: функция объявлена, но её тело не найдено —
обычно забыли `.c` файл в команде сборки.

**function pointer** `[фáнкшен пóйнтер]` — указатель на функцию
Переменная с адресом функции. Таблица таких указателей — диспетчер
по номеру: обработчики VM exit, запросов драйвера.

**indirect call** `[индирéкт кол]` — косвенный вызов
`call rdx` — вызов по адресу из регистра или памяти. Ghidra не знает,
куда он уйдёт; смотри в отладчике.

**DWARF** `[дворф]` — формат отладочной информации GCC
Так `gcc -g` записывает имена и строки исходника. x64dbg его не читает:
он понимает только формат Microsoft (PDB). Приложение П1.9.

## Свой ассемблер

**directive** `[дирéктив]` — директива
Строка для самого ассемблера, а не для процессора: `.text`, `.globl`,
`.intel_syntax noprefix`. В машинный код не превращается. Приложение П2.

**object file** `[óбджект файл]` — объектный файл
Собранный кусок программы (`.o`, `.obj`) со списками имён: «что у меня
есть» и «что мне нужно». Компоновщик склеивает такие файлы в `.exe`.

**.globl** `[глóбл]` — сделать имя видимым снаружи
Без неё компоновщик не найдёт функцию: `undefined reference`.
В MASM функция `PROC` видна снаружи сама.

**leaf function** `[лиф фáнкшен]` — листовая функция
Функция, которая никого не вызывает и ничего не кладёт на стек.
Ей не нужно описание пролога.

**unwind data** `[анвáйнд дэйта]` — данные раскрутки стека
Описание пролога каждой функции в секциях `.pdata` и `.xdata`. По ним
отладчик и Windows проходят по стеку назад. В `gcc` задаются
директивами `.seh_`, в MASM — `PROC FRAME`, `.pushreg`, `.allocstack`,
`.endprolog`.

**MASM / ml64, Microsoft Macro Assembler** `[мáсм / эм-эл-сúксти-фор]` — ассемблер Microsoft
Ассемблер из Visual Studio, файлы `.asm`. Полное имя читается
`[мáкроу эсéмблер]`, «макро-ассемблер Microsoft» (П2.12). В Visual Studio для x64 нет
вставок ассемблера, поэтому свой ассемблер пишут в таких файлах.

**rdtsc, Read Time-Stamp Counter** `[ар-ди-ти-эс-си]` — прочитать счётчик тактов
Отдаёт 64-битный счётчик двумя половинами: `EDX:EAX`. Полное имя
читается `[рид тайм-стэмп кáунтер]` (П2.8).

## Гонки и блокировки

**data race** `[дэ́йта рейс]` — гонка данных
Два потока без договорённости меняют одни данные, и результат зависит
от того, кто успел первым. `counter++` из двух потоков теряет
прибавления. Приложение П3.

**atomic** `[этóмик]` — атомарный, неделимый
Операция, в середину которой не может вклиниться другое ядро.
Функции Windows `Interlocked…`.

**lock prefix** `[лок прúфикс]` — префикс `lock`
Байт `F0` перед инструкцией: сделать её атомарной. `xchg` с памятью
атомарна и без него.

**compare-exchange** `[кэмпéр иксчéйндж]` — сравнить и обменять
«Если там всё ещё то, что я жду, — запиши новое». `lock cmpxchg`,
`InterlockedCompareExchange`.

**critical section** `[крúтикал сéкшен]` — критическая секция
Участок кода, где в одну секунду может быть только один поток.

**spinlock** `[спинлок]` — спин-блокировка
Блокировка, где ждущий крутится в цикле с `pause`, а не засыпает.
Держать коротко, не засыпать внутри, не входить дважды.

**deadlock** `[дэ́длок]` — взаимная блокировка
Два потока вечно ждут блокировки друг друга. Лечится одним порядком
взятия блокировок.

**per-CPU data** `[пер-си-пи-ю́ дэ́йта]` — данные «на процессор»
У каждого логического процессора своя копия: блокировки не нужны.

**cache line** `[кэш лайн]` — строка кэша
Кусок памяти в 64 байта, которым кэш процессора обменивается с
памятью и с другими ядрами.

**false sharing** `[фолс шэ́ринг]` — ложное разделение
Данные разных ядер лежат в одной строке кэша и мешают друг другу,
хотя общих данных нет.

**affinity mask** `[эфúнити маск]` — маска привязки
Биты «на каких логических процессорах потоку можно работать».
`SetThreadAffinityMask`.

---

**lock** `[лок]` — префикс «запереть»
Префикс перед инструкцией, которая читает и пишет память: другие ядра
видят либо «до», либо «после», а не середину. Байт `F0`. Приложение П3.4.

**exchange and add, XADD** `[иксчéйндж энд эд]` — обменять и сложить
Прибавляет число к памяти и отдаёт старое значение. С `lock` — один
неделимый шаг. Приложение П3.4.

**compare and exchange, CMPXCHG** `[кэмпéр энд иксчéйндж]` — сравнить и обменять
Пишет новое значение, только если в памяти лежит ожидаемое старое.
С `lock` — основа блокировок. Приложение П3.5.

**Interlocked** `[интерлóкт]` — сцепленный, взаимно заблокированный
Семейство функций Windows (`InterlockedIncrement` и другие), которые
делают атомарные операции через `lock`. Приложение П3.4.

**per-CPU** `[пер-си-пи-ю́]` — данные «на процессор»
У каждого ядра своя копия данных, чтобы ядра не мешали друг другу.
Так устроен и гипервизор. Приложение П3.8.

**cache** `[кэш]` — кэш памяти
Быстрая память у каждого ядра с копиями недавно тронутых байтов,
чтобы не ходить каждый раз в медленную оперативную. Приложение П3.8.

## Язык документации

**SDM (Software Developer's Manual)** `[эс-ди-э́м]` — руководство Intel
Главная книга о процессорах Intel: том 2 — инструкции, том 3 —
системное программирование (3C — VMX), том 4 — MSR. Приложение П4.

**APM (Architecture Programmer's Manual)** `[эй-пи-э́м]` — руководство AMD
Том 2 — системное программирование и SVM, том 3 — инструкции.

**revision** `[ривúжен]` — ревизия (версия документа)
Номера глав между ревизиями сдвигаются — ищи по названию раздела.

**set / clear** `[сет / клир]` — бит равен 1 / бит равен 0
Не «установить» и «очистить» вообще, а именно 1 и 0.

**reserved** `[ризёрвд]` — зарезервировано
Не трогать: писать только то, что велено (обычно 0).

**must / should / may** `[мас / шуд / мэй]` — обязательно / рекомендуется / вправе
*May* — процессор вправе, но не обязан: код должен работать при обоих вариантах.

**undefined** `[андифáйнд]` — не определено
Там может оказаться что угодно — не опирайся.

**respectively** `[риспéктивли]` — соответственно, по порядку
*A and B are set and cleared, respectively* — A = 1, B = 0.

**high-order / low-order** `[хай-óрдер / лóу-óрдер]` — старшие / младшие (биты)

**Hex-Rays** `[хекс-рэйз]` — Хекс-Рэйз
Бельгийская компания, которая делает IDA и её декомпилятор.

**database, `.i64`** `[дéйтабейс]` — база (IDA)

**autoanalysis, `AU: idle`** `[óутоэнáлисис, áйдл]` — автоанализ, «без дела»

**graph view / text view, Space** `[граф вью / текст вью, спейс]` — граф / текст, пробел

**navigation band** `[нэвигéйшен бэнд]` — полоска навигации

Приложение П5.

**subroutine, sub_, loc_, off_, byte_, unk_** `[сáбрутин]` — подпрограмма; имена-заглушки IDA

`unk_` — неразобранный байт, `a…` — строка, `var_`/`arg_` — стек,

Приложение П5.

**comment / repeatable comment** `[кóммент / рипúтэбл кóммент]` — комментарий / повторяемый
Клавиши `:` и `;`. Повторяемый виден ещё и везде, где на это место

**IDAPython** `[áйда-пáйтон]` — Python внутри IDA

Приложение П5.

## Python (приложение П6)

**Python Install Manager, `py`** `[пáйтон инстóл мэ́неджер, пай]` — установщик Python
Официальный способ ставить Python на Windows: `py install 3.13`,
`py list`, `py -V:3.13 скрипт.py`. Старый установщик `.exe` выпускают
до версии 3.16. Приложение П6.

**idapyswitch** `[áйда-пай-свич]` — переключатель Python для IDA
Программа в папке IDA: находит установленные Python и выбирает, с каким
работает IDAPython. IDA 9.2 понимает Python 3.11–3.13. Приложение П6.

**REPL, `>>>`** `[рэпл]` — окно «прочитай — вычисли — напечатай»
Read–Eval–Print Loop: набрал `python` без имени файла — пишешь выражение
и сразу видишь ответ. Калькулятор реверсера. Выход — `exit()`.
Приложение П6.

**string, `str`** `[стринг]` — строка, текст
В Python текст — отдельный вид данных: `"Hello"[0]` — буква `'H'`.
В байты его переводит `encode`, обратно — `decode`. Приложение П6.

**bytes, bytearray** `[байтс, бáйт-эррэй]` — байты, изменяемые байты
Числа от 0 до 255, то, что лежит в файле: `b"Hello"[0]` — это `72`.
`bytes` менять нельзя, `bytearray` можно. Приложение П6.

**f-string** `[эф-стринг]` — f-строка
Строка с буквой `f` впереди: `f"{x:08X}"` вставляет число в hex
шириной 8 с нулями. Как `printf` в C. Приложение П6.

**indentation** `[индентéйшен]` — отступ
В Python вместо фигурных скобок: что сдвинуто под строкой
с двоеточием, то и тело `if`, цикла, функции. Ошибка —
`IndentationError`. Приложение П6.

**list** `[лист]` — список
`[1, 2, 3]` — как массив в C, только растёт сам: `append` добавляет
в конец. Приложение П6.

**dictionary, dict** `[дúкшенери, дикт]` — словарь
Пары «ключ → значение»: `info["machine"]`, `OPS.get(код)`. В Python
им заменяют и структуру, и `switch`. Приложение П6.

**tuple** `[тьюпл]` — кортеж
Несколько значений в круглых скобках. `struct.unpack` всегда
возвращает кортеж, поэтому одно значение берут через `[0]`.
Приложение П6.

**slice** `[слайс]` — срез
`data[off:off + size]` — кусок с номера `off` до `off + size`, конец
не включается. Заменяет `fseek` и `fread`. Приложение П6. В Rust срез —
тип `&[T]` или `&str`: адрес и длина, в аргументах — два регистра,
у `&str` нет нуля в конце. Приложение П8.

**module** `[мóдуль]` — модуль (Python)
Файл `.py` с готовыми функциями, подключается словом `import`:
`import struct`, свой `import pe_info`. В x64dbg (глава 13) модулем
называют другое — загруженный `.exe` или DLL. Приложение П6.

**struct** `[стракт]` — модуль `struct`
Раскладывает байты по полям по строке формата: `"<IHH"`. `<` —
little-endian и без выравнивания, `B`/`H`/`I`/`Q` — 1/2/4/8 байт без
знака, маленькие буквы — со знаком. Приложение П6.

**docstring** `[дóкстринг]` — строка документации
Строка в тройных кавычках сразу под `def`: описание функции для людей,
Python её не выполняет. Приложение П6.

**false positive** `[фолс пóзитив]` — ложное срабатывание
Правило поймало то, что только похоже на искомое: `xor` с `1Fh` после
`bsr` — не шифр. Скрипт сужает круг, решает человек. Приложение П6.

**PyInstaller** `[пáйинстóлер]` — сборщик программ на Python в `.exe`
Кладёт в файл загрузчик на C и архив с интерпретатором и байт-кодом.
В конце архива — метка `MEI\014\013\012\013\016`
(`4D 45 49 0C 0B 0A 0B 0E`). Приложение П6.

**overlay** `[óуверлэй]` — наложение, хвост файла
Данные за последней секцией PE: Windows их в память не грузит.
Там, например, лежит архив PyInstaller. Приложение П6.

**PyGhidra** `[пай-гúдра]` — Python 3 в Ghidra
Запуск — `support\pyghidraRun.bat`, в скрипте — строка
`# @runtime PyGhidra`. `getBytes` отдаёт знаковые байты Java:
нужна маска `& 0xFF`. Приложение П6.

**pip, PyPI** `[пип, пай-пи-áй]` — установщик модулей, каталог модулей
`py -V:3.13 -m pip install pefile` скачивает модуль из каталога PyPI
(Python Package Index). Приложение П6.

## C++ (приложение П7)

**C++** `[си-плюс-плюс]` — Си-плюс-плюс
Язык, выросший из C: добавил классы, исключения, стандартную
библиотеку. На нём написано большинство программ Windows; компилятор
Visual Studio — «Microsoft Visual C++». Приложение П7.

**class, method** `[класс, мéсод]` — класс, метод
Класс — структура, у которой есть свои функции; функции класса —
методы. В машинном коде метод — обычная функция с адресом объекта
в `RCX`. Приложение П7.

**this** `[зис]` — «этот», скрытый аргумент метода
Адрес объекта, который компилятор тайно передаёт методу первым
аргументом, в `RCX`. Поля — смещения от него: `[rcx+10h]`.
Приложение П7.

**constructor, destructor** `[констрáктор, дистрáктор]` — конструктор, деструктор
Методы, которые готовят новый объект и убирают за ним. Конструктор
класса с виртуальными функциями пишет в `[this]` адрес таблицы класса.
Деструктор пишется с тильдой: `~Animal()`. Приложение П7.

**scalar / vector deleting destructor** `[скéйлер / вéктор дилúтинг дистрáктор]` — удаляющий деструктор
Функция Visual Studio в ячейке 0 таблицы: вызывает деструктор и, если
во втором аргументе включён бит 0, освобождает память (`operator delete`).
Имя `??_G…` — scalar, для одного объекта; `??_E…` — vector, умеет ещё
удалять массивы (бит 1). Приложение П7.

**inherit, base class, derived class** `[инхéрит, бэйс класс, дирáйвд класс]` — наследовать, базовый класс, производный класс
`class Dog : public Animal` — `Dog` наследует всё, что есть у `Animal`.
В памяти объект наследника — объект базового класса и приписанные
к нему поля. Приложение П7.

**virtual function, vtable** `[вёрчуал фáнкшен, ви-тэйбл]` — виртуальная функция, таблица виртуальных функций
Функция, которую выбирают во время работы по настоящему классу
объекта. Таблица — массив адресов таких функций в `.rdata`; у Visual
Studio она зовётся vftable. Вызов: `mov rax, [rcx]` →
`call qword ptr [rax+N]`. Приложение П7.

**name mangling, decorated names** `[нэйм мэ́нглинг, дéкорейтид нэймз]` — искажённые («украшенные») имена
Имена, в которые компилятор зашил класс, аргументы и прочее:
`?name@Dog@@UEBAPEBDXZ` у Visual Studio, `_ZNK3Dog4nameEv` у g++.
Расшифровывают IDA, Ghidra, `undname`, `c++filt`. Приложение П7.

**Itanium** `[айтéйниум]` — схема g++ для C++
Правила раскладки объектов и искажения имён, которым следует g++
(названы по процессору Itanium, для которого их придумали). Отличаются
от правил Visual Studio. Приложение П7.

**RTTI** `[ар-ти-ти-áй]` — сведения о типах во время работы
Run-Time Type Information. У Visual Studio включены по умолчанию
(`/GR`): в данных лежат строки `.?AVDog@@` с именами классов, а перед
таблицей класса — адрес записи RTTI. Приложение П7.

**throw, try, catch** `[сроу, трай, кэч]` — бросить, попробовать, поймать
Исключения C++. `throw` у Visual Studio — вызов `_CxxThrowException`,
у g++ — `__cxa_throw`. В ядре исключения C++ выключены. Приложение П7.

**SSO** `[эс-эс-óу]` — оптимизация коротких строк
Small String Optimization: `std::string` держит текст до 15 букв
прямо в объекте (у Visual Studio), длиннее — в куче. Признак: вместимость
больше 15 — в начале объекта адрес. Приложение П7.

**standard library, std::** `[стэ́ндард лáйбрери]` — стандартная библиотека
Готовые классы C++: `std::string`, `std::vector`. У Visual Studio
и у g++ они устроены по-разному. Приложение П7.

## Rust (приложение П8)

**Rust** `[раст]` — «ржавчина», язык программирования
Системный язык, как C, но многие ошибки с памятью ловит компилятор,
а остальные — проверки во время работы. Приложение П8.

**rustup, rustc, cargo** `[раст-ап, раст-си, кáрго]` — установщик, компилятор, сборщик
`rustup` ставит Rust, `rustc` компилирует, `cargo` создаёт проекты
и собирает: `cargo build`, `cargo build --release`. Приложение П8.

**panic** `[пэ́ник]` — паника
Остановка программы на Rust при ошибке: номер вне массива, `unwrap`
от `None`, переполнение в отладочной сборке. В коде — вызовы
`core::panicking::…` и `ud2` после них. Приложение П8.

**bounds check** `[бáундз чек]` — проверка границ
Перед обращением к элементу: `cmp` длины с номером → прыжок →
`panic_bounds_check`. Приложение П8.

**Vec, String в Rust** `[век, стринг]` — вектор, строка
Растущий массив и растущая строка: три поля по 8 байт — вместимость,
адрес, длина. Порядок не обещан (у rustc 1.99: +0, +8, +16). Приложение П8.

**Option, Result** `[óпшн, ризáлт]` — вариант, результат
`Some(x)` / `None` и `Ok(x)` / `Err(e)`. `Option<&T>` в памяти — указатель
или 0. Приложение П8.

**unwrap** `[ан-рэ́п]` — «распаковать»
Взять значение из `Option` или `Result`, а если его нет — паника
(`unwrap_failed`). Приложение П8.

**niche** `[ниш]` — ниша
Свободное значение типа, которое Rust берёт под метку: у ссылки ноль
не бывает, поэтому `None` — это 0. Приложение П8.

**ownership, borrowing** `[óунершип, бóрроуинг]` — владение, заимствование
Правила Rust: у значения один владелец; ссылка `&` — посмотреть, `&mut` —
поменять. Проверяет компилятор, в `.exe` их нет. Приложение П8.

**v0 mangling** `[ви-ноль мэ́нглинг]` — новый вид имён Rust
Имена с `_R`, по умолчанию с Rust 1.97. Старый вид — `_ZN…17h…E`.
Числа перед словами — длины. Приложение П8.

**lang_start** `[лэнг старт]` — запуск языка
`std::rt::lang_start`: служебный `main` передаёт ему адрес твоего
`main`. Приложение П8.

**ud2** `[ю-ди-два]` — неверная инструкция
Всегда вызывает сбой `#UD` (вектор 6). Компилятор ставит её после
вызовов, которые не возвращаются, — например после паники. Приложение П8.

## Сеть (приложение П9)

**protocol** `[прóтокол]` — протокол
Договорённость, как устроены сообщения: что идёт первым, сколько байт
в поле, что значит число. У самодельных протоколов описания нет — его
восстанавливает реверсер. Приложение П9.

**packet** `[пáкет]` — пакет
Порция данных, которая прошла по сети: заголовки всех слоёв и полезная
нагрузка. Wireshark показывает одну строку на пакет. Приложение П9.

**payload** `[пéйлоуд]` — полезная нагрузка
Данные самой программы внутри всех заголовков пакета. В Wireshark —
`Len` в строке TCP и `Data` в подробностях. Приложение П9.

**IP address** `[ай-пи эдрéс]` — IP-адрес
Адрес компьютера в сети. IPv4 — четыре числа 0–255 через точку.
Приложение П9.

**port** `[порт]` — порт
Номер программы внутри компьютера, 0–65535. HTTP — 80, HTTPS — 443,
DNS — 53. Клиенту Windows выдаёт временный порт 49152–65535.
Приложение П9.

**loopback, 127.0.0.1** `[лýп-бэк]` — петля
Адрес «сам себе»: пакет не уходит дальше ПК. В Wireshark на Windows
петлю пишет **Adapter for loopback traffic capture** от Npcap.
Приложение П9.

**network byte order, htons / ntohs** `[нéтворк байт óрдер]` — порядок байтов сети
Числа в сетевых заголовках идут старшим байтом вперёд — наоборот
по сравнению с x86 (endianness, глава 3.7). `htons` и `ntohs`
переставляют два байта, `htonl` — четыре. В Python — `struct`
с форматом `>`. Приложение П9.

**TCP** `[ти-си-пи]` — протокол управления передачей
Transmission Control Protocol. Доставляет всё и по порядку,
но передаёт **поток байтов**, а не сообщения: границы программа
размечает сама. Приложение П9.

**handshake** `[хэ́нд-шейк]` — рукопожатие
Начало разговора TCP из трёх пакетов: SYN → SYN, ACK → ACK. В TLS —
своё рукопожатие поверх TCP (Client Hello, Server Hello). Приложение П9.

**SYN, ACK, FIN, RST, PSH** `[син, эк, фин, рэ-сéт, пуш]` — флаги TCP
Биты байта флагов: FIN 0x01 — «закончил», SYN 0x02 — «начнём»,
RST 0x04 — «обрыв», PSH 0x08 — «отдай сразу», ACK 0x10 — «получил».
Приложение П9.

**Seq, Ack** `[сик, эк]` — номер по порядку, подтверждение
Seq — номер первого байта пакета, Ack — следующий байт, который
сторона ждёт. Ack одной стороны = Seq + Len последнего пакета другой.
Приложение П9.

**UDP** `[ю-ди-пи]` — протокол пользовательских датаграмм
User Datagram Protocol. Без рукопожатия и без гарантий, зато каждый
пакет — отдельное сообщение. На нём работает DNS. Приложение П9.

**socket** `[сóкет]` — сокет, «розетка»
То, через что программа говорит по сети: `socket`, `connect`, `send`,
`recv` из `ws2_32.dll`. Приложение П9.

**Wireshark** `[уáйр-шарк]` — «акула на проводе»
Бесплатная программа для записи и разбора сетевого трафика. Пакеты
ловит драйвер Npcap. Приложение П9.

**TShark** `[ти-шарк]` — Wireshark в командной строке
Ставится вместе с Wireshark, если не снять галочку. Без окна, зато
удобен для скриптов. Приложение П9.

**Scapy** `[скéйпи]` — библиотека пакетов для Python
Читает и собирает пакеты. Ставится командой `py -m pip install scapy`.
Брать, когда свой разборщик из П9.15 понятен до байта. Приложение П9.

**Npcap** `[эн-пи-кэп]` — драйвер записи пакетов
Ставится вместе с Wireshark. Ловит и петлю — через Windows Filtering
Platform. Приложение П9.

**display filter, capture filter** `[дисплéй фúльтер, кэ́пчер фúльтер]` — фильтр отображения, фильтр захвата
Фильтр отображения прячет лишнее в уже записанном: `tcp.port == 7777`.
Фильтр захвата не даёт лишнему записаться, правила записи у него
другие: `port 7777`. Приложение П9.

**Follow TCP Stream** `[фóллоу ти-си-пи стрим]` — «следить за потоком TCP»
Окно Wireshark со всем разговором подряд: клиент красным, сервер
синим. Analyze → Follow → TCP Stream, Ctrl+Alt+Shift+T. Приложение П9.

**DNS** `[ди-эн-эс]` — система доменных имён
Телефонная книга интернета: по имени сайта даёт IP-адрес. Обычно UDP,
порт 53. Приложение П9.

**HTTP, HTTPS** `[эйч-ти-ти-пи, эйч-ти-ти-пи-эс]` — протокол передачи гипертекста
Язык сайтов, текстовый: `GET / HTTP/1.1`, строки-заголовки, пустая
строка, содержимое. HTTPS — тот же HTTP внутри TLS. Приложение П9.

**User-Agent** `[ю́зер-эйджент]` — «агент пользователя»
Заголовок HTTP с именем программы, которая делает запрос. Для
реверсера — подпись программы. Приложение П9.

**TLS (Transport Layer Security)** `[ти-эл-эс]` — защита транспортного уровня
Шифрование поверх TCP. Видны адреса, порты, имя сайта (SNI), время
и объём, не видно содержимое. Не путать с **TLS callback** из главы 13:
там TLS — Thread Local Storage, совсем другое. Приложение П9.

**SNI (Server Name Indication)** `[эс-эн-ай]` — указание имени сервера
Имя сайта в Client Hello, открытым текстом. Фильтр
`tls.handshake.extensions_server_name`. Расширение ECH прячет и его.
Приложение П9.

**certificate, certificate pinning** `[сертúфикет, пúнинг]` — сертификат, закрепление сертификата
Сертификат — «удостоверение» сайта. Закрепление — программа сама
проверяет сертификат и не доверяет посреднику, даже отладочному прокси.
Приложение П9.

**pcap, pcapng** `[пи-кэп, пи-кэп-эн-джи]` — файл записи пакетов
Форматы записей трафика. pcapng — по умолчанию в Wireshark; pcap —
проще: заголовок 24 байта, перед каждым пакетом 16 байт. Приложение П9.

**pktmon** `[пакет-мон]` — наблюдатель за пакетами
Встроенная в Windows 10 (с версии 2004) и 11 запись трафика: `pktmon
start --capture --pkt-size 0`, `pktmon stop`, `pktmon etl2pcap`.
Нужны права администратора. Приложение П9.

**session key** `[сéшн ки]` — ключ сессии
Ключ, который действует только в одном подключении. В задаче 06
сервер передаёт его первым байтом приветствия. Приложение П9.

## Профессия

**writeup** `[рáйтап]` — разбор задачи
Запись хода решения: что искал, где нашёл, что понял. Основа портфолио.
Глава 40.

**portfolio** `[портфóлиоу]` — портфолио
Набор твоих работ, которые можно открыть и посмотреть: разборы,
инструменты, свой гипервизор.

**fuzzing** `[фáззинг]` — фаззинг
Автоматический поиск ошибок: программе подсовывают миллионы
испорченных входных данных и ждут падения.

**bug bounty** `[баг бáунти]` — награда за ошибку
Официальная программа компании: платит за найденные уязвимости,
если работать строго по её правилам.

**responsible disclosure** `[риспóнсибл дисклóужер]` — ответственное раскрытие
Сначала сообщить производителю, дать время исправить, публиковать
только потом.

**NDA (non-disclosure agreement)** `[эн-ди-э́й]` — соглашение о неразглашении

## Как учить

Не пытайся выучить словарь целиком — бесполезно. Термины оседают сами, когда
ты встречаешь их в деле по пятому разу.

Но одну вещь сделай прямо сейчас: прочитай разделы «Самое основное» и
«Процессор и код». Эти двадцать слов будут в каждой главе, и лучше, чтобы они
не тормозили чтение.

Остальные разделы читай по мере продвижения — они привязаны к главам, и
номер главы указан у каждого термина.
